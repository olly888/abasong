# Abasong 独立品牌、产品风格与设计系统方案 V1

日期：2026-10-28。状态：独立设计提案，可进入方向评审与原型验证；未视为最终品牌定稿。

## 1. 设计任务与决策边界

这份方案从产品实际用途推导，不继承旧版设计系统的配色、字体、图形或主按钮规则。旧 PDF 只作为历史参考；产品规则以 PRD V10.2 与本轮用户要求为依据。

**保留的产品事实**：

- 产品名 Abasong / 阿巴送；主要面向洛杉矶尾程配送司机及 DSP。
- 同一个客户端，底部为“首页 / 司机圈 / 我的”，没有 DSP 工作台。
- 地图是主要空间交互；司机既能接任务，也能找人接手。
- 平台帮助发现、联系、交接及记录协作结果，配送费用完全私下结算。
- 不展示全平台精确轨迹；不以付费代替进入信息的使用授权。

**本轮重新提出**：品牌气质、色彩、字标方向、图形、地图风格、排版、组件、动效、文案及设计交付机制。候选宣传语、符号与色彩尚未获得最终批准。

**判断方案优劣的标准**：户外是否看得清；五秒内是否知道当前对象与下一步；是否能区分报价、经验与事实；是否能从个人接活自然切换到代表 DSP 发需求；界面是否清楚但有人情味。

## 2. 设计立场

Abasong 应表现为一款清楚、可信、与同行关系紧密的移动工具。街道、楼栋、等待、赶时间、愿意搭把手的人，是它的内容来源。

推荐的品牌性格：**清醒、可靠、利落、温暖**。

| 性格 | 产品中的表现 | 约束 |
|---|---|---|
| 清醒 | 信息有明确来源、时间与状态 | 不制造虚假在线人数与成功承诺 |
| 可靠 | 价格、范围、联系人、下一步清楚 | 不用一个“认证”徽章概括所有事实 |
| 利落 | 常用动作短，关键确认明确 | 不为了减少点击省略报酬或交接确认 |
| 温暖 | 真实同行、平等交流、主动协作 | 不把所有司机统一叫“兄弟”，兼容不同用户 |

产品不需要通过大量品牌装饰证明自己有个性。品牌识别主要由少量稳定元素构成：颜色、字标、卡片秩序、地图标记与语言。

## 3. 三个独立视觉方向

| 方向 | 核心色彩 | 气质与优势 | 代价 | 建议 |
|---|---|---|---|---|
| 01 路标信号 | 石墨 `#18211D`、黄绿 `#D5F24A`、粉笔白 `#F4F5F0` | 识别鲜明，贴近道路标记与现场工作，能在克制界面中形成记忆 | 黄绿不能作浅底正文；需与绿色成功状态严格区分 | **推荐作为主方向** |
| 02 清晰工具 | 深蓝 `#172A43`、浅蓝 `#CDE3FF`、白 | 熟悉、安静，信息呈现容易接受 | 容易接近常见企业工具，品牌区分较弱 | 可作为低风险比较方向 |
| 03 街区温度 | 深褐 `#34231E`、浅陶土 `#F4B89F`、暖白 | 有邻里感，适合真实人物摄影和社区传播 | 红橙语义与紧急、错误状态要仔细隔离 | 可研究传播端应用 |

推荐 01 并非因为色彩流行，而是它能把“在路上、看得见、彼此协作”转成简单的识别系统。方向 02、03 在预览中仅切换核心颜色，用于比较感受，不代表完成三套系统。深夜、色觉差异、室外屏幕与本地用户接受度仍需测试。

## 4. 品牌表达与标志规划

### 4.1 名称与描述

- 产品名称：Abasong / 阿巴送。
- 英文字标候选：小写 `abasong`，保持友好与紧凑；正文可用 Abasong。
- 功能描述候选：**附近司机协作网络** / **The nearby driver network**。
- 主宣传语候选：**附近有同行，路上有照应。**
- 辅助传播句候选：**查地址、找任务、找同行。**

上述短句分别负责品牌情感和功能解释，不要求全部同时出现在 App 首页。宣传语不能表达“附近一定有人接单”或“平台保证支付”。是否保留原口号由品牌评审决定，本方案不默认沿用。

### 4.2 标志概念：汇合

推荐探索“两条独立路径在一个共同节点形成连接”的抽象符号。表达司机保有自主性，同时可以互相协作。方向应能应用于 App 图标、头像角标、仓库贴纸和单色印刷。

预览页内的双路径符号为几何探索稿，仅用于验证识别关系，不视为完成商标、最终矢量母版或可注册结论。字标同样是排版示意，不是定制字形。

正式标志交付必须包含：

1. 至少三种结构探索，并在 24px、48px、App 图标和远距离海报上比较。
2. 中英文组合、纯英文、独立符号及单色版本。
3. 光学留白、最小尺寸、图标安全区、正反白和禁用示例。
4. 字形、字体授权与相似标志检查；未经检查不宣称可注册。
5. SVG/PDF 矢量母版、PNG 导出、命名与版本。

不把货车、包裹、闪电、定位针和握手全部塞进一个标志。符号中不出现任何承运商品牌元素。

### 4.3 品牌资产层级

App 内标志轻量露出；用户工作信息优先。对外海报、邀请页、网站可放大符号与宣传语；两者共享字形、颜色和声音，但不要求用同一种页面构图。

| signalSoft | `#F1F8D4` | 可用设置、品牌提示表面 |

| textMuted | `#66736A` | 次要元信息，仍需满足其背景对比 |
| border | `#DCE2D7` | 非关键分割线；不能单独作为可操作控件边界 |

### 5.2 使用规则

- 大部分界面由浅背景、白卡、深文字构成；黄绿保持少量，避免整个产品像警示牌。
- 常规主操作用深底白字；黄绿深字用于被选中对象、品牌强调和少量明确的确认节点。一个区域最多一个高强调按钮。
- signal 不代表认证、完成或成功，也不用于白底小号正文；禁用黄绿底白字。
- 价格默认深色，与件数和时间形成层级，不用绿色暗示确定收益。
- 状态颜色是语义，不随品牌色比较器一起改变。
- 文字和状态不能只靠颜色表达；错误还必须有说明和恢复动作。

### 5.3 目前已经检查与尚未检查

`contrast-check.json` 包含推荐方向的 10 组色对计算：正文目标至少 4.5:1，指定必要控件边界和焦点色至少 3:1。该检查只证明指定静态色对，不等于完整界面符合无障碍要求。

地图底图叠加、禁用状态、透明表面、实际字体、暗色模式和方向 02/03 尚需单独检查。不能拿 10 组色对通过替代整体可访问性测试。

## 6. 字体、数字与排版

### 6.1 字体选择

产品初版优先使用平台系统字体，降低中文字体下载、渲染和首屏成本：iOS 使用系统拉丁字与苹方体系；Android 使用系统拉丁字与系统 CJK 无衬线回退。Web 使用 `ui-sans-serif`、系统栈与中文回退。

品牌网站与宣传材料可评估 Inter 或其他适合的无衬线字体，但应确认字体文件与许可。预览没有下载任何字体，实际使用本机可用字体；不把预览中的字形视为定制品牌字。

数字使用 tabular numerals，保证件数、价格、时间对齐；无需全界面等宽字体。敏感凭证用清晰、可区分 `0/O`、`1/I` 的字形，并经真实设备验证。

### 6.2 产品字号

| 层级 | 大小 / 行高 | 字重 | 用途 |
|---|---|---|---|
| Display | 40 / 48 | 700 | 引导、品牌页，非任务列表 |
| H1 | 28 / 36 | 700 | 根页面标题 |
| H2 | 20 / 28 | 600–700 | 卡片标题、面板标题 |
| Body | 16 / 24 | 400–500 | 主要内容与输入 |
| Label | 14 / 20 | 500–600 | 控件标签、简短辅助信息 |
| Caption | 13 / 18 | 400–500 | 时间和来源；不承载唯一关键条件 |
| Key number | 28–32 / 36 | 600–700 | 件价、件数、关键时间 |

品牌传播标题可另有更大的字阶。预览板的手机是并列缩略展示，其 CSS 字号不作为工程交付字号依据；原型与实机按本表检查。

支持系统字体放大到 200%：卡片可增长、按钮文本可换行、底部面板可滚动，关键报酬与截止时间不得被省略。长中文地址、英文楼名与中英混排需单独测试。

## 7. 布局、密度与基本尺寸

- 4px 基础单位；常用间距 4、8、12、16、20、24、32、40、48、64。
- 手机内容水平边距默认 20px，窄屏可降至 16px；不要把所有元素贴边。
- 最小交互区 48×48px，主按钮高 52px；小图标也要有足够点击区。
- 输入、按钮圆角 12px；卡片 20px；底部面板顶角 28px；标签与意图选项可用胶囊形。
- 圆角具有层级，不能把所有容器做成同一种超大胶囊。
- 阴影只用于地图上的浮层与层级分离；普通列表主要靠留白和分割。
- 底部导航包含安全区；可触达区域不被系统 Home 指示器遮住。
- 重点验证 360–430px 宽手机；平板保持内容阅读宽度，不顺势变成 DSP 工作台。

## 8. 地图视觉与交互

### 8.1 地图的角色

地图帮助用户理解区域、距离和对象关系。任务条件由卡片解释；复杂长内容进入二级页面。地图不是背景装饰，也不是全行业实时监控屏。

地图方案与地图供应商分离。选择供应商时需验证自定义样式、标签、本地覆盖、中文表现、点位聚合及许可；预览采用手工 SVG 示意，不依赖真实地图 API，不具备导航功能。

### 8.2 推荐日间地图

浅灰绿陆地 `#E8EDE1`、浅绿公园 `#D8E3C8`、白色道路、弱化支路、适度保留主干道名称和当前区名。保留必要归属标注，真实地图实施时不得遮盖供应商法定标识。

关闭无关商家标签，保留有用的街道、楼宇和入口。任务点位、司机聚合与当前选择比底图更醒目。视野变化后不立即重排所有结果，提供明确的区域重新搜索动作。

### 8.3 点位系统

| 对象 | 标记 | 选中态 | 避免误解 |
|---|---|---|---|
| 任务 | 圆角价格/件数标签 | 深底、浅色文字、描边与面板同步 | 发布报价不是保证收入 |
| 可用司机 | 人形图标与区域聚合 | 描边与对应候选面板 | 不画连续移动小车暗示精确轨迹 |
| 楼宇 | 楼宇图标 | 填充与入口卡片同步 | 有一般资料不代表有可用密码 |
| 自己 | 蓝点与精度圈 | 不作为其他用户实时位置模板 | 无权限时允许手动选区 |
| 求助 | 图标+简短类别 | 高对比文字与求助状态 | 普通求助不使用急救警报视觉 |

选中态还要靠尺寸、形状或描边，不能只变颜色。稀疏区不要展示可反推个人位置的假精确点；密集区聚合，且不能夸大实时可用数。

### 8.4 底部面板

三个停靠高度：摘要、半屏、展开。摘要保留对象、关键条件和主要动作；半屏支持比较；展开支持完整列表。提供可点击的展开/收起按钮，拖动不是唯一操作方式。

选对象时移动地图应给用户保留方向感，不快速飞跃；拖动面板时不误触底图；输入时按软键盘调整。位置权限、通知权限在需要时解释，不在第一屏连续弹窗。

## 9. 三导航与页面风格

### 9.1 首页

地图 + 搜索 + 当前意图 + 上下文面板。三个意图为查地址、找活、找人。预览以显式意图切换展示，正式原型仍可与“底部行动入口”比较，不将偏好当作验证结果。

默认面板应该让用户直接理解能做什么：查公寓、找任务、找支援。进行中的协作保持可恢复；多个任务汇为“需要你处理 N 项”，不在地图堆叠多张大卡。

### 9.2 司机圈

页面以最近会话、常合作联系人和线路圈组成。人与任务有关系，但不复制任务状态；圈内引用原任务卡。使用头像、姓名、区域和简短会话摘要建立关系感。

没有公开朋友圈、短视频和点赞排行榜。DSP 的合作司机也是该页的关系分组，不增加独立工作台。

### 9.3 我的

身份档案、主动可用设置、全部协作、信息贡献、合作组织、平台服务订阅、隐私与帮助。允许个人与组织身份并存，在发布时明确操作主体。

**不出现配送钱包、司机收入、应收款、付款确认或结算入口。** 平台自身服务费的订阅管理标注用途，不能设计成配送财务中心。

## 10. 四类核心卡片

| 卡片 | 第一层 | 第二层 | 主要动作 |
|---|---|---|---|
| 任务卡 | 区域、发布报价、件数、时间 | 路线条件、付款约定、发布人、资格 | 查看并申请 |
| 司机卡 | 可用时段、容量、区域 | 经验来源、资格适用范围、合作事实 | 邀请协作 |
| 楼宇卡 | 正确楼栋、入口、资料状态 | 停车、包裹室、来源、更新时间 | 查看信息/发求助 |
| 当前协作卡 | 现在进展与本人下一步 | 截止、对方、条件版本、异常 | 确认/联系/处理 |

共同语法：上方少量状态 → 清楚标题 → 关键数字或事实 → 条件与来源 → 一个主操作。全部信息不能同样加粗；不堆徽章。图片不是每张卡都必需，地图、字与事实应独立完成判断。

## 11. 组件系统

### 11.1 基础组件

按钮（primary、secondary、tertiary、danger）；图标按钮；单行/多行输入；金额与数量输入；时间窗；区域选择；单选/多选；开关；标签；头像；分割线；加载骨架；Toast；错误提示；确认弹窗；底部面板；导航；列表行。

每个可操作组件至少定义 default、pressed、focus、disabled、loading；表单另有 error、helper、read-only。加载期间不重复提交，保留操作语义。禁用态不承担唯一解释，旁边说明原因。

### 11.2 业务组件

任务报价块、时段与容量块、经验来源标签、准入缺口、任务条件版本、交接数量确认、协作进度、资料新鲜度、授权状态、隐私分享条、免费信息额度说明。

“资料核验通过”“经验自报”“任务准入待核实”必须是三个不同的语义，不组合成绿色大盾牌。信息额度不隐藏前置权限检查，会员也不能绕过授权。

### 11.3 核心状态

发布中 / 等待响应 / 已有申请 / 待本人确认 / 待批准 / 待到场 / 待交接 / 协作中 / 结果待确认 / 协作结束。状态必须伴随本人下一步，不能只有进度条。

没有“待付款”“已到账”“欠款”等配送资金状态。平台服务订阅有其独立商品生命周期，并明确只属于软件服务。

## 12. 内容与品牌语气

使用司机在现场能快速理解的动词：查地址、找任务、找人、联系、申请、确认、修改、退出、报告失效。

| 场景 | 推荐文案 | 理由 |
|---|---|---|
| 尚无司机响应 | 暂无符合条件的申请，可调整报价或时间 | 真实，并给下一步 |
| 状态非实时 | 15 分钟前声明可用，接手前需确认 | 不冒充实时在线 |
| 经验自报 | 司机填写：熟悉 Alhambra 公寓线路 | 说明证据来源 |
| 无楼宇资料 | 这里还没有资料，可以向附近同行求助 | 不输出错误近似信息 |
| 私下付款 | 配送费用由双方私下结算 | 清楚表达边界 |
| 交接完成 | 已确认交接 60 件 | 表达工作事实，不推断未来妥投或费用结清 |

不使用“海量优质运力”“保证四分钟接单”“官方认证全能司机”“已确保安全”等无法支持的承诺。中英界面共用信息层级，不逐字硬译；英文卡片长度与地址断行单独评审。

## 13. 动效、反馈与现场可用性

- 点击/选中反馈约 120ms；组件切换约 200ms；面板过渡约 280ms，均为初始参数。
- 动效用于解释状态和位置，不做持续漂浮、闪烁、粒子或庆祝动画。
- 尊重减少动态效果；定位与底部面板移动不让用户丢失当前对象。
- 弱网提交超时显示“正在核实提交结果”，避免用户重复确认；不能擅自显示成功。
- 交接确认后可用轻量触觉反馈，需测试平台支持；不用频繁震动模拟任务紧急程度。
- 行驶中不要求填写、改价、扫码或处理长条件；必要时提示停车。

## 14. 摄影、插画与图形

摄影优先呈现真实车辆、街区、公寓入口和日常同行协作，避免西装握手、无人仓库和悬浮包裹科技图。拍摄获得同意并避开收件人地址、面单、车牌与住户进入凭证等敏感信息。

独立品牌图形可从“区域块、路径、汇合点”发展，主要用于邀请页、海报和空态。地图里的真实对象不用插画伪装。空态小图可以带温度，但主动作必须清楚，且不能把空地图画满假司机。

## 15. 无障碍与设计质量

除色对计算外，正式上线需检查：读屏标签与顺序、焦点恢复、模态焦点约束、键盘可达、拖动替代、200% 字体、减少动效、非颜色状态、触控区、强光和弱网。地图结果必须有列表替代。

典型测试：

1. 大字下看清件价、件数、时限与私下付款约定。
2. 不使用精确位置也能浏览并申请。
3. 只用读屏完成任务条件查看与申请。
4. 面板展开后返回，选中对象和滚动位置保持。
5. 资料失效时可快速反馈；无资料不被收费或误导。
6. DSP 与司机都在同一三导航找到当前协作。
7. 看见“协作结束”不会理解成平台已结算。

预览仅验证视觉方向和少量本地交互；尚未进行上述完整用户或设备测试，不声称已通过。

## 16. 设计变量、组件命名与工程对接

交付文件：`tokens.json`、`tokens.css`、`create_tokens.py`、`contrast-check.json`。JSON 采用带类型的令牌结构，语义变量引用基础色；这些文件是设计与工程交接起点，不声称已兼容所有设计工具的自动导入。

分层建议：

```text
基础层：color / space / radius / size / fontSize / fontWeight / motion
语义层：action / text / surface / status / focus / map
组件层：Button / TaskCard / DriverCard / BuildingCard / Sheet / Navigation
页面层：Home / Circle / Profile / TaskFlow
```

设计工具组件命名采用 `组件/变体/状态`，如 `Button/Primary/Loading`、`TaskCard/Rescue/Selected`。页面不得单独硬编码另一套金色、圆角或“认证绿”。

版本管理分基础变化、组件变化和文案变化。颜色、字号、交互区及语义变更需要更新令牌、组件、示例和回归检查，不只修改一张设计稿。

## 17. 执行路线与验收

| 阶段 | 主要工作 | 交付 | 决策门槛 |
|---|---|---|---|
| A 方向 | 比较品牌性格、色彩、标志结构 | 方向板、简短理由 | 确定一个主方向，不拼贴三套 |
| B 核心原型 | 查公寓、找任务、发支援、交接、多任务恢复 | 三导航与三条完整核心流程 | 用户能独立找到下一步，身份和付款约定不混淆 |

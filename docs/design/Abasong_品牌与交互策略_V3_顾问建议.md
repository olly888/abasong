# Abasong 品牌与交互策略 V3 · 设计顾问建议

日期：2026-10-29。依据：用户已批准的 [PRD V12](../../Abasong_PRD_V12_首版产品需求.md)、[首版页面范围](../../Abasong_V12_页面范围与原型验收.md) 和 [视觉基础 V2](../../design/abasong-independent-v1/Abasong_国际化视觉与设计系统_V2.md)。

本文件为独立设计评审与后续设计系统建议，不代表实际聘请了 Amazon/Uber 在职或前任设计师，也不代表已有真实司机实验结果。颜色为 Abasong 自主候选，不宣称是其他品牌的官方色值。用户后续已同意皇家蓝方向，当前制作规则以《设计系统V3·原型制作基线》为准；旧原型和现有V2令牌未自动改色。

## 1. 战略判断

**首推保留黑白地图与内容骨架，引入 Abasong 自主皇家蓝 `#1467D8` 作为主品牌色及关键提交动作色。深海蓝 `#126B86` 保留为备选，不与首推色同时使用。**

本轮依据主代理提供的官网可视观察和只读计算样式结果修订：Amazon Flex 当前所访问页面以白/米白底、深色字和蓝色动作为主；多个可见 `Deliver now` 按钮背景为 `rgb(0,106,230)`，即 `#006AE6`，白字、约 32px 圆角；`How to earn` 等链接也出现同色，页面另有白底深字动作。这些是该页面在观察时的样式，不是 Amazon 全品牌官方色标准。[参考页面](https://flex.amazon.com/)

皇家蓝方案更贴近用户明确希望的 Flex 灵感，也比偏青的深海蓝更鲜明。`#1467D8` 比观察到的按钮蓝略收敛，白字仍有 5.30:1 对比；它是独立候选而非对方官方色。主色差异本身不足以建立品牌独立性，还需自有字标、组件、地图表达和准确归属。

借鉴 Uber 的价值在于地图与面板的明确关系、稳定的动作层级和低噪声操作。借鉴 Amazon/Flex 的价值在于让任务、条件与下一步容易理解，并在司机真正需要帮助时提供可预测的响应。颜色可以帮助形成自己的识别，但不能代替可靠的地址匹配、正确的进入资料与可联系的支援者。

不建议把所有黑色按钮统一替换成蓝色。司机在户外短暂打开 App，只需要快速找到当前公寓密码；这一场景主要依靠大字、地址和资料状态。蓝色应在需要明确执行时出现，例如发布需求、提交报名、保存新密码。无须点击就能看到的核心信息不能被大按钮压下去。

### 配色方向的取舍

| 方向 | 优点 | 代价 | 建议 |
|---|---|---|---|
| 纯黑白 | 结构清晰、地图克制、延续现有方向 | 主动作与普通强调难形成独立品牌记忆 | 可作为中性骨架，不必承担所有品牌表达 |
| 高亮青蓝大量铺色 | 鲜明、轻快 | 部分亮色色值与白字对比不足，地图/密码/动作同时抢注意力 | 不作为默认整套界面；不据此推断所有蓝色都不合格 |
| 黑白骨架＋深海蓝主动作 | 对比高、偏克制，较容易与常见皇家蓝区分 | 偏青且较沉静，与用户所指 Flex 蓝灵感距离更大 | 备选 |
| 黑白骨架＋自主皇家蓝主动作 | 更贴近用户方向，鲜明，保留白字可读性 | 需靠形状区分位置/选中态，也需防止同类工具视觉同质化 | 首推 |

这是专家判断，效果仍需在相同布局下用真实司机测试；不能由“蓝色代表信任”直接推导更高转化或留存。

## 2. 品牌定位与识别

Abasong 的品牌承诺建议围绕：**关键时候，找到可用的信息和愿意帮忙的人。** 这句话用于品牌策略和对外介绍，不常驻首页地图，也不承诺每栋有密码或每次必有人接。

品牌气质：清楚、可靠、直接、有人情味。品牌识别应由五件事共同构成：稳定的字标、固定的皇家蓝、地图/面板关系、大而清楚的关键数字、简短一致的动作语言。

建议字标继续采用自主排版的 `abasong`；连接/接力符号可以探索为图形资产，但不得把类似 Amazon smile 的箭头、包裹图形与对方字体组合成近似品牌签名。不能通过颜色或广告文案让司机误以为这是 Amazon 官方 App 或承运商内部系统。无需为此在产品首页增加长免责声明；通过自有字标、应用商店主体及准确的对外说明建立清楚归属。

首版不因品牌更新新增吉祥物、开屏动画、复杂插画和奖励体系。品牌首先出现在 App 图标、必要字标、主动作与对外招募材料。

## 3. 推荐颜色系统

### 3.1 自主候选

| 语义令牌 | 候选值 | 用法 |
|---|---|---|
| `brand.primary` | `#1467D8` | 首推自主皇家蓝；关键操作默认填充 |
| `brand.primaryPressed` | `#1054B3` | 主要按钮按下状态 |
| `brand.surface` | `#EDF4FF` | 小面积选择/辅助表面，不铺满地图 |
| `brand.onPrimary` | `#FFFFFF` | 主要按钮文字与必要图标 |
| `text.primary` | `#101114` | 标题、地址、密码与主要事实 |
| `text.secondary` | `#53565B` | 描述与次要事实 |
| `text.metadata` | `#686C73` | 时间等元信息，须按实际背景验证 |
| `surface.canvas` | `#F6F6F6` | 基础画布 |
| `surface.card` | `#FFFFFF` | 面板与内容卡 |
| `map.selfLocation` | `#245CC4` | 自身位置，保留独立定位语义 |
| `status.success` | `#236346` | 已完成、实际有用反馈等有限状态 |
| `status.warning` | `#855307` | 需复核、待确认 |
| `status.danger` | `#AE3734` | 错误与危险操作 |

这些值是推荐方案，不是已批准的最终品牌标准。备选深海蓝使用 `#126B86`、按下 `#0B526B`、浅表面 `#EAF4F7`，仅在方案比较中展示，不与首推色并列作为两个品牌主色。皇家蓝相近候选 `#1769D2` 也具备足够白字对比，但不建议因细微差异长期保留多个决策选项；首推仍为 `#1467D8`。

### 3.2 已计算的色对

按标准 sRGB 相对亮度公式计算：

| 前景 / 背景 | 对比度 | 结论 |
|---|---|---|
| 白字 / 首推 `#1467D8` | 5.30:1 | 超过普通文字 4.5:1 基线 |
| 白字 / 按下 `#1054B3` | 7.14:1 | 超过普通文字 4.5:1 基线 |
| `#1467D8` / `#EDF4FF` | 4.79:1 | 可用于正常尺寸文字 |
| 白字 / 观察页面按钮 `#006AE6` | 4.99:1 | 此具体色对白字可达普通文字基线，不是官方全品牌标准 |
| 白字 / 相近候选 `#1769D2` | 5.27:1 | 数值合格，首推仍固定为 `#1467D8` |
| 白字 / 备选深海蓝 `#126B86` | 6.05:1 | 对比更高，但不会仅凭高出约 0.75 判定整体更优 |
| 白字 / 假设亮青 `#00A8E1` | 2.73:1 | 不适合普通白字按钮；不是本轮官网取色或确认的官方色 |
| `#101114` / 白底 | 18.88:1 | 核心信息具备高对比基础 |

这是具体色对验证，不等于完整产品通过无障碍认证。地图背景、半透明层、键盘、禁用、焦点、实际设备及低亮度仍需实测。品牌色与位置色即便数值不同，也不能只依赖两种蓝区分对象，必须通过蓝点/光环、区域形状、描边及标签共同表达。

## 4. 用色分配：让品牌有分寸

### 4.1 首页与地图

- 地图以中性灰为主，保留道路、建筑及必要地名；不要把整片区域染成品牌色。
- 未选中公寓保留轻量建筑表达，选中公寓采用品牌色轮廓或有限浅填充；不同时高亮多个无关对象。
- 自己位置是蓝点与精度光环，不画成司机头像或品牌色价格气泡。
- 找活未选中标记用清楚的黑白价格/需求标签；选中可使用品牌描边或填充，卡片同步。
- 找人显示主动可用的服务区域；不因蓝色头像让人以为是可追踪的实时司机位置。
- 底部导航用图标/字重区分选中，可加少量品牌色；不做三块大蓝色导航胶囊。

### 4.2 品牌动作与信息动作

| 情境 | 处理 |
|---|---|
| 发布需求、提交报名、保存贡献 | 品牌蓝实心按钮，每个操作层只保留一个主要提交动作 |
| 地图“＋ 发需求” | 独立浮动入口，可用皇家蓝；不附着公寓卡 |
| 公寓密码 | 深色高对比数字；不蓝底包围密码，不把“看到密码”做成额外 CTA |
| 展开历史 | 卡片自然展开，轻量手柄/箭头；不新增卡外大按钮 |
| 有用/没用 | 记录内中性操作；选中后图标/文字/边界表态，非两颗并列实心品牌按钮 |
| 添加/更新密码 | 展开卡内入口，进入编辑后提交按钮才采用品牌色 |
| 取消、返回、更多 | 中性文本或浅表面，不与主动作抢层级 |
| 删除、撤回需要确认的操作 | 使用危险语义及明确动作名称，不能复用品牌蓝掩盖后果 |
| 当前排序第一的码 | 只表达实际排序依据和时间，不用品牌徽章把它包装成官方认证 |

独立浮动发布入口是持续入口；面板中出现提交动作时，可以暂时收起或降低发布入口层级，避免两个同权重大按钮争夺焦点。阅读公寓卡时不强制收起地图工具，只处理实际遮挡。

## 5. 关键交互的设计优化

### 5.1 公寓现场

默认流程是识别后直接给地址和第一条可展示记录，而非欢迎页、搜索教程或功能入口集合。用户展开时保持地址可辨认，历史列表在面板内滚动；反馈后避免整张面板突然跳动。需要更新排序时保持当前操作记录的视觉锚点，并让下一次收起摘要采用新结果。

切回承运商 App 再回来，恢复所选公寓与展开位置；除非用户主动回到当前位置，否则新的 GPS 点不能抢走阅读。候选不明确时让用户选栋；不要用强品牌色把猜测结果装成已确认。

多条记录中的关键信息顺序：密码/进入方式 → 必要适用范围 → 贡献与实测时间 → 本条反馈操作。手机号、住户资料和包裹面单不作为贡献图片要求。第一版没有入口/停车独立菜单。

### 5.2 配送支援

任务卡应让司机先判断愿不愿意去：区域、开始时间、数量、价格单位、剩余缺口。展开后说明取件区域、理货、接手条件和最晚要求；品牌蓝只承担报名/联系这类下一步。

用户能接一部分时，报名表允许输入可接数量；表单不默认将全部数量当作承诺。报名成功后进入带需求来源卡的会话，消息失败和报名失败分别处理，防止重复报名。私下结算约定按文字呈现，不设计支付完成态。

### 5.3 可用司机与 DSP

司机声明可用时段后，即使关闭或切出 App，找人区域卡仍按声明时间计算。文案不写“在线即可接单”；截止时间到后停止作为可用对象推荐。工作经验标明自报/已核验，不能用品牌色认证章代替实际核验依据。

同一个端的组织来源显示具体联系人，用户不需要在司机/DSP 两套工作台之间切换。常联系的价值是能再次找到合作过的人，不是公开的司机追踪或能力排名。

### 5.4 社区与品牌温度

首版司机圈用真实互助文字、需求卡、基础回复承载人情味。避免用虚构头像墙、活跃人数和品牌口号制造热闹。趣事、租车/租房等先允许普通内容表达，不因品牌升级扩成生活服务市场。

## 6. 开发前应补齐的设计系统交付

建议保留 V2 的基础尺寸与字级，V3 先完成语义色与核心组件升级，避免一次改色同时改布局造成无法判断效果。

| 层次 | 必须交付 |
|---|---|
| 基础令牌 | 品牌/中性/状态/位置颜色、类型与别名；间距、字级、圆角、触控、动效；原生与 Web 映射 |
| 基础组件 | 按钮、输入、选择、标签、分隔、头像、列表行；默认/按下/焦点/加载/禁用/错误 |
| 地图组件 | 公寓选择、位置点/精度、需求标记、司机区域、聚合、定位与独立发布入口、合法归属标识避让 |
| 面板组件 | 收起/中间/展开高度，面板和列表手势关系，键盘/安全区避让，选中与返回恢复 |
| 业务组件 | 密码记录与反馈、需求卡、司机卡、报名表、需求版本快照、文字会话、必要通知 |
| 全局状态 | 定位/权限、无资料、多候选、网络/重试、过期/关闭、提交幂等、撤回/删除、空列表 |
| 可访问性 | 字体放大、读屏名称、焦点与返回、颜色之外的状态表达、减少动效、地图候选可操作替代路径 |

保留基础触控 48px、主按钮 52px；实际代码按平台逻辑单位实现，不把设计稿 px 机械当作设备物理像素。主要密码使用清晰数字特性，并实际检查 `0/O`、`1/I`、`#/*` 与输入键盘。

## 7. 品牌方案如何验证

建议使用同一布局制作两个主要对照版本：A 为现有黑白主动作，B 为首推皇家蓝主动作；若团队仍需比较备选，深海蓝只作为同任务的第三个候选。只改变主品牌令牌和有限选择状态，内容、任务、地图和测试设备相同。不能根据三个不同颜色同时改了排版的页面判断颜色效果。

让真实司机完成门口查码、反馈、部分数量报名和返回原 App 的任务；记录首次找到关键数字/动作的时间、误触、是否认出当前公寓、是否把有用票误认为认证。休息时再问独立品牌记忆与归属，不在配送中进行长访谈。

测试覆盖室内/日光、常规与放大字体、iOS/Android、无固定码和多候选状态。比较的是任务表现和可辨认性；若司机把自有品牌误认成 Amazon 官方服务，应调整字标/构图/表达，而不只微调色相。

没有试测数据前，不写“蓝色提升转化”“司机更信任”或“国际化评分提升”的结果。对比不通过时可保留黑白按钮，品牌蓝继续用于识别资产和少量选择状态。

## 8. 本轮执行边界

本文件提供品牌色、操作层级、核心场景与设计系统升级建议；不修改已认可的首版业务范围、不改变密码有用优先规则、不新增结算、不扩展 DSP 工作台。现有 V2 令牌和模拟原型保持原状，待主代理综合官网观察形成统一方案后再同步。

主代理早先的一种访问方式收到 CloudFront HTTP 403，随后已通过普通浏览器完成 [Amazon Flex 官网](https://flex.amazon.com/) 的可视核查与只读计算样式观察。该访问限制现已解决，不能继续作为本轮未看过参考网站的结论。本文所述页面颜色来源于主代理的实际观察；当前没有官方品牌手册证据，不将页面 CSS 推广成 Amazon 全品牌标准。皇家蓝首推仍是待用户确认的 Abasong 自主方案。

# Abasong 设计系统 V3：原型制作基线

日期：2026-10-29。状态：用户已同意推荐方向，用于下一版原型制作；不是已完成的原生组件库或品牌商标定稿。依据：[V12.1需求补充](../Abasong_V12.1_需求补充与原型决策.md)、[页面规格](../product/Abasong_V12.1_页面功能信息与交互规格.md)、[V3顾问策略](Abasong_品牌与交互策略_V3_顾问建议.md)。本版替代 V2 的主动作颜色和相关业务组件规则；不改首版范围。

## 1. 设计目标

司机在公寓门口，应先看清“哪栋、哪个码、何时贡献”；找支援时，应先看清“去哪、何时、多少、多少钱、有什么门槛”。地图承担地点判断，面板承担条件判断，品牌色承担主要动作。

基础为黑白灰，品牌皇家蓝用于自有识别和关键执行。不能把页面、密码、反馈和地图同时铺蓝；也不借品牌色制造官方认证。设计说明、测试控制、业务策略写在原型外壳与文档，不进入App实际页面。

## 2. 语义色与基础令牌

| 令牌 | 值 | 用途 |
|---|---|---|
| brand.primary | `#1467D8` | 发布、报名、保存等关键提交 |
| brand.pressed | `#1054B3` | 主按钮按下 |
| brand.surface | `#EDF4FF` | 有限的选中浅表面 |
| brand.onPrimary | `#FFFFFF` | 实心主色上的文字/图标 |
| text.primary | `#101114` | 密码、地址、任务事实 |
| text.secondary | `#53565B` | 次要事实 |
| text.metadata | `#686C73` | 贡献/实测时间等，仍需读得清 |
| surface.canvas | `#F6F6F6` | 应用画布 |
| surface.card | `#FFFFFF` | 内容卡/面板 |
| surface.subtle | `#F0F0F0` | 搜索/次级表面 |
| border.divider | `#E3E4E6` | 非必要分割线，不代替输入边界 |
| border.control | `#82858A` | 必要输入/次级控件边界 |
| location.self | `#245CC4` | 自身定位点，与主色靠形状共同区分 |
| status.success | `#236346` | 已成功操作与有依据的状态 |
| status.warning | `#855307` | 待复核/条件待确认 |
| status.danger | `#AE3734` | 错误、删除/撤回等危险动作 |

白字/主色5.30:1，白字/按下7.14:1，主色/浅底4.79:1。指定色对已计算，实际地图、透明度、焦点、字体放大及设备仍需验证；不称整套无障碍认证通过。位置点与品牌对象不只靠两种蓝色区分。

间距4为基础，常用8/12/16/20/24/32；页面边距20、紧凑屏16。圆角控件10、卡片16、面板顶角24。触控区至少48逻辑单位，主按钮高52；文字放大时允许按钮增高和换行。原生单位使用dp/point而非设备物理像素，Web映射CSS px。

系统字体，不加载Amazon/Uber专有字体。字级：页面标题28/36、二级标题24/32、卡片标题20/28、正文16/24、辅助14/20、密码40/48；金额与时间使用tabular numbers。密码很长时换行/横向阅读策略需真机确认，不能为了塞一行缩小至难读。`0/O`、`1/I`、`#/*`必须清楚。

## 3. 导航、返回与布局

- 首页/司机圈/我的固定三导航，图标24、标签14；不随司机/DSP身份替换。
- 首页公寓/找活/找人为同路由状态；当前视图用字重/下划线表达，不做三个大色块。
- 顶部搜索和消息；消息进入二级列表，不加第四项底部导航。
- 所有二级流程使用返回，回到真正来源而非一律首页；保留区域/筛选/选中对象/滚动。
- 登录完成恢复原意图，刷新对象后由用户继续提交。系统返回与页面返回一致。
- 地图有可操作列表/候选替代路径，不把操作能力仅放在小地图点上。

参考画板390×844，同时验证375宽、430宽和字体放大。高度不能作为业务控件绝对定位的依据；顶部/底部避让系统安全区，键盘出现时提交按钮和最后字段可达。原型外壳可以显示流程目录，手机画面中不显示测试备注。

## 4. 地图与面板组件

| 组件 | 默认行为 | 状态/约束 |
|---|---|---|
| 中性底图 | 保留必要道路、建筑、地名 | 归属标识可见，不被卡片/导航盖住 |
| 自身位置 | 蓝点+精度光环 | 粗略/旧位置不制造精确楼栋感 |
| 公寓建筑 | 一般建筑轻灰；选中才用主色轮廓/浅填充 | 未知building不伪装已识别公寓 |
| 需求标记 | 黑白数量/价格/需求标签，选中与卡同步 | 议价显示议价，不写$0；区域中心不是取件点或司机位置 |
| 司机区域 | 区域轮廓/聚合与档案卡 | 无精确行驶头像、不常驻轨迹 |
| 回定位 | 独立地图工具 | 用户主动触发才解除选中锁定重新匹配 |
| ＋发需求 | 独立主色浮动入口 | 不放公寓卡内；编辑/提交流程中隐藏，避免竞争 |
| 公寓面板 | 收起展示核心内容，点击/拖动展开 | 展开保留所属地址；记录列表在内部滚动 |

面板初始规格：收起按内容测量，常规约176–220逻辑单位；中间约可用高度52%；展开最大约86%，均要避让导航/系统区。比例是原型起点，允许按真实内容及放大字体调整，不把超出高度的密码直接裁掉。可见记录数量随空间变化，不强迫每屏固定三条。

拖拽只由手柄/面板顶部发起；内部列表非顶部向下滑时优先滚动列表，抵达顶部再允许收起。列表操作按钮不触发整卡展开/收起。减少动效偏好下取消大幅地图飞行。普通过渡160–240ms，面板约280ms；不以动效延迟密码出现。

## 5. 公寓信息组件

收起：名称（有则显示）→英文地址→排序第一的可展示密码/方式→贡献时间/有依据的状态。没有码则真实空态与卡内添加入口，不增加卡外说明/按钮条。

展开：固定公寓身份→每条记录的密码、必要适用范围、贡献时间、最近实测→本条有用/没用→内部添加密码入口。当前有用优先、同组贡献时间倒序；不用票数徽章把记录包装成官方保证。

反馈默认中性描边/图标，选中有清楚文字/形状；错误回滚本条状态。重排不把用户手指下的记录突然跳走：保留当前记录锚点并在下一次收起后更新首码；顺序最终必须与服务端一致，不能永久固定旧排序。

更新密码进入编辑后“保存密码”为主按钮，原纪录不覆盖。待审核反馈“已提交，待审核”只在必要回执出现，不在首页长期挂说明。来源确认仅在贡献时进行，不每次查询弹长段声明。

## 6. 需求与司机组件

### 6.1 任务卡

支援任务信息：配送区域→报价与单位→本次包裹量/剩余缺口或所缺人数→具体日期/开始时段→最低承接量（有则显示）→取件区域。卡片保持4–6条关键事实，条件全文在详情。所有需求都服务本次配送，不出现长期招聘卡。

详情展开理货、账号/接手要求、相关配送经验、最晚时间和发布者私下付款约定。宣传总量/线路总供给不放到个人承接数量位置。未知信息如实“联系确认”，不推导时薪、当天收入或司机到场时间。

本人主按钮“管理需求”；他人开放需求主按钮“报名”，联系为次级；已报名主按钮“继续联系”；终态保留“查看报名/历史联系”，不仍显示可报名。按钮层级按当前任务决定，不能同屏三个大蓝按钮。

### 6.2 表单

分为基础区域、时间数量、接手条件三组，非三套复杂流程；可选字段折叠。每条配送支援都明确具体日期、当次包裹量和开始时段；选择联系议价后不填假金额；整线显示不可拆分。没有长期招募、入职、带教和试线专用表单。

每个输入始终有可见标签，不能只靠placeholder。货币前缀USD/$、单位后缀与输入分开。错误在对应字段附近，顶部只显示一个必要汇总，草稿不因错误清空。提交中防重复；失败保留普通草稿，敏感密码草稿仅会话内存。

### 6.3 司机卡与可用状态

显示主动声明区域/时段、容量和相关经验。可用、在线、核验为三种不同信息，不复用绿色点代表全部。头像不放在精确坐标上暗示实时追踪；无可用声明的联系人仍有基础档案，不能把该人整体隐藏。

## 7. 基础组件状态矩阵

| 组件 | 默认 | 操作中/选中 | 失败/不可用 |
|---|---|---|---|
| 主按钮 | 皇家蓝白字，明确动作名 | 按下深蓝；加载保留文字与指示 | 禁用用中性背景，不靠透明度隐掉字；相邻说明必要原因 |
| 次按钮 | 白底/控件边界/深字 | 字重或浅表面 | 不与主要提交同权重 |
| 输入 | 可见标签与单位 | 焦点主色边界+清楚焦点环 | 红边+字段错误文本，非仅变红 |
| 反馈 | 中性文字/图标 | 本条状态与可取消行为 | 网络失败回滚，不累计假票 |
| 需求卡 | 当前条件与状态 | 选中与地图同步 | 终态禁报名，历史仍可查看 |
| 消息 | 发送者/文字/时间 | 本人发送中；失败旁重试 | 不称对方已读，重试复用消息ID |
| 状态行 | 文字+必要图标 | 加载局部骨架/指示 | 空态/错误不冒充真实内容，不生成假资料 |
| 公共确认 | 明确具体动作与对象 | 危险动作采用危险语义 | 取消不改状态；删除账户显示真实任务进度 |

## 8. 内容、语言和访问性

中文操作、英文地址、USD、mi、当地AM/PM和跨日日期；跨区显示时区，不能按手机所在地悄悄改任务时区。固定术语：公寓/找活/找人、发需求、有用/没用、报名、已联系、已找到、已关闭、已到期。已联系不改写为已到场，已找到不改写为已结算。

所有可操作元素有读屏名称；地图有候选/列表替代；焦点进入弹层后不跑到底图，关闭恢复原触发点。状态不只依赖颜色。字体放大200%至少保证主要流程可操作，密码/金额/关键单位不能截断。真实手机号、微信、二维码和住户信息不进原型示例数据。

## 9. 制作交付与评审

首批交付：H01+S01+L01+B01+B02+A02–A04及G01/G03状态，演示完整门口查询/纠错/贡献/反馈。之后依目录制作找人找活/分享、消息/常联系、最小社区/我的。每批同时提交正常及关键异常，不能只交“好看”的成功画面。

按四条真实任务评审：门口查码、发支援并管理报名、找活并联系、日常设置/交流；不要求用户逐页重复批准同一基础控件。通过后标记原型版本并冻结本批；后续更改可追溯，不称永不修改的最终版。

令牌文件位于 `tokens-v3.json` 和 `tokens-v3.css`，为新版独立资源；旧目录的V2令牌和preview.html未在本轮覆盖。品牌图标与完整组件库由后续制作交付，不用网页对照图冒充原生组件已开发。

## 我的公寓组件增补

“我的”只提供“我的公寓”入口；U06双栏目“我保存的/我共享的”，截图添加与手动添加为页内操作。U09以“我的记录·仅自己可见”和“共享资料·随资料库更新”分区。保存按钮明确范围，默认私存；共享单独确认。贡献卡显示查看/有用/不能用及最近反馈，不能把查看宣称为成功进入。沿用V3蓝色关键操作与原有排版，不新增第四导航。

# Abasong D1 UI/UX评审与优化建议

日期：2026-10-30（America/Los_Angeles）。评审对象：`dc19a09`原生视觉实现、当前本机对照页与截图、V12.1逐页规格/ADD-08/截图P0补充及最新扩展原型。采用UI/UX设计顾问视角，由Codex完成；没有声称邀请了真人设计师或完成独立司机可用性研究。

本次为评审建议，不修改产品基线、已认可原型或应用代码。缺项分为已确认需求未实现、现有实现需要修正、待验证风险和新增设计建议，不能把建议写成已批准需求。

## 1. 结论

地图主导、三导航、浮动搜索、卡内层级与皇家蓝方向应保留。当前已经从工程表单转为接近原型的产品结构，但仍未达到首版完整UI/UX验收。最重要的差距是贡献效率、查码成功态与异常恢复，不是更换品牌色或再做一套视觉风格。

当前对照主要覆盖定位空态、搜索、私人添加和私人库。原型未开启定位，iOS可能已获授权但无法取得模拟器位置；这些是同类布局对照，不是同一权限/数据状态。真实Mapbox底图、系统安全区和开发齿轮不作为产品设计缺陷；齿轮遮挡消息/刷新位置会干扰截图判断，正式验收应排除该开发浮层。

## 3. 页面优化方案

### 首页

维持“搜索/消息 → 地图视图 → 公寓与当前位置 → 唯一卡片 → 三导航”。发需求保留独立地图操作位置，但不应在暂未开放时比可用的查码路径更像可点击主操作。品牌蓝用于真正可执行的关键动作和选中态，不增加大片蓝色背景。

卡片默认优先英文地址与当前可用记录，名称可辅助识别；只有必要门别/时段才增加信息，避免回到楼宇/入口/停车等多菜单。无密码时添加前置，已有密码时反馈只在展开层。避免把“贡献时间最近”“有用反馈”“刚验证可用”混为同一个可靠性标签。

空态图标、垂直留白和卡片高度先保持原型基线。若现场测试证明空态占用过大，再提议压缩；当前不把审美偏好包装成必须重做的需求。定位失败恢复动作调整属于本次新增建议，确认后同步原型/页面规格再改代码。

### 搜索与贡献

搜索页进入后应易于立即输入，搜索提交/清空/等待/无结果须可辨；是否自动弹键盘应在真机与返回路径上验证。已有明确公寓时不得再次要求输入完整地址。未收录公寓的提议和仅私存要明确区分，不能为了少一步静默共享到相邻楼。

U01贡献入口的主要路径应是截图，手填作为快速替代；来源声明、门别与符号保留是必要信息，算法解释不是产品字段。批量确认优先可提交项，歧义项可以留待处理；私存和共享采用明确范围及不同提交文案，沿用ADD-08。

### 我的公寓与我的

保持“贡献”高于“管理”的层级，不把两者合并回同质列表。私人卡片直显密码是正确方向；区域筛选、私人/共享标识、取消收藏与删除范围是后续完善重点。退出登录移入合理的账号操作区域或降低视觉权重属于可选精修，不抢占查码/截图主线。

## 4. 建议实施顺序

1. 先形成独立的核心卡片验收场景清单，验证成功/无密码/无资格/无固定码/长地址/时段/失败状态；不等到真实共享数据准备好才看成功态。
2. 在下一批D1工作中补齐截图贡献入口及流程，并同步大字、搜索选中返回首页、反馈锚点/收藏状态等已有需求差距；OCR真实处理按原计划，不以视觉占位替代。
3. 修正未开放功能的可用性表达和定位失败恢复；新增建议确认后更新原型/规格。
4. 最后精修图标、字号、动效与安全区，做双端真机/字体放大/读屏。不要重新选择品牌色、增加第四导航或改造成配送任务管理App。

## 5. 验收证据要求

设计场景与业务实测分别记录；每张图标注数据状态、权限状态、设备和版本。至少覆盖：门口查到码、点码放大、错误楼栋切换、无码添加、截图多图确认、定位失败转搜索、私存编辑不改共享、反馈失败/重排不丢位置。未测不能用“看起来一致”代替通过。

可用性测试建议观察司机能否完成任务、首次点击路径、重复输入/重试次数及错误恢复；先收集结果，再制定时延/成功率目标，不承诺未经实测的“几秒查到”。

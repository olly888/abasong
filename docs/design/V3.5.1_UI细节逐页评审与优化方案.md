# V3.5.1 UI 细节逐页评审与优化方案

日期：2026-11-09（洛杉矶）。状态：**DTL-01–03各自范围完成，build3已安装iPhone13Pro。** [DTL-03报告](../technical/V3.5.1_DTL-03_可见读取回程与签名包验收.md)记录双端核心区读取、慢响应与贡献回程，及真机首页／搜索返回确认。下一批DTL-04；下文保留方案论证，不将初版“未运行原生”解释为当前状态。

本轮目标：保留用户选定的 Muse「上方地图、下方纵向卡片」结构，让地图更好用、三模式卡片真正统一，并收敛二级页的阅读和操作细节。品牌继续使用 V3.3 正式资产；V3.4 表单行为、V3.5 业务与权限规则继续有效。

## 1. 结论与证据边界

建议采用：**较大的固定地图区＋固定三模式栏＋一张完整的标准卡＋下一张标题行预览**。三模式共用同一个 `HomeResultCard` 槽位组件，普通字号下统一高度。纵向滚动继续保留，不改回横向滑卡。

“第二张只显示地址”应当是**首屏可视范围**，不是把第二张变成另一种折叠卡。向上滚动后，第二张仍显示完整卡片；返回、贡献成功或点地图对象时，目标卡片成为第一张完整可见卡。这样不增加点击展开的步骤，也不会破坏三模式等高。

本轮证据：

- 重新阅读本地归档的 [Muse 逆向 PRD（22 页）](references/muse-20261108/abasong-app-prototype-prd-2026-11-08.pdf)，重点对照第 6、9–18 页；原始资料说明见 [归档索引](references/muse-20261108/README.md)。没有声称重新检查了远端 Muse 的最新版本。
- 实际打开本地 `?layout=muse&v=m1` 原型，测量 390×844 首页；通过检查器遍历 36 个入口并读取页面结构。入口遍历不是 36 页全部交互验收，部分入口需要先建立业务上下文。
- 检查当前页面目录的 39 个活动节点及关键组件源码；关键首页、表单、我的页面的 7 个文件与冻结候选 `3e36678` 一致。
- 视觉检查包含已有 iOS 原生首页证据、M5/M6 的 RN Web 组件截图，以及本轮“我的”原型截图。历史截图与 RN Web 图不能代替本轮双端原生验收。
- 本轮未改 App、接口、数据库、资格或云环境；没有重新要求用户操作手机。

## 2. 首页空间分配

### 2.1 先按内容计算，再确定地图比例

不把所有手机写死为 55% 或 60%。扣除系统顶部安全区和底部导航后，按下方必须可见的内容反算：

```text
可用内容高 = 屏幕高 − 顶部安全区 − 底部导航总高（含底部安全区）
标准下方区 = 顶部留白12 + 模式栏56 + 工具行48
           + 列表顶部4 + 首卡180 + 卡间距12 + 下一标题预览44
           = 356
地图高 = 可用内容高 − 356
```

**180 已成为正式原型与 DTL-02 原生标准字号的基准，三模式均通过本批尺寸核对。** 长码与放大文字允许增高，不允许通过截断正文实现等高。若原生实测需调整，应整组调整，不为每个模式各取一个数。

| 参照条件 | 现状 | 本提案计算值 | 说明 |
| --- | --- | --- | --- |
| 390×844 浏览器原型，顶部 34、底栏 73，可用 737 | 地图约 310 | 地图 381；约增加 23% | 同一原型坐标口径，可直接比较 |
| 390×844 原生示例，假设顶部 47、底栏 94，可用 703 | 42% 约 295 | 地图 347；约增加 18% | 安全区是假设值；运行时必须实测，不能当成本轮 iPhone 测量 |

正常竖屏下，地图大致占可用内容的一半。首屏重点是多给司机看清周边建筑的空间，同时完整显示第一张卡。过度追求 60% 会再次截断卡片或挤压操作区。

### 2.2 首屏与滚动行为

- 三模式的分界位置、工具行位置、卡宽和普通卡高一致；切换时地图与面板不跳高。
- 查码初始第二张只露出门牌、街道和同一标题行上的距离，不露城市、半条密码或底栏。
- 找活、找人采用相同预览节奏，分别露出下一条配送区域/标题、司机姓名与状态，不伪装成公寓地址。
- 只有一条结果时不制造假卡、假地址或“还有更多”提示；保留同一布局，底部自然留白。
- 滚动列表不改变地图高度。列表滚动与地图手势分区；不加入多段拖拽抽屉或会自动缩小的地图。
- 地图点选某公寓、贡献成功返回时，以对象 ID 定位列表，让该卡完整露出；不只高亮一张仍在屏幕外的卡。
- 用户主动拖图后，列表滚动更新选中标记，但不强制反复飞地图；定位按钮恢复附近推荐。三模式各自保留筛选、位置、缩放和阅读锚点。

### 2.3 地图与顶部控件

- 保留 Muse 的品牌＋消息、下方搜索组合；品牌字标不重复出现在结果标题、卡片、表单页头。
- 字标宽至少 120；顶部消息、搜索、定位保持至少 48 的独立热区。不能通过缩小热区给地图“腾空间”。
- 顶部组合尽量控制在约 112–116 高，清除重复外边距；先增加地图视口，不另做一套全屏地图首页。
- 定位固定在可见地图右下；比例尺和 Mapbox 归属位于左下且不被面板遮挡。不能因为换组件而删除归属。
- 相机可视内边距取真实 header/定位/面板尺寸，蓝点和选中建筑避开覆盖；扩大地图不能靠缩小建筑或更改定位坐标实现。
- 公寓优先突出选中建筑和门牌，距离是辅助。找活用仓库/任务区域，找人用服务区域汇总；不为统一卡片而制造司机精确距离或实时位置。

### 2.4 小屏、大字及异常

- 标准竖屏、普通字号：采用统一卡高，满足一张完整卡＋下一标题。
- 可用内容不足约 596 时（地图 240＋标准下方区 356），启用短屏布局：先取消第二张预览，再压缩非交互留白；不要把首卡裁掉。240 是原设计起点；DTL-01 浏览器实测 320×568 时改为最小地图 160，以保留完整首卡，360×640 地图为 221。原生须按实际安全区校准。
- 系统字体放大：同一组件、同一适配规则；优先让完整内容可读、列表可滚动，允许卡高增长并取消首屏第二张预览。不锁字体倍率，不在卡片内部再套一个小滚动区。
- 32 字符门禁码、长地址、跨日时段作为压力样本。普通副信息可在摘要省略并在详情完整显示；门禁码、金额及关键单位不截断、不自动缩小到难读。
- 如必须严格要求所有大字号也绝对等高，需要按三模式最坏内容共同提高高度，而不是藏字。本方案不建议为这种形式一致牺牲可读性。
- 空结果不放空白的 180 高假卡：复用状态组件，保留面板边界和模式栏，状态说明＋一个有效操作。加载用相同骨架；失败保留地址，不能冒充“暂无门禁码”。

## 3. 三模式统一卡片规范

### 3.1 统一到结构，不统一业务含义

建议直接升级现有 `HomeResultCard`，不是再造第四种卡片。它管理几何、选中态、按下态、读屏分组及槽位；数据解析仍由各业务容器负责。

| 槽位 | 查码 | 找活 | 找人 |
| --- | --- | --- | --- |
| 标题 28 高 | **2445** E Del Mar Blvd；右侧约 80 m | West Covina；右侧承运商或状态 | 头像＋昵称；右侧可接活/待开始 |
| 次行 18 高 | Pasadena（必要时 CA），不用重复公寓名称 | 仓库找司机 / 途中代送 | 主要服务区域，超长摘要省略 |
| 核心条 48 高 | 完整门禁码；右侧门别 | 单价及单位／联系议价；右侧件数与缺口 | 可接活时段，跨日时可两行 |
| 底栏 36 高 | 贡献时间＋用户名；可见记录数与详情箭头 | 到场时间；仓库取件区域或途中交接 | 容量与车型；承运商经验，注明自报 |

共同参数（首轮）：页面左右边距 16，卡宽=可用宽−32，内边距 14，圆角 16，边框 1，卡间距 12。内部为标题区 46＋间隔 10＋核心条 48＋间隔 10＋底栏 36，加上下内边距及边框，共 180。

- 标题门牌 22/28、700；街道 16/24、400。完整地址在详情、搜索候选和贡献确认中展示。首页城市另作次行，不挤在门牌后。
- 核心门禁码 28/34、700；价格 24/30、700；时段 16/22、600。三者视觉重量接近，不强制把时间也做成巨大数字。
- 次行和底栏采用 12/18 或现行对应 token；核心辅助量采用 14/20。关键操作不降到 12 字号。
- 选中：浅蓝底＋蓝描边；未选中：白底＋中性描边；使用同宽边框，切换不改变几何。不要对每个蓝色文字再套蓝色背景标签。
- 距离作为近似位置参考，沿用已有距离契约；地址边界与代表点的不同口径只在必要的解释中交代，不恢复“至边界”标签。过期或无定位时不显示假距离。

### 3.2 各状态都占同一槽位

| 状态 | 核心条与操作 | 底栏 |
| --- | --- | --- |
| 有权且有门禁码 | 原样正文＋门别 | 贡献时间、用户名、可见条数 |
| 成功读取但无门禁码 | 「暂无共享门禁码」＋「添加」 | 必要地址核对状态，不伪造贡献者 |
| 读取中 | 等高骨架／读取中 | 不残留上一公寓的时间和姓名 |
| 读取失败 | 「读取失败」＋「重试」 | 保留当前地址，详情解释错误 |
| 无查看资格 | 清楚的资格状态；有效时提供登录或查看资格入口 | 不泄露记录数量、正文及贡献者 |
| 暂停共享 | 「暂不共享」 | 不展示不可能成功的添加按钮 |
| 地图临时候选，地址未确认 | 「地址待核对」＋「核对」 | 不把不确定门牌绑定已有密码 |

“添加／重试”必须放进预留核心槽位，不再追加到卡片外或底部形成第四块。独立按钮有自己的热区；与整卡“查看详情”事件不重叠。标准字号超出时先调整槽位，不简单 `overflow:hidden`。

### 3.3 第二张预览涉及读取与选择规则

当前 `HomeResultList` 以整卡可见 15% 作为可见项。新布局下仅露出 44 高地址仍可能超过这一阈值，不能继续据此推断“司机正在看第二张门禁码”。

实施时区分三种状态：

1. 地址行进入视口：显示地址预览，不触发选中和镜头跳转。
2. 核心信息区实际进入视口并稳定：允许按原有资格和并发限制读取该对象；请求与对象 ID、会话版本绑定。
3. 用户点选或目标卡成为主要阅读项：更新选中标记；读取失败只影响该卡。

这不是重新设计接口。复用现有可见对象读取器、过期清理、慢响应隔离和账号切换保护；新增核心区域的可见判定。VoiceOver/TalkBack 聚焦时应把对应整卡滚入可视区域，隐藏的第二张不能成为无法看见却可提交的按钮。

## 5. 表单专项：减少阅读和输入，不减少必要信息

### 5.1 仓库找司机

**首层必看顺序：取件与派送 → 到场安排 → 人数/件数/报价。**

- 仓库地址联想点选后显示完整摘要及“更换”；不常驻城市/州/邮编四个输入框。手动填写才展开这些字段。
- 同时选择派送区域：仓库在哪里与包裹送到哪里不能合并，不能由仓库所在地静默替代派送区域。
- 快递公司用常用选项＋其他；人数步进器；件数“确定/约数/待确认”；报价保留既有“按件/按线路/联系议价”口径，不把费用估算当实际收入。
- 到场日期用今天/明天/其他，时间用原生选择器；必须展示最终具体日期、时间和洛杉矶时区。不要显示“今天”却保留已经过去的时间。
- 下架时间与到场时间不同：保留现行默认计算，核对页显式呈现。不要为了短表单静默修改业务截止时间。
- 接手要求、补充说明和身份设置用折叠摘要；有填写内容或错误时自动展开。折叠不代表清空。

### 5.2 送不完，找人代送

- 默认展示交接地区，不强制填写仓库地址；保留司机切换取件方式的已有能力。
- “尽快接手”与指定日期/时间二选一；不是把“尽快”解释成平台保证有人接。
- 剩余件数可待确认、报价可联系议价；保留账号/转派要求的简短选项，必要说明再填写。
- 车型、特殊包裹等没有已批准字段时不在此次样式升级中新增。

### 5.3 核对页、错误和返回

- 核对页无需复制全部表单边框：报价摘要一块、各组事实列表、组右侧“修改”。已有 `DeliveryReview` 已采用这一方向，继续微调而非重做。
- “返回修改”与顶部返回、系统返回保持一致，回到相关组并保留滚动位置。错误定位到第一处问题，字段下短句解释；其他组不清空。
- 提交结果未知时保持原稿和幂等标识，按钮“重试”；不得改成“已发布”或新生成一份需求。
- 标准字号保留单个底部主要动作；大字/键盘按现有 PageFrame 流式行为可滚动触达。不要重复顶部和底部两个同色提交按钮。

## 6. 品牌、图标及组件约束

- 品牌主蓝 `#1769FF`、浅蓝选中底和深蓝文字继续来自现行 token；主文案黑/深灰，元信息次灰。无新的渐变、装饰横幅或另一套“高级蓝”。
- 图标继续使用已有 Lucide 映射及 `Icon`，常规 24、辅助 20；热区统一至少 48。静态设计示意不能引入另一套图标到正式 App。
- 统一的重点是 `HomeResultCard / PageFrame / SelectionField / ChoiceChip / ActionButton / StatePanel / ListRow / BottomSheet`。不更换 RN/Expo，不因细节问题整体改 SwiftUI 或引入新 UI 框架。
- 首页三模式卡必须同组件、同高度策略；帖子、聊天气泡、完整表单、详情页不强迫套成相同 180 高卡。它们共享字阶、间距、边框和动作规范。
- 表单和详情不用处处显示 logo；品牌以一次正式字标、主操作、选中态、焦点和一致图标体现。

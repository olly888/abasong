# V3.5 · M1.1 原型细节对比与优化

2026-11-08。用户要求对比原型细节、提出专业建议并继续优化。本批仅更新浏览器原型与文档；手机内测包、API、权限和数据存储均未变。

## 1. 结论与证据

Muse 值得吸收的是连续的阅读层级：品牌与搜索 → 地图对象 → 三模式 → 主要信息条 → 详情。上一版 M1 已实现上下结构，但找活、找人的筛选又占一整行，列表被压缩；来源和信息数量单独排两行，公寓卡偏高。继续压缩固定工具区域、重排卡片信息，比再加阴影、色块或更换框架更有效。

本次重新打开并操作了 [Muse 原型](https://muse.ai/s/abasong-app-yuan-xing-xtxx6hkxqst3ah/w-8f71Q2ZfMyTowd3NUI7htmUg77EBKqUiGmY67OcHw)三个模式，核对归档 PDF 第 9–11 页，保存三模式参考截图。以本机 390×844 原型测量前后尺寸；参考稿手机框内宽度不同，不把参考截图当成逐像素尺寸基准。

## 2. 逐项判断与落地

| 细节 | 原型对比与问题 | M1.1 处理 |
|---|---|---|
| 上图下列比例 | M1 地图占可用高度 46%，找活/找人的首张几乎填满列表，没有下一条线索 | 普通屏调整为约 42%/58%；小屏按可阅读内容适配，不强制所有设备同像素高度 |
| 三模式工具区 | 找活/找人比查码多整行筛选，切换后列表起点跳动 | 三模式共用起点。筛选用带文字的轻按钮放在分区行；有条件才在列表顶部显示摘要，可一键清除 |
| 公寓阅读顺序 | M1 门别标签先于门禁码，来源与统计各占一行 | 地址数字 → 完整门禁码沿左侧阅读；门别放码条右侧；城市单独弱层级；时间/用户名与条数合并尾行 |
| 地址长度 | 把州和邮编放卡片辅助行，增加密度 | 卡片城市即可；详情保留完整城市、州、邮编。长街道单行省略，无障碍名称保留完整地址 |
| 当前焦点 | M1 选中边框叠阴影容易显重 | 蓝边、极浅底色足够；常态细边框。状态变化不改变外框尺寸 |
| 价格信息 | Muse 价格条帮助判断，M1 报价与件数分散 | 数值报价左侧、件数及缺口右侧；到场时间单列；取件区域留尾行。议价与待确认不伪造数字 |
| 司机信息 | M1 将容量突出为唯一主信息，未来时段也一律写“可接活” | 时段放核心信息条；愿去区域、容量与车型次之；未来显示“待开始”，跨日写明结束日期 |
| 找人距离/实绩 | Muse 有约距、日均件数、完成支援数；当前资料不支持相同口径 | 不抄这些示例。地图继续区域聚合；经验标自报，容量不改称日均实绩 |
| 地图标记含义 | 所有对象都画钥匙，无码对象易被误解为有可读门禁码 | 当前可读且有记录才画钥匙；无码、读取失败、无资格等用中性位置标记。不能从图标旁路暴露受限正文或数量 |
| 整卡与内部动作 | 可点击整卡中嵌按钮，键盘语义和误触处理不清楚 | 使用独立详情按钮与独立添加/重试按钮；Enter 可进入详情，直接添加只进入表单 |
| 小屏消息入口 | M1 低高度隐藏整条品牌行，同时藏掉消息 | 仅收起字标展示，消息保留在搜索旁，操作目标仍至少 48 |
| 无码与失败 | 同样是没有密码可显示，但司机下一步不同 | 无码前置添加；失败重试；无资格/暂停各有状态，不冒充“暂无共享码” |

**统一的是卡片骨架、间距、字阶和动作，不强行让不同内容占同样高度。** 标准公寓卡更紧凑；跨日时间、长来源或大字号可以增高，不能裁切来保持形式一致。

## 4. 保留与不采用的参考细节

- 保留官方字标、品牌蓝和单套 Lucide 图标；蓝色用于选择、数值报价和行动，辅助信息用中性色。不为本批重新定义一套品牌。
- 不添加“你已到达”“入口正确”等标签。附近候选不等于已确认配送对象。
- 来源时间和用户名是判断门禁信息新旧的依据，不为缩短卡片删除。没有接口依据不展示“12 位司机确认过”。
- 保留两场景、联系议价、待确认件数、仓库地址受权详情、本人纠正。团队优先、强制油补、分拣第三场景不随视觉对齐进入本批。
- 不加入不可拖动的假手柄、多档抽屉、卡片自动轮播。普通滚动只滚列表，停稳联动选中，切模式/详情返回保持位置。

## 6. 下一步原生落地依据

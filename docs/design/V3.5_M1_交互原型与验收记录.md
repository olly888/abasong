## 已实现的结构与交互

| 部分 | 本批实现 |
|---|---|
| 首页布局 | 真正上方地图、下方列表；可用高度默认约 46%/54%；列表单独纵向滚动，无抽屉拖拽假手柄 |
| 三种模式 | 查码 / 找活 / 找人固定在内容区顶部，仅一组；取消此首页重复地图/列表切换 |
| 品牌 | 使用官方字标；品牌蓝选中态、主操作；复用现行 Lucide 图标。三类独立卡共用边框、圆角、间距和层级 |
| 查码卡 | 门牌重点、街道常规字重、城市次级、距离 m；完整合成门禁码、门别、贡献时间和用户名；暂无记录可直接添加 |
| 找活卡 | 两场景、配送区域、报价单位、数量语义、到场时间、仓库/交接区别；继续进入已有需求详情及报名 |
| 找人卡 | 自报配送经验、服务区域、可接时段与件数；地图仅展示服务区域聚合，不模拟司机精确位置或编造距离 |
| 地图联动 | 点公寓标记滚到对应行；纵向滚动停稳后按焦点线选卡并高亮；不因选中某司机改变区域筛选 |
| 浏览记忆 | 分模式保留滚动、选中、筛选和示意镜头；详情返回保留原位置；定位只重置当前模式镜头，找人筛选仍保留 |
| 贡献回程 | 卡片和“我的”复用统一贡献表单；非首张成功后回原公寓；本人纠正保留符号/前导零并隐藏自己的旧值 |
| 空态与异常 | house 附近仍有公寓、附近无匹配、定位关闭、未登录、无查看资格、共享暂停、单行读取失败、慢响应、筛选无结果分别呈现 |

地图与资料均是**合成演示**。示意图缩放、距离和选中不能当成 Mapbox 覆盖或定位精度验收。多行门禁码来自各自的合成记录，不接真实业务库；M3 的逐对象授权、并发与缓存失效仍待开发。受控扩围、真实可视覆盖、跨账号权限、系统地图手势仍分别留在 M2–M4。

小屏策略：320 宽可以阅读并滚动；屏高 ≤650 时缩小地图占比并收起顶栏字标行，保留搜索、定位、三模式和操作，优先保证列表可用。大字号压力场景是原型字体增大检查，不等同 iOS Dynamic Type 或 Android 系统字号验收。

## 建议按此顺序体验

1. 查码：上下滚动到第二/第三张，点击地图对应标记；进入详情再返回。
2. 第三张无码公寓：添加合成门禁码，确认回原卡；进入详情可纠正自己的合成贡献。
3. 找活/找人：筛选区域与日期、点区域、进详情、回首页、切换模式；核对视角及浏览位置保留。
4. 桌面左侧分别切换定位关闭、无匹配、单行失败和慢响应，检查信息是否容易理解。

主结构确认后进入 M2 原生共用分区/卡片/模式记忆；随后 M3 实现多可见公寓的独立受权读取及回程。不会把这次浏览器通过标成双端已对齐。

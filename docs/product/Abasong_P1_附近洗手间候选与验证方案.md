# Abasong P1「附近洗手间」候选与验证方案

版本 0.1，2026-11-08，洛杉矶。状态：用户认可方向，纳入 P1 候选；未进入正式开发排期，未实现原型/API/原生页面，未采集门店密码或开展现场验证。

## 1. 决策与范围

目标：帮助配送司机尽快找到能使用的洗手间，减少绕路和白跑。可共享的洗手间门禁码只是其中一种进入信息。

- 当前主线仍为 V3.5/M7 双端原生集中验收，不改变已冻结的候选源码、远程 CI 证据、云部署或签名包。
- 在 West Covina 一带先验证 10–20 个地点，再用轻量原型核对价值与交互，决定是否进入 P1 实现。地点目标数不代表已经采集或验证。
- 地点不限于麦当劳、星巴克；可包含有公开信息或现场确认的公共设施、加油站、商场等。品牌名称不构成可用性依据。
- 保持首页/司机圈/我的及查码/找活/找人结构，不新增第四个首页模式，不在公寓底图默认铺满门店标记。
- 不新增付费、广告竞价排名、自动派单、配送路线采集或人工逐条审核工作台。
- 此文确认候选方向和验证计划，不是可直接生成代码的最终 API/数据库契约，也不宣称上线承诺。

## 2. 证据与待验证假设

2026-11-08 补充[产品、API 与公开资源研究](../research/附近洗手间产品_API与公开资源调研_2026-11-08.md)：已找到 FlushPin 等直接参照，并实测 REFUGE 城市检索返回 5 条 West Covina 记录、核对洛杉矶官方地图六个公开 CSV。它们是资料线索，不等于现场可用或已获商业导入许可；WC-02 的地点使用条件验证仍未完成。没有采集密码或修改功能。

| 内容 | 依据 | 结论边界 |
|---|---|---|
| 用户提供的照片有密码锁，并标示仅供顾客、向前台询问 | 本轮用户附件 | 只能证明该场景存在；不据此确认品牌、分店、密码或所有门店规则；不将原图纳入公开数据集 |
| 星巴克空间包括洗手间，供顾客和员工使用 | [星巴克官方规则](https://about.starbucks.com/code-of-conduct/) | 知道密码不等于具备使用条件；具体分店可用性仍须核实 |
| 地图服务能查询地点、类别和附近结果 | [Mapbox Search Box](https://docs.mapbox.com/api/search/search-box/) | 位置、品牌信息不能证明洗手间存在、开放或密码有效；搜索不是全部门店清单 |
| Search Box 默认仅供临时使用 | [Mapbox 使用限制](https://docs.mapbox.com/api/search/search-box/#search-box-api-restrictions-and-limits) | 永久保存需适用授权或独立允许持久化的来源；其他接口的永久设置不自动覆盖 Search Box |
| 已有洗手间工具展示收费、钥匙与无障碍信息 | [Flush 官方介绍](https://www.jrustonapps.com/apps/flush-toilet-finder) | 说明「地点＋使用条件」可作为设计参照，不代表 Abasong 的覆盖或留存已验证 |

待验证：司机需求出现频次、现有工具哪里不足、近期同行信息能否减少白跑、是否愿意更新信息、维护成本是否可承受。本次未找到足以确认美国麦当劳所有门店统一洗手间规则的官方依据，不做全品牌推断。

## 3. 轻量原型目标

入口：点击首页搜索，提供「找洗手间」快捷入口。进入独立附近结果页，沿用上方地图、下方纵向卡片与现行品牌/组件规范。退出后恢复原三模式、选中对象和阅读位置。

卡片按以下层级组织：

1. 地点名称＋近似距离。
2. 分店地址＋使用条件；地点名称与地址共同区分同品牌分店。
3. 最近确认时间；有适用且可共享的门禁码时显示具体洗手间范围和完整字符。
4. 主要操作「导航」，次要操作「更新信息」。信息没有确认时，不用品牌或地图标记暗示可用。

地图采用统一洗手间图标与店名，选卡与标记同步。首版不依赖各品牌 Logo，不更改公寓建筑高亮规则。

| 结果状态 | 推荐文案/行为 |
|---|---|
| 已确认无需密码 | 「无需密码」＋使用条件与最近确认时间 |
| 已确认需要询问 | 「请向前台询问」；顾客限制另行展示 |
| 可共享密码存在 | 展示适用洗手间、密码、贡献人/时间及使用条件 |
| 洗手间或条件未确认 | 「使用情况待确认」；不标「可用」 |
| 临时关闭或暂不提供 | 明确状态，不作为可用推荐；不把门店营业中等同洗手间开放 |
| 旧信息待复核 | 「信息待更新」；不能只靠历史累计有用票置顶 |
| 查询失败 | 「暂时无法加载」＋「重试」，不冒充空结果 |
| 成功查询但无已确认地点 | 说明当前范围内暂无已确认信息，可主动扩大范围；不保证该范围没有洗手间 |

使用条件（如顾客可用）与进入方式（无需密码/询问前台/密码）分别记录，不能做成互相排斥的一组选项。更新尽量点选，补充说明选填。不自动读取用户相册或收集配送路线。

## 4. 数据、距离与信息保护

- 地点、分店、具体洗手间是不同层级。码绑定明确分店及适用范围，不扩散到同品牌或同店其他洗手间，不写入公寓的门禁来源或三门别选项。
- 图标、卡片、反馈与字面值保护可复用；公寓资格/对象授权不能未经设计直接套用为洗手间权限。实施前明确读写人群、对象隔离与停显规则。
- 只共享获准传播且适用的码。店员当次告知不自动等于可公开传播；来源不清楚时记录询问前台等信息，不通过公开社交帖子批量导入密码。
- 保留前导零与 #/*，区分更新时间和最近成功使用时间。排序考虑近期成功与失败，过期阈值待试点后确定，不编造固定有效期。
- 门店要求停止显示时，可沿用受控停显思路：位置及使用条件保留，码停止展示；权限/数据变更需实际测试，不能仅靠客户端隐藏。
- 原型初始查找半径拟为 1–2 公里，数值待验证；结果不足时由司机主动扩围。不得直接继承公寓 200→500→1000 米策略。
- 初期按距离展示，未确认/关闭状态清楚区分；「可用性优先」推荐排序留作试点评估，不能用未标明的排序改变距离含义。
- 近似直线距离可本地计算，不写成驾车距离或到达时间。导航交给外部导航应用。
- Mapbox 可提供 ETA/沿路线查询，但需适用输入及额外用量评估；Abasong 没有承运商完整路线，首版不承诺顺路推荐。[官方参数](https://docs.mapbox.com/api/search/search-box/#get-suggested-results)
- 地图查询按用户主动使用触发，有请求范围和次数上限；不随每次 GPS 更新扫描全部连锁门店。持久化来源/许可需要可追溯，不能用手动确认掩盖供应商数据限制。

## 5. 分批验证与任务状态

| 编号 | 工作 | 出口 | 当前状态 |
|---|---|---|---|
| WC-01 | 候选需求与边界登记 | 主线不变，来源、使用条件及未知状态明确 | 文档完成 |
| WC-02 | West Covina 地点样本核对 | 10–20 个地点有来源、分店地址、条件、核实日期；未核实明确标记 | 待安排；已核实 0 |
| WC-03 | 轻量交互原型 | 查找→核对条件→导航→反馈；返回恢复原公寓；失败/未知/过期状态可体验 | 待安排；未制作 |
| WC-04 | 小范围实际使用验证 | 记录完成耗时、白跑原因、信息失效及复用情况 | 待安排；无参与者/现场结果 |
| WC-05 | 是否进入 P1 实现的裁决 | 形成采纳/缩小/暂缓结论，再拆 API、数据、原生和验收任务 | 待 WC-02–04 证据 |

不要求用户现在专程前往、招募人员或提供密码。先完成当前 M7；如需现场配合，沿正常配送安排窗口。现有的 5 司机/2 DSP 测试仍单独追踪，本候选不替代其结果。

样本记录建议字段：样本编号、地点名称/类别、公开分店地址、资料来源链接、可保存依据、是否有洗手间、使用条件、进入方式、开放信息来源、核实日期、是否现场核实、最后成功使用时间、问题分类。文档/CSV不记录真实密码、私人手机号、精确司机轨迹或收件人资料；码如进入实现阶段，再使用受控业务链路。

验证指标：

- 找到可用地点的时间：从开始查找到确认可使用；另外记录到达前查询耗时，避免混为导航时间。
- 成功使用率：实际使用成功次数 / 实际尝试次数，注明样本量；只点导航不算成功。
- 白跑情况：关闭、无洗手间、条件不符、密码失效、定位错误分别记录。
- 信息维护：两次核实之间的变化、司机更新意愿与实际更新行为。
- 重复使用与分享：分开记录意愿与实际行为，不由一个截图或一次成功推断增长。

不预设没有依据的留存收益、覆盖率或工期。若只有门店点位、无法可靠说明使用条件，保持查询线索级别；若可用性和更新无法维持，则缩小为已确认地点或暂缓密码部分。

## 6. 后续验收清单（尚未执行）

- 同品牌两个分店、同店不同洗手间不串码；切卡和迟到响应不回填前一对象。
- 未确认地点不标可用；店铺营业不自动代表洗手间开放。
- 无码且无需密码、需询问、暂不可用、未知、加载失败分别展示。
- GPS 漂移不抢走阅读；定位/导航目标明确；搜索页面返回保留公寓阅读位置。
- 更新失败保留本次输入；纠正只影响相应来源；停显后不能继续读取旧缓存正文。
- 距离、开放信息和更新时间有来源；无法计算或资料缺失时不编造。
- 密码符号与前导零完整；登录/对象权限和数据源存储限制另有实测证据。
- iOS/Android安全区、键盘、动态字体与点选目标遵循同一设计系统；原型通过不计原生通过。

本轮仅完成规划登记与文档检查，没有应用改动、地图调用、门店采集、云变更或新增计费资源。

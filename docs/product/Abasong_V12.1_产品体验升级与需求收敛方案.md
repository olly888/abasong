# Abasong V12.1 产品体验升级与需求收敛方案

本轮证据/范围裁决入口：[E01–E12](../research/Abasong_竞品与替代方案证据表_2026-11-05.md)、[G01–G14](V3.2_首版需求缺口与范围裁决.md)、[六步基线](../Abasong_V3.2_可开发与可验收基线.md)。原型五核心任务补验与真实7人观察分开；后者未开展，不能把文档收敛写成市场验证。

更新2026-11-05。状态：本轮产品与原型方案基线；未证明目标体验已经在App实现或经真人验证。依据：用户真实配送经历/已完成访谈、[当前产品基线](../../产品基线.md)、[DoorDash研究](../research/DoorDash_司机端深度研究与Abasong借鉴方案_2026-11-04.md)。本轮保留既有核心业务，用更准确的语义和更少的操作提升体验。

## 1. 产品经理结论

产品价值按顺序为：**快速核对地址并查码 → 便捷贡献、纠正 → 当次支援和联系 → 私人积累与同行交流。** 本轮不以页面数量、地图装饰或内容停留时长作为交付目标。

已完成的需求访谈不重复从头进行。下一轮观察司机/DSP能否独立完成任务，验证选择是否清楚、操作是否节省、没有资料时是否有合理下一步。首批资料覆盖和有效查码仍是内测价值出口，漂亮地图及工程测试均不能替代。

## 3. 五种地域与时间概念

| 概念 | 定义与作用 | 不产生的效果 |
|---|---|---|
| 服务区域 | 请求、司机声明及发现使用同一业务区域ID；有来源才显示几何 | 不等于承运商线路ID、司机位置或实际缺口 |
| 浏览筛选 | 本模式的区域/日期/类型/经验等临时查询条件 | 不修改本人偏好、声明或通知 |
| 常跑区域 | 未来私人持久偏好，减少重复选择 | 不自动开启声明、不改已发布意向、不代表已核验经验 |
| 当次声明 | 一次起止时间内愿意去的1–5区域、可选件数 | 不代表在线、已到场、已接单或平台预订 |
| 通知设置 | 是否及何时允许相关打扰；未来机会提醒有独立业务规则 | 不自动接单，不替代声明，不删除站内消息 |

## 4. 三条最小主流程

### 4.1 查码与补充

打开H01 → 真实定位附近200米候选 → 核对门牌 → 直接读码；不是目标则横滑或搜索。无码保留地址和前置添加入口；确认后共享并回到实际公寓。不能要求先确定G1/G2、进入建筑或停稳8秒才出附近卡片。

本轮新增[地图卡片与距离补充](Abasong_V3.2_地图卡片与距离体验补充.md)（UP12/UX10）：地址数字28px加粗、街道20px常规单行，完整城市/州/邮编在展开层；距离放顶部辅助行，取发现同源的近似边界/参考点距离，粗略位置弱化、过期隐藏。三模式地图共用独立滑卡外框和横向轨道，找活一需求一卡、找人一司机一卡，保留列表。

同一社区按明确地址及密码适用范围组织，不按屋顶重复出几十张卡。house默认不当公寓，分类缺失但已有业务公寓仍可发现。不用最近公寓的码填到未关联地址。

### 4.2 批量贡献

首页/我的同一个贡献菜单 → 选择一张或多张截图 → 集中核对地址、密码及共享意图 → 确认所选条目 → 结果。只要求修正不确定项，首尾符号和前导零不可丢；无法明确地址不自动猜绑。

本次网络失败保留输入，已成功项不重复提交；确认离开后新添加从空白选图开始。正常贡献不增加审核等待；查看/贡献资格与资料有效反馈分别表达。

### 4.3 当次支援

司机从H03/我的进入U03 → 声明一次时间和区域 → 返回来源。找活者从H02查看需求、报名并联系；DSP从H03看声明和最小档案、发起既有文字会话。双方私下约定接手和付款。

声明、报名、已联系、已找到分别使用现有含义；报名不自动扣减缺口，联系不等于合作确认或到场。不给“预约成功”“线路已保留”等承诺。

### 4.4 仓库取件与派送分开

用户最新DashLink样本补充纳入[仓库取件地址与导航](Abasong_V12.1_仓库取件地址与导航补充.md)。P03仓库取件填写完整地址、名称选填，明确取件时段/理货与接手条件；D01在报名之前可看仓库地图、复制和跳外部导航。H02摘要分“取件地区/派送地区”，地图仍以配送区域为发现视角，不把仓库当派送线路。途中交接沿用既有文字确认。

当前只有取件区域，没有完整地址链路。此为原型目标，不是已接通服务；不增加仓库目录、候补、认证评分、扫码/POD或保证收入。导航不等于报名或到场。

## 5. 首页三模式与上下文裁决

| 行为 | 公寓 | 找活/找人 |
|---|---|---|
| 查询范围 | 200米地面距离；缩放不改变半径 | 全部区域默认、用户筛选；不套200米 |
| 地图对象 | 建筑/门牌/当前公寓 | 公开服务区域点，或有来源的对照区域面 |
| 点区域 | 不适用 | 将区域作为浏览筛选；原对象仍属于该区则保留，否则清除旧对象，新结果后选首项 |
| 横滑 | 切公寓与建筑/门牌同步，仅当前卡读码 | 切需求/司机与配送区/声明服务区同步，不更改区域筛选，不自动报名或联系 |
| 点卡/对象 | 选同一公寓，保持阅读 | 选同一需求/司机，进入既有详情；不改变声明或定位 |
| 列表/地图 | 公寓横滑按既有规则 | 共用相同筛选、选中ID和排序；返回保留滚动及相机上下文 |
| 定位按钮 | 解除阅读锁，恢复附近推荐 | 只让镜头回本人位置，不清除区域筛选，不更改声明/通知 |
| 模式切换 | 返回按本模式状态恢复 | 结果、错误、数量和选择隔离；不显示另一模式迟到结果 |

“当前结果”只表示本次已加载列表。区域点上的数值也须有同样口径，不能把最多100项加载上限叫全区域总量。若跨区汇总司机，按用户去重；同司机愿去多区不等于多个司机。单条需求数、需要人数和包裹件数不能混用。

## 6. 时间与表单

- 浏览保留不限日期/今天/明天；本轮不增加“现在”或任意工作窗口。
- 目标找活日期指需求的**接手日期**（starts_at的洛杉矶本地日期）；有效截止expires_at不是配送工作结束。当前实现使用起始/截止重叠，需后续真实服务修正后才能认为原型日期语义已落地。
- 找人按本人声明起止区间与所选日期相交，同时排除现在已经关闭/到期的声明。未来声明明确日期，不叫“在线”。
- U03维持单时段、开始7天内、最长24小时、1–5有效区域、可选件数；保留系统日期和时间选择器，补今天/明天快捷选项。
- 结束不晚于开始时明确显示次日日期；关闭提交开关与版本，不被旧时间阻止。失败保留输入，版本冲突重读前保持草稿。
- 无有效旧时段时先为关闭草稿，可提供可修改的参考时间；不能根据上次设置或偏好自动开启、续期。

## 7. 原型中的机会提醒边界

现有消息/通知设置可以继续展示。未来相关机会提醒适合解决司机在其他App工作时漏消息的问题，但依赖主动偏好、事件去重、时间/区域规则和真实推送送达。

首轮不增加未接通的开启按钮，不模拟“已发送给8位司机”“已读”或短信兜底。最多在原型评审外壳给出后续流程说明；产品界面不出现未来功能介绍。对外启用前完成真实凭据、账号隔离、拒绝/关闭/到期及投递回执验证。

## 8. 可验收目标（UX01–UX10）

| ID | 待验证条件 |
|---|---|
| UX01 | 门外场景直接出附近独立卡；地址、完整密码、贡献时间和用户名清楚，不出现入口或8秒阻挡 |
| UX02 | 横滑、慢响应、GPS刷新、详情回程不串地址/密码，不抢主动阅读 |
| UX03 | 两处贡献菜单一致；OCR不确定项未确认不共享，部分成功重试不重复，退出重入不续填 |
| UX04 | 选区→列表→详情→返回、切模式与定位的效果符合第5节；筛选不越界修改其他设置 |
| UX05 | 数量与加载范围相符，失败不显示0；未来、到期和当前有效声明可区分 |
| UX06 | 今天/明天及跨日能独立理解，关闭/到期不继续推荐；接手日期不混用发布截止 |
| UX07 | 每层一个主动作，错误/空/定位/底图状态分开，失败保留本次可恢复输入 |
| UX08 | 小屏、软键盘、200%字号、系统返回及读屏有等效操作；未测项明确记录 |
| UX09 | 取件仓库/派送区分清；发布明确地址，详情看图/复制/导航/返回一致，途中交接及旧需求不生成假仓库点 |
| UX10 | 三模式独立等高横滑卡；公寓地址分级、距离不挤地址且精度/时效准确；切卡不改筛选，地图/列表/详情回程仍是同一对象，一司机多服务区不重复 |

建议观察5名司机（熟手和偶尔支援者）及2名DSP完成上述主任务；记录独立完成/需要提示/失败、步骤、时间和误解。建议原型出口为每类任务至少4/5司机独立完成、两名DSP能解释区域/声明含义，且无错地址共享或误认为已接单；这是小样本设计目标，不证明市场转化、留存或规模。参与者未准备时记录待测，不能代填通过。

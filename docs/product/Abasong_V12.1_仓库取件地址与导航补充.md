# Abasong V12.1 仓库取件地址与导航补充

2026-11-04。依据：用户本轮提供的5张DashLink截图、真实仓库取件经历和现有P03/D01实现。状态：**已接入R2a原型，待用户体验确认；未修改App、契约或数据库**。承接[产品收敛](Abasong_V12.1_产品体验升级与需求收敛方案.md)和[原型升级计划](Abasong_V12.1_原型升级制作与验收方案.md)。

## 1. 判断：值得吸收的核心

司机判断一条支援需求，先要知道“去哪里取、几点能取、取多少、去哪里送、多少钱”。取件仓库和配送线路是两处不同的地点，不能只给一个配送区域代替仓库地址。

本次不是恢复独立集合点分享：**仓库是发布者主动写入需求的固定取件地点；临时交接仍在现有文字会话约定。** 不增加集合点聊天卡、位置共享/追踪、扫码理货或POD功能。

官方FAQ也描述一次取件对应多次派送，以及到取件点后核对、装车的流程；这支持借鉴取件信息层级，不意味着Abasong应承担承运商扫描、派单或履约。[DoorDash官方FAQ](https://help.doordash.com/en-us/dashers/article/waitlist-faq-for-runners)

## 3. P03发布：少量必需字段

配送类需求（部分包裹、整线、临时增人）目标增加一个取件方式：**仓库取件（默认）/途中交接**。不要求用户先切DSP角色，不改为两套客户端。

仓库取件表单：

1. 配送区域、既有承运商/线路。
2. 取件仓库：名称选填；**完整地址必填**，含门牌/街道、城市、州，邮编可获得时带入。输入地址联想，点候选后可看位置并核对。取件区域从已确认资料建议、由发布者核对，不拿区域中心当仓库坐标。
3. 当次日期/可开始取件时间、最迟取件时间（有明确截止时填写）；继续使用既有时间字段含义，不用发帖截止或配送截止替代取件窗口。
4. 现有数量、人数、报价单位、已理货/未理货和接手条件；额外入口/装货说明放既有选填说明，不增加必填流程或身份证上传。

发布预览明确“取件仓库/地址将向登录司机展示”。不增加仓库认证、强制联系人或新的授权勾选步骤；发布者确认可对司机展示的商业取件地址。个人住址、临时私密碰面点不用仓库字段公开。

选途中交接时保留大致取件区域和“具体地点联系确认”，详情不提供虚假的仓库点。车辆/其他求助不强制仓库。旧需求未填完整地址时保持可查看，显示实际缺失状态，不能用旧pickup_area补猜街道。修改为仓库取件后按新字段规则核对；草稿/复制沿用既有能力，不新增仓库管理平台。

供应商联想失败不清空输入；允许手工填写并确认完整地址。有效地址但未成功定位可保留地址，地图待定位；不能因厂区不在POI库就逼用户选附近别处。不同城市同街名、多个近似结果、坐标和地址冲突时必须核对，不静默选择第一项。

## 4. H02与D01：摘要和完整信息分层

H02地图仍以配送区域发现需求，区域点统计语义不变，不把仓库点/司机蓝点当配送线路位置。列表/摘要显示“取件地区 · 派送地区”、日期、报价单位及数量，不在每张卡里加载缩略地图或塞长地址。

D01顶部保留真实状态、报价/数量和配送区域；紧接清楚的取件区块：

- 取件时段（明确日期；跨日写日期）。
- 仓库名（有才显示）＋完整地址行及位置图标。
- 次级“复制地址”和“导航”；点地址或位置图标打开App内取件地图。
- 派送区域单独列出，理货/接手条件保持已有信息；报名仍是需求详情层主动作。

仓库名称不是唯一识别项；完整门牌/街道/城市/州不能只剩“Los Angeles”或承运商品牌。**公寓收起卡单行规则不套到取件详情**，完整地址可换行，不裁掉关键门牌或异地城市。报价称DSP报价并带每件/整线/议价，不变成平台保证收入；不生成缺乏依据的预计工时/时薪。

距离第一轮可不显示；若展示本机计算，只写“距取件点约N mi（直线）”，不用“车程/驾车N分钟”。没有定位权限照常看地址、复制和导航，不为此强制索要GPS。道路里程/ETA需要另经真实路线服务与成本评估，不是本补充前提。

## 5. 取件地图、复制和外部导航

复用现有Mapbox组件，在D01内打开独立面板/覆盖层，页面ID仍D01，不增第四导航或新仓库模块。默认仓库为中心、约16级供核对，允许缩放及已有比例尺/归属；有本人位置可显示蓝点，不要求镜头强行同时包含远处蓝点。这个点只表示取件地点，不证明具体装货门或承运商认证。

地图层完整地址＋一个主按钮“导航”，复制为次操作。关闭地图后回原需求/滚动；从外部导航回App不产生报名、已联系、到场或已找到状态，也不发送消息。

复制仅在用户点击后写完整地址到剪贴板，成功才提示“地址已复制”。不自动读取剪贴板或复制密码/联系人。导航点击后选择地图：iOS提供Apple Maps/Google Maps，Android优先Google Maps；只传目标地址或已确认目标点，不传本人的精确GPS、账号或API token。导航应用自行确定起点。取消仍留原页。

地图显示失败保留地址和复制；无坐标时给“暂时无法显示位置”，可重新定位地址，不画区域中心假点。完整地址仍可交外部地图解析。外部地图不可打开时保留页面，提供复制/浏览器地图；没有完整地址时只能联系确认，不导航到配送区域中心。地址/需求版本变化后重新读当前地址，防止旧图导航去旧仓库。

技术优先外部地图链接，不为首版引入Mapbox Navigation SDK或自建路线。Google Maps官方支持通用地图链接且无需Google API key；原生外链应处理取消及无法打开，不能把“打开成功”当实际抵达。[Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)、[React Native Linking](https://reactnative.dev/docs/linking)

## 6. 契约与数据增量边界（目标，非已发布）

当前只有pickup_region_id/派送region_id等，pickup_area为服务端区域标签；没有结构化仓库地址/导航字段。不能把全文塞进地区字段或私聊来源卡绕过契约。

拟在需求及条件版本增加小型pickup_location值对象：kind（warehouse/contact_handoff）、可选label、确认的address_text/结构化地址、可空point、位置依据/来源。地址和点绑定同一需求版本；只需需求内存储，不建全城Warehouse表。发布、编辑、预览、复制需求、详情及版本变更同步契约/生成类型/事务测试。

登录且有权查看该需求者可在报名之前核对发布者提供的仓库地址；屏蔽/权限规则仍生效。普通仓库地址不复用公寓共享密码的查看资格，不能因无查码资格而隐藏该需求的取件地址。游客公开摘要、分享H5和锁屏默认只给现有大致取件地区，不新增精确地址/坐标；详情DTO独立，不扩大普通敏感字段访问或复活已退役集合点接口。

用户直接填写并确认的地址与供应商地理结果分别标来源；永久存供应商点位沿用已核对的许可/永久编码配置，不把临时联想结果原样存库。位置不明确时point为空。外链由客户端固定供应商模板及编码构造，不能直接执行发布者提交的任意URL；地图ID不能跨供应商冒用。

## 7. 原型与R4验收增量

H02/P03/D01/预览及地图覆盖层已接入[R2a原型](../../design/abasong-independent-v1/v12.1-experience/index.html)，可核对地址、复制及导航选择，未更新App。V3.1仍现行；皇家蓝/黑白灰和现有Button/Sheet/状态组件保持。文案ID C60–C73见[文案表](../design/Abasong_界面文案与状态规范_V1.md)。

新增UX09：司机能区分取件仓库与派送区域，详情→看地图→复制/导航→返回不丢上下文；DSP能发布可明确找到的仓库地址，途中交接不被迫公开私人地点。

必须覆盖：同城市两仓库/同承运商多地址、取件与配送不同城市、手输未定位地址、联想失败/歧义、底图失败、无GPS权限、导航App缺失/取消/返回、地址改版、旧需求缺地址、公开摘要隔离，以及长地址/200%字体/读屏等效。模拟器打开链接不等于真机导航通过，不能自动记到场。

先做少量必要体验，不纳入候补队列、每日抢位、优先评分、仓库席位、预估收益、承运商扫码/POD、身份证采集或新的司机推送订阅。

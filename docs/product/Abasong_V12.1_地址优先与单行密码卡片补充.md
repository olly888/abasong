# ADD-17 地址优先与单行密码卡片

2026-11-01。依据用户配送经验：到达后首先核对面单与建筑门牌，不依赖公寓名称；地址尽量同行，密码和贡献人清楚可读。覆盖此前名称优先的排版要求，沿用ADD-15直接阅读。

## 信息与排版

| 场景 | 首要信息 | 次级信息 |
|---|---|---|
| 首页收起卡 | 一行“门牌号 + 街道”，门牌28、街道20；密码40 | “今天 8:20 AM 贡献 · 阿杰”；查看记录入口 |
| 首页展开卡 | 完整街道，窄屏/长地址可换行；密码29 | 城市/州/邮编、公寓名称、每条贡献时间与用户名、门别及已有反馈 |
| 候选/地址联想 | 一行门牌+街道，门牌21、街道17 | 城市/州/邮编与公寓名称，支持区分同街同号不同城市 |
| 我的公寓列表 | 地址先于名称，密码仍在卡片直显 | 区域、私存/共享等已有状态；权限不变 |
| 贡献/公寓详情/拍面单核对 | 完整目标地址优先，门牌突出 | 公寓名称和地域用于核对；编辑仍保留完整输入 |

字体为默认逻辑字号，保留系统字号缩放。门牌与街道属于同一文本行，不把门牌独立成一行；标题、密码分开，密码旁显示小字“门禁密码”，避免把两组数字混淆。收起卡不显示公寓名称/城市第二行；展开才补全。没有密码/没有资格等状态仍优先显示同一地址标题，不增添解释备注。

## 三项落实决定

1. **长地址**：收起卡与结果列表尾部省略，优先保留开头门牌与街道；不缩小字号硬塞。首页点地址、手柄或记录入口展开，完整地址可读；读屏名称始终包含完整地址。列表点选后在详情核对，不能凭被省略的文字改变匹配结果。长用户名收起可尾部省略，展开后完整显示。
2. **门牌原样保留**：包括字母、方向、分数及连字符，如123A、123 1/2、12-34、A17。不能只取第一个数字、丢弃E/N方向或将Apt28当作建筑门牌。展示层不能确定拆分时整条地址原样显示，不猜数字。展示拆分不参与公寓匹配、地址归一或地图门牌来源。
3. **地图与卡片一致**：使用已明确关联的建筑门牌；社区主地址不复制到社区每栋建筑。地图关联仍按ADD-13来源/几何规则；这次只改阅读层级，不能因地址看起来匹配而扩大自动识别范围。选定公寓、密码和地图高亮仍使用同一实体。

## 密码与贡献人

- 常见密码为4–6位数字，前/后可能有`#`或`*`。展示原值，不转数字、不去前导零、不重新分组、不替换或省略符号。符号与数字同字号同权重，使用数字对齐字体特性。
- 这是常见格式描述，不新增4–6位硬校验，也不拒绝已支持的其他有效进入资料。32字符值仍完整换行；无固定码等进入方式继续按原规则展示。
- 元信息统一为“今天 8:20 AM 贡献 · 用户名”；非当天明确月/日，跨年加年。按资料当地时区判断“今天”，首批洛杉矶范围使用America/Los_Angeles，不按设备任意时区改变事实。
- 用户名使用服务端`contributor_display_name`，空缺仅回退“司机”；不使用手机号、微信或真实姓名推断。无效时间显示“时间未知”，不编造时间。查看与反馈统计不代替贡献人。
- 排序保持有用优先、同组贡献时间倒序；展开中的反馈与锚点保留。无审核、放大页或新操作按钮。

## 开发与验收

同步扩展原型和原生H01/S01/L01/B02/U06/U09；39节点/292状态不新增路由。契约已有完整地址及贡献显示名，无新增接口、迁移或权限。本次不变更地图API、定位阈值、真实账号能力或正常自动认定开关。

验收重点：单行门牌+街道、展开完整地址、公寓名降级；4/5/6位及首尾符号/前导零不丢失；长地址/长用户名/32字符码可读；当天、跨日和未知贡献信息正确。原型、双模拟器TEST视觉与iPhone现场分别记录，默认字号通过不能推广成200%字号/完整读屏验收。执行结果见[本批记录](../technical/D1_地址优先卡片与贡献人展示验收.md)。

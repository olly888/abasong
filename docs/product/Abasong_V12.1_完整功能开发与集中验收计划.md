# Abasong V12.1 完整功能开发与集中验收计划

2026-11-03，最新用户决定。本文调整执行顺序，不改变PRD、三导航、产品边界及发布质量要求。

## 当前目标

先把已批准的完整业务功能开发出来，继续通过本地自动化、真实隔离数据库和现有开发预览验证。双真实账号短信、云业务KMS、现场和独立iPhone内测包暂缓，合并到后续集中验收；不再反复要求本人收短信或操作设备，也不把这些依赖当成其他功能研发的阻塞。

这不代表D1/A4/A5已经通过，不关闭真实账号、云加密、真机、分发和外部试点门槛。现有云环境保留，本次没有新云资源、费用或权限变更。临时双账号本机登录服务已停止，不继续发送测试短信。

## 功能开发批次

| 批次 | 可用结果 | 主要实现和自动检查 |
|---|---|---|
| B1 · 需求发布与管理 | 首页发需求→选择类型→填写→保存草稿/预览→确认发布→我的发布/详情→本人标记已找到或关闭 | 五类临时求助；配送/取件分区；具体时间、件数/人数、最低量、整线、报价和接手条件；版本、幂等、草稿隔离、到期与屏蔽 |
| B2 · 报名与协作状态 | 司机报名→发布者看报名→标记已联系→本人撤销报名→发布者修改缺口 | 容量/最低量/到达时间/所见版本；自己不能报名自己；并发报名、同事务创建来源会话；报名不自动扣减缺口；补发布后编辑、版本通知、重开与复制 |
| B3 · 联系消息 | 统一消息入口→来源会话→文字/需求卡→已读及失败重试 | 本人参与、双向屏蔽、防重、分页；精确集合点仅发布者明确分享给指定会话；通知和推送按设置处理，不伪造送达 |
| B4 · 可用司机与地图找活/找人 | 主动声明时段/区域/容量→区域内需求和可用司机→地图与列表切换→联系 | 可用不等于在线，不公开实时精确轨迹；区域位置、到期、经验自报与核验分开；保持首页公寓查码优先 |
| B5 · 首版补齐 | 最小司机圈、常联系、我的发布/报名、设置、举报/屏蔽/删除、主动分享公开摘要 | 引用同一需求状态；公开摘要字段独立于完整业务DTO；不增加长期招募、生活市场、支付或自动派单 |
| B6 · 集中联调与内测交付 | 公寓价值闭环＋临时支援＋消息＋我的串联，集中处理真实账号与真机出口 | 恢复双真实账号/真实KMS，授权OCR质量，弱网与越权回归，iOS/Android验收；用户准备好后再构建独立iPhone包与现场测试 |

B1先交付正常发布/关闭；发布后改价、重开、缺口和报名联动放B2，不能在界面上伪装已完成。B2/B3按来源会话依赖衔接，底层事务可以先实现，再接消息完整页面。

## 每批固定做法

1. 对照最新页面规格及原型确认现有行为，不新增DSP工作台，不改首页/司机圈/我的。
2. 使用已有OpenAPI、领域状态和权限边界；必要增量同时更新生成源、类型和迁移，保留历史数据。
3. 开发真实API和原生页面，运行与改动直接相关的自动检查及一次性数据库测试；不提供只靠前端布尔值的业务权限。
4. 更新总计划状态表、工程状态与可审查PR，明确“源码接入、自动检查、原生观察、真实账号、真机”的不同证据。
5. 没有改动且已经通过的手势不反复要求本人补测。需要本人时集中列最少步骤，不把每个开发批次都拆成短信验收。

平台只做临时配送支援及灵活协作。报价与付款文字是双方的私下约定；发布、报名、已联系、已找到和关闭均不等于自动派单、实际到场、配送完成或费用结清。

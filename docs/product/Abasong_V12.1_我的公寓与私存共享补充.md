# V12.1 我的公寓、私人保存与主动共享

更新：2026-10-30。用户已同意将重复入口整合为“我的公寓”，并将收藏、私人保存、主动共享、贡献效果与纠正纳入首版。此补充优先于旧版“收藏公寓后置”和截图导入只提交共享的规则；其他综合收藏仍后置。合成原型可操作，原生/API/数据库未因此实现。

## 1. 信息架构

“我的”仅保留一个“我的公寓”入口，移除同级“贡献公寓资料/我的密码贡献”的重复菜单。添加资料是U06内操作，不再占独立同级入口。

| 页面 | 信息与动作 |
|---|---|
| U06 我的公寓 | 我保存的/我共享的两个栏目；区域筛选；截图添加/手动添加；本人导入记录及继续处理 |
| U09 公寓详情与我的记录 | 公寓地址与自定区域；我的私人密码/备注；当前共享资料；地图入口；修改/删除私存和主动共享 |
| B04/B05/B06 | 截图整理复用；B05默认仅自己保存，可主动选择同时共享；B06区分私存、共享、同码、待审核及失败 |
| H01 | 收藏公寓入口，保存自有公寓ID引用，原卡结构和三导航不变 |

U09重新启用但仅用于公寓工具，不恢复旧综合收藏、帖子/商品收藏或完整路线规划。U06可按司机自定区域整理和筛选；不在“司机圈”混入私人资料，也不新增DSP工作台。

## 2. 保存与共享

- 私人保存：用户主动提供的地址、密码、门别、备注，仅本人可读写；账号正常时不以共享资料查看资格作为本人私存的读取条件。限制账号/删除状态仍按服务端规则处理。
- 收藏公寓：保存公寓ID和私人区域标签，访问时读取最新有权查看的共享记录，不自动复制共享密码到私人库。不提供整库复制或通过快照绕过撤回/资格变化。
- 主动共享：用户确认具体资料与分享范围后，经当前资格、来源、目标公寓、审核和去重规则复制必要字段到共享贡献链路。私人备注、区域标签、原图和整个私人资料库不随共享提交。
- 默认保存范围为“仅自己保存”。截图识别与公寓匹配不能替代共享确认；存在私存不等于已有贡献，也不产生有用反馈。
- 用户可先私存，以后逐条主动共享；导入也可集中选择“同时共享给有资格的司机”。首版不在同一批内再提供复杂的多套逐行分享策略，想单独共享的项可保存后从U09选择。
- 修改私存独立生效，已共享记录不随私人编辑自动覆盖。取消收藏/删除本人私存，不删除其他司机的共享资料；移除整个本人公寓记录需明确确认其私人数据范围。
- 未收录公寓可以先私存，不强制等待共享库审核；主动共享时才创建/关联公寓提议，待审核不冒充已收录或已可用。不得把当前GPS/临时地图候选误作为永久精确地址。

## 3. 导入、草稿与失败语义

B05底部：明确保存范围→核对资料→保存N条/保存并共享N条。默认未勾共享。共享资格不足时仍可私存，不能以私存身份跳过共享权限。

批次首次提交后固定本批提交范围；失败重试复用同一意图，不能把先前私存失败请求静默改成共享。未提交候选变更后重新确认。部分成功逐项保留，不重写成功数据。

私存成功、共享成功、同码共享、共享待审核是独立结果。保存与共享组合中发生共享失败，应明确“已私存、共享失败”，而不是要求重新导入。后端实现需分别持有幂等结果，避免重试生成重复私存/重复贡献。现有原型仅演示主要状态，完整双阶段失败事务待技术实现。

私人资料、草稿与共享记录应分别建模；不能只翻转一条记录的public字段。导入草稿有期限，正式私人记录不是草稿到期时被连带清理的对象；原图仍按短期规则删除。

## 4. 贡献效果

“我共享的”按贡献记录展示公寓、状态、贡献时间、被其他司机查看的次数、有用/不能用反馈数量和最近反馈时间。待审核/已撤回仍可查看本人元数据；共享正文继续校验当前资格。首版不展示查看者身份、精确位置或个体行为轨迹。

被查看不等于成功进入。后端统计口径需排除本人、重试、预取、机器人/滥用及同一用户的重复读取；去重窗口在T23冻结，不能以所有地图请求数当“帮助人数”。反馈计数来自当前有效用户反馈，不能因同码贡献、导入或纠正自动增加。聚合展示不是对司机的能力排行榜。

本地原型的反馈数字是标明的合成示例，未接真实事件统计。上线前需明确查看事件触发点、去重与留存，测清口径后再展示真实数字，不编造增长。

## 5. 纠正共享密码

动作“纠正密码”：输入正确密码→确认来源和范围→提交纠正。新增正确记录或复用已存在的同码同范围记录，并关联被纠正的本人贡献事件。

- 不覆写旧密码正文、首次贡献时间或他人的反馈；新记录从自己的贡献时间/反馈开始，不继承旧记录的有用票或查看次数。
- 旧记录只有本人来源时，按现有撤回/纠错规则停止其展示并保留审计历史。
- 若旧共享记录合并了其他贡献者或有效反馈，停止/标记本人的贡献，发起原记录复核；不能以“我的修改”抹去其他人的来源、记录或反馈。
- 正确密码已存在时，追加同码贡献/确认事件，不刷新该共享记录最初贡献时间。
- 私人编辑、共享纠正、撤回本人贡献、举报错误关联为不同动作；修改某个私人密码不会自动撤回或替换共享记录。

## 6. 技术任务和权限扩展

本轮不修改已应用0001，也不假装现有OpenAPI已覆盖以下内容。

- T32（P0）私人公寓/收藏/区域与私存记录：owner隔离、增量迁移、正常账号本人访问、共享资格独立；私存正文加密，AAD绑定owner与对象/版本，不写普通本地持久缓存。
- T33（P0）主动共享与纠正：最小共享DTO、当前资格、来源与目标对象、同码事务、双阶段幂等、旧贡献终止/复核与新事件关联。
- T34（P0）贡献反馈摘要和查看统计：独立聚合接口，只返回本人记录的必要计数；去重、限流、事件保留及真实口径测试。
- T35（P0）原生U06/U09与截图联动：空态、未收录私存、区域、资格变化、删除、草稿/正式记录区分、私存与共享独立失败及双账号测试。

建议新增私人公寓/收藏、私人记录与区域标签实体；共享引用仅指向公寓/贡献事件，不让公共DTO引用私人正文。API职责包括本人收藏和私存CRUD、区域维护、主动分享、纠正本人贡献、贡献摘要；具体路径/operationId与T27一起扩展源契约和生成器，生成类型后才编码。

纠正和导入仍复用共享排名/权限；private owner授权不代表access.read授予。账号切换/退出清理内存敏感资料；客户端按钮状态不构成数据隔离。原图/私存/共享的删除、撤回与留存规则分别验证。

## 7. 验收

1. “我的”只有一个我的公寓入口；私人、收藏和共享来源可辨，区域整理有效。
2. 默认截图保存后共享列表/地图不新增密码；主动共享才新增正式贡献，私人备注不随之传播。
3. 修改/删除私人记录不改共享库；收藏打开最新有权记录，撤回/资格变化不被旧快照绕过。
4. 未收录地址可先私存；共享走提议审核。未持共享资格仍能读写本人的正常私存。
5. 纠正后新旧记录的正文、时间、统计不混淆，涉及其他司机来源时保留并复核。
6. 两个真实账号无法猜ID读取/更新对方私存，重试不重复，退出/删除清理按对象区分。
7. 真实统计与合成数据隔离，不将被查看数宣称为成功进入人数。

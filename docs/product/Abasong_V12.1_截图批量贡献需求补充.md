# Abasong V12.1 截图批量贡献需求补充

更新：2026-10-30。产品依据：用户明确要求将快递APP中的公寓地址/密码截图识别纳入首版设计和开发。状态：P0需求与设计任务已纳入；端侧原生选图/识别确认已接入既有保存接口，双端部分场景有实际证据；服务端批次/数据库增量迁移、恢复和完整验收仍未完成。与[PRD V12](../../Abasong_PRD_V12_首版产品需求.md)、[V12.1补充](../Abasong_V12.1_需求补充与原型决策.md)共同组成基线。

## 1. 产品价值与首版范围

司机在查不到当前公寓密码时才打开Abasong；平台价值取决于目标公寓是否已有能用的资料。不能要求熟悉线路的司机把已有知识逐条重新录入。首版必须支持从系统照片选择器选择一张或多张截图，识别其中的公寓地址与密码，匹配公寓并集中确认贡献。单图解决当下贡献，多图导入用于补齐整个线路区域。

截图导入为P0，与公寓查询、单条贡献、反馈一起构成D1公寓闭环。不是承运商APP集成，不读取其他APP账户、后台画面或完整配送任务；仅处理用户主动选择、有权共享的截图。手动贡献保留为识别失败/无截图时的替代。整段文本粘贴与表格导入为P1复用渠道，不阻塞首版截图链路；文档/PDF、全相册扫描、自动抓取、后台截屏、批量公开导出不纳入首版。

## 2. 入口与页面

保持一端、首页/司机圈/我的三导航，无新增首页常驻按钮条。

- U01“我的”：直接入口“贡献公寓资料”→B04；U06“我的贡献”：提供同一导入入口和本人批次记录。
- H01公寓卡展开层、B02单条贡献面板：二级动作“从截图添加”→B04。收起地图卡仍优先地址与可展示密码，不展示批量工具。
- 从某公寓进入仅传来源和返回意图，不能将该公寓强制套给所有图片，也不能用当前GPS替代截图中的地址。

| 节点 | 目的 | 最小元素与主动作 |
|---|---|---|
| B04 截图导入 | 选图并启动处理 | 返回、已选缩略图/移除/追加、数量、处理失败原因；主动作“识别截图” |
| B05 识别结果确认 | 批量核对、只修异常 | 可提交/待处理分组，每条地址、密码、匹配状态、必要图块；主动作“确认提交N条” |
| B06 导入进度与结果 | 知道何时可用并稍后继续 | 已贡献/同码记录/待审核/待处理/失败的数量，逐条状态、重试、继续确认；主动作随状态变化 |

B05复用一个行内编辑/候选公寓面板，不为每张截图建立完整新页面。每次只保留当前主动作；状态进度必要，解释OCR技术或宣传算法的备注不进入产品界面。U06的批次默认只显示元数据，密码正文仍需权限。

## 3. 主流程

1. 已登录且具有对应导入资格的司机主动选图。未登录保留非敏感入口意图，登录后重新选图；不把原图或明文写入通用导航参数。
2. 系统照片选择器只授权用户选择的照片；展示所选图，可移除误选项，不要求整个相册权限。取消不产生空贡献。
3. 按图上传并异步提取；每张可独立重试。切到其他页面可继续服务端任务，回来从本人批次恢复，不要求司机一直等在屏幕前。
4. 按截图内局部语义/版面关联地址和密码，生成候选记录，再匹配平台公寓。单图多条记录允许拆分，多图同一记录允许识别为重复。
5. B05先呈现能够核对的记录；明确匹配、字段完整的行默认进入可提交组，用户可取消选择。集中浏览后进行一次来源与归属确认，再提交所选行，不强制逐条输入或逐条打勾。
6. 不确定记录进入待处理组，不能默认选入。司机可改错字、选择正确公寓、补缺失地址/密码、删除误识别，处理后再加入提交组。
7. 仅提交已确认行；提交复用既有贡献/提议、资格、去重与审核规则。不能将OCR草稿直接变成共享密码。
8. 部分记录成功不受其他失败影响。已成功项不重复提交；余下保存为本人受保护草稿，之后从U06继续。不强迫司机为三条异常重新上传整批。
9. 结果区分“上传完成”“识别完成”“贡献已提交”“审核后可展示”。只有符合现有发布规则的记录才进入其他司机查询结果。

## 4. 识别与匹配规则

- 密码始终按字符串处理，保留前导零、大小写、#、*、顺序及有意义分隔。0/O、1/I、5/S、缺失符号等歧义必须高亮待确认，不能自动改成看似合理的数值。
- 不把订单号、邮编、单元号、电话号码、配送停靠号、Wi-Fi密码或住户私人门锁信息当成公寓共享通行密码。截图无密码就是无密码，不凭模型补全。
- 地址需保留原文用于本人核对，并形成规范化匹配字段。楼号/街道/城市/州/ZIP不完整或冲突时不自动判唯一；公寓名称相同不等于同栋，门禁密码相同也不能反推同栋。
- 多地址/多密码只按明确局部对应关系建立候选，绝不交叉组合。多个入口/适用范围不明确时交由司机确认；不强制录入停车/楼宇长资料。
- 当前定位可以辅助候选排序，不能替代缺失地址；允许一批图片来自不同城市、线路和历史配送地点。不要把当前公寓ID套到整批。
- 无匹配公寓先由司机确认地址并提交公寓提议，状态待核验；不直接把未经许可的地图供应商临时候选写入永久公寓库。地址持久化许可另行按现有地图策略验证。
- 贡献相同公寓+适用范围+密码时复用已有记录、追加贡献/来源事件，保留原contributed_at；不同门别/时段不因数字相同合并。
- OCR识别或人工确认不代表实测“有用”，不能产生有用票、成功进入时间或官方认证。仍按有效有用组优先、同组贡献时间倒序、稳定ID规则展示。
- 上传时间与资料原日期、司机声明的最近使用时间分开。历史截图不能显示“今天验证有效”；资料日期未知就不编造。缺失日期不阻止整理草稿，展示与审核遵循现有规则。

## 5. 编辑、权限与资料生命周期

普通B02手动输入仍只在编辑会话内存保留。新增导入批次允许服务端加密草稿以支持稍后继续，这是对既有草稿规则的明确扩展；不得转存明文到AsyncStorage、通用草稿、日志或推送。

- 创建、查看、编辑、取消、重试和提交批次均校验当前账号与对象归属。本人批次ID不是授权；资格撤销、封禁、切账号后重新判定，提交时不能沿用识别时资格。
- 原图、OCR全文及候选密码属于受控处理资料；只保留提取必需信息。公开地图、司机圈、公开分享、推送不包含原图、原始面单、姓名电话或密码正文。
- 司机选图时可移除/裁剪误含资料，不要求每张先手动打码才可识别。处理服务只输出需要的地址/通行候选，截图原件不进入公共共享库；不得用真实截图做模型训练。
- 优先评估端侧OCR与字段筛选，再决定是否需要服务端识别补充；尚未锁定OCR供应商。若将原图交给外部服务，必须先确定数据用途/区域/留存/日志与删除行为，不能假设外部不留存已成立。
- 原图仅短期私有存储、短效上传权限、处理后删除；失败/取消/超时也有回收任务。加密候选草稿有有限保留期和到期删除。具体数值与外部服务配置在受控试点前冻结，不能以“稍后继续”为无限留存理由。
- 批次删除只清理本人未提交源资料/候选；已进入共享记录的撤回遵循既有贡献归属规则，不能连带删除其他司机的记录或反馈。

## 6. 异常状态和恢复

必须覆盖：照片权限拒绝/有限照片授权、无图/损坏图/不支持格式、低清/裁掉地址、多地址对应不明、无密码/符号歧义、同名异栋、跨区截图、公寓未收录、全重复、批次内重复、部分上传失败、OCR超时/服务失败、取消与处理结果回写竞态、切后台/进程结束后恢复、权限撤销/切账号、重复点击与断网重试、部分提交成功后继续、原图已删除/草稿过期。

没有匹配公寓、没有密码、待审核、识别失败是不同状态。用户纠正一条不得重跑已成功的整批。失败保持已确认项，不公开错误关联密码。

## 7. 技术开发拆分与契约状态

以下是实施设计方向，不是已生效的API/SQL。当前OpenAPI及已应用0001迁移尚未包含导入实体；先扩展源契约/生成器，再生成类型，新增迁移，禁止修改已应用0001冒充升级。

| 工作项 | 设计要求 |
|---|---|
| IMP-01 / T25 | 用户授权样本集与识别方案实测：地址字段、符号、误配、单图多条；记录样本构成和人工真值，技术调用前使用合成/脱敏样本 |
| IMP-02 / T26 | 原型B04/B05/B06与U01/U06/H01/B02入口；空、进行中、异常、部分成功、待审核、恢复状态 |
| IMP-03 / T27 | 导入API、owner/资格权限、状态转换、分页/逐项提交DTO、幂等与留存；OpenAPI源和生成器同步更新 |
| IMP-04 / T28 | 新增导入批次/源文件/候选记录实体、加密及清理任务；采用增量迁移 |
| IMP-05 / T29 | 异步提取/匹配worker、按图隔离重试、任务租约、取消竞态、输入不可信防护和费用限额 |
| IMP-06 / T30 | iOS/Android选图、上传、确认编辑、批次恢复与部分提交；复用现有单条贡献事务 |
| IMP-07 / T31 | 双端真机、权限矩阵、失败恢复、去重/排序、删除、同区域真实线路命中率验收 |

建议接口职责：创建本人批次、申请短效上传、完成单文件上传、启动处理、查询本人批次与候选、修正候选、提交选中项、取消/删除未提交资料。接口路径、operationId、错误码、分页与大小限制在T27冻结；页面目录中的新节点明确标“接口待扩展”，不能伪造已存在operationId。

建议实体：import_batches（owner/状态/版本/保留截止/计数）、import_sources（批次/私有对象引用/状态/清理截止）、import_candidates（来源关联/受控候选/匹配目标/歧义/确认版本/提交结果）。不在父批次JSON存整批明文密码；允许同一候选关联多张源图，同图产生多候选。成功后只关联正式贡献事件，保留最少可追溯元数据。

批次状态拟为created/uploading/queued/processing/needs_review/submitting/completed/partial_failed/failed/cancelled/expired；候选有待补充/待匹配/待确认/可提交/已提交/重复/待审核/失败/移除状态，最终枚举随契约冻结。服务端按owner、当前资格、版本和单项幂等执行，不相信客户端提交的OCR分数或“可发布”标志。确认后地址/密码再变更必须重新确认。

首版不增加承运商SDK或导入承运商任务数据。并发/图片数/图片大小/总量/每日额度/超时、OCR可自动归组的阈值与草稿保留期均为待实测配置；至少设置有限预算与返回明确错误，不承诺无限导入。系统识别文本是数据，不执行截图里嵌入的指令、链接或工具调用。

## 8. 验收与冷启动指标

P0完成必须有以下证据，而不只是OCR演示成功：

1. 一张合法截图可正确提取并匹配公寓与密码；司机无需重新输入完整地址，确认后通过正式贡献链路可被有资格的另一账号查询。
2. 多图批量能一次确认所选完整记录；少数异常不阻塞其他项，后台处理/进程重启后可继续。
3. 多地址不串码；0/O、前导零、#/*样本保留；错栋/缺地址不能作为已确认首码发布。
4. 重复上传、重复点击、并发提交不产生重复正文、不刷新原贡献时间、不伪造有用反馈。
5. 无权账号不能读取他人原图/候选、猜ID或越权提交；密钥/OCR依赖失败不退明文，删除/取消不回写已过期资料。
6. 公寓提议待审核、正式贡献待审核与已可展示分别呈现，结果数可逐项核对，不将HTTP成功计作有效密码。
7. iOS/Android真实选图和会话恢复验证，记录处理耗时、人工修正次数、单条确认操作量及实际调用费用；没有实测前不承诺准确率或秒数。

观测：单张/批次完成率、无需改地址的匹配比例、地址与密码配对错误率、待处理比例、确认操作数/耗时、每条新增可用记录成本、首次查询命中率及后续实际有用反馈。统计只记必要计数/耗时/状态，不记地址、密码、图片内容或司机精确轨迹。先覆盖几个相邻线路区域，逐步验证供给是否改善查询体验，不以导入条数替代有效覆盖。

## ADD-08 贡献优先与按入口确认范围（2026-10-30）

本节为最新规则，覆盖此前“所有截图默认私存”和“我的仅一个入口”的描述。产品首要价值是司机能查到共享密码；贡献公寓密码是主要操作，我的公寓是个人管理入口，两者职责不同，不是重复列表。

- U01：突出“贡献公寓密码”，打开截图识别（主要）/快速填写；“我的公寓”作为次级管理菜单。文本粘贴/表格导入仍P1，不加到首版主要菜单。
- H01收起有密码：显示优先密码，不显示“已收藏/我的公寓”文字。收起无密码：显示“暂无共享密码”和主要“添加密码”按钮，直接带入已选公寓的填写页，不要求重复输地址。
- H01展开：添加密码在地址之后、历史列表之前；收藏用地址旁可读屏图标，不在密码列表底部堆主要操作。未定位/多候选/无资格/网络错误不得假装暂无密码；先解决目标或权限。
- B02：首页添加自动带入明确选择的公寓，按钮“确认共享”，来源声明必选；同码不刷新贡献时间、不增加有用票。通用快速填写先选择/核对公寓，不以当前位置默认猜栋。
- B04/B05：从贡献入口进入默认共享贡献；从我的公寓“导入私存”进入默认仅自己保存。确认页用可见的单选范围与明确提交文案，不静默切换；共享时说明同时保存到我的公寓。提交前需明确来源声明，共享资格不足可主动改选私存，不自动降级。
- 批次首次提交锁定范围；失败重试不扩大分享。未提交时切换范围会清除先前确认，必须重新核对。私存与共享仍分别持有结果，部分失败保留已保存内容。
- U06我保存的卡片直接显示一条密码和门别、多条时显示“另有N条”。本人私存标“私人记录”；只收藏的公寓读取最新且当前有权查看的共享密码，不复制为私存。资格不足只隐藏共享正文，不隐藏本人正常私存。

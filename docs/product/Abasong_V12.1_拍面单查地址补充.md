# ADD-16 拍面单查地址

2026-10-31，用户批准纳入规划。排在首页自动查码核心流程之后、临时支援业务扩展之前。L1实验已记录；L2原型、原生相机入口及确认流程已接入开发版，验收边界见下方记录，不代表生产上线。

## 价值与范围

蓝点表示司机实际位置，面单表示配送目的地。司机在街边、停车区、相邻楼之间，或希望提前查下一站时，可拍面单取得目的地地址。到达公寓后自动出现地址和密码卡片仍是首要路径。

一个入口：公寓搜索页 S01 输入框旁的相机图标，名称“拍面单查地址”。不增加首页悬浮按钮、底部导航或独立任务中心。不读条码查运单、不接承运商账号、不做 POD；也不写入截图贡献批次、私人库或共享密码。

## 简洁流程

1. 搜索页点相机，首次调用系统权限；拍一张面单。
2. 端侧识别后回到同一搜索页，显示提取的收件地址，允许直接修改。司机核对后点“查找此地址”，再使用现有 Mapbox 候选列表。原始整段 OCR 不进入输入框或外部查询。
3. 点选地址，沿用现有定位/公寓匹配：明确匹配则打开公寓卡片，否则显示临时目的地卡片。地图相机可以移动，GPS 蓝点仍表示真实位置。

不另加上传、批次、识别详情、保存进度或继续上次页面。后续可通过实测缩短操作，但不得因 OCR 高置信度就跳过地址核对或直接选中第一条地图结果。

## 信息和状态

| 状态 | 信息与操作 |
|---|---|
| 拍照前 | 单张拍摄，返回仍保留原搜索输入 |
| 正在识别 | 简短“正在识别地址”，返回可取消；迟到结果不得覆盖后来手动输入 |
| 唯一完整地址 | 门牌/街道为主，城市/州/邮编为次；主操作“查找此地址”，可修改或重拍 |
| 多个收件地址 | 最多5项，逐个选地址；不自动选一个，不混入寄件地址 |
| 字符不确定/地址不完整 | 仍使用同一输入区域核对修改；不猜门牌，不擅自补当前城市或最近公寓 |
| 没识别到地址 | “没识别到收件地址”；“重新拍照”或“手动输入” |
| 拒绝相机权限 | 保留手动搜索；永久拒绝时可去系统设置，无反复弹窗 |
| 搜索断网/无结果 | 复用 S01 现有重试/修改地址；不要求重新拍照 |
| 公寓有资料/没密码/未匹配/没资格 | 分别复用现有卡片，不将房屋或商业地址标成公寓，也不把没资格写成没密码 |
| 离开/退出账号 | 清理当前照片和识别内容；不产生跨次历史或可恢复批次 |

## 识别和数据规则

- 优先 `To`、`Ship To`、`Deliver To`，排除 `From`、`Return Address`。两栏面单按空间归属，不能按全部文字拼接。
- 合并门牌街道、城市、州、邮编；公寓房号仅供本次识别判断，外部搜索使用楼宇级地址，不为每个 Apt/Unit 新建公寓。楼栋后缀无法确定归属时要求核对。
- 不将手写停靠号、线路号、条码内容、电话或邮编当门牌；不把字母 O 自动转为 0。地址分类和公寓身份继续由原有匹配流程判断。
- 地图候选如果门牌/城市/邮编与确认的地址冲突，应显示差异并让用户选择，不静默纠正后自动跳转。多候选和无资料继续保留手动选择。
- 端侧 OCR。原图不上传，不主动保存到相册；识别结束后清理本次缓存照片，取消等待后须等原生任务实际释放文件再清理。业务层不保存姓名、电话、运单号、EXIF、原始 OCR 或搜索历史；原生只为校正图像读取方向。系统强杀时未返回的相机缓存不能保证即时清除，由系统缓存回收兜底，需列入真机恢复验收。只向既有地址接口发送用户确认的最小地址。
- 不调用扫码/POD接口，不保存面单内容到贡献记录。照片处理采用现有大小、像素和任务取消约束；手机拍照图片须验证方向和尺寸后再交给 OCR。

## 设计和实现边界

沿用 V3 字体、颜色和触控尺寸。相机图标只有搜索地址这一项含义；不出现“批次、任务恢复、OCR置信度”等面向工程的字段。识别和手输共用结果列表，视觉验收仍对照原型。

可复用现有端侧 Apple Vision/ML Kit 模块与搜索接口 `POST /v1/search/addresses/suggest`、`retrieve`；本批不新增后端接口、数据表、依赖或权限能力。已接入相机权限、单张拍摄、照片方向、缓存清理、同页核对与现有地址搜索。后台/相机返回保留当前操作，退出与迟到结果隔离；旧原生安装包显示更新提示，不直接调用缺少权限描述的系统相机。

## 分批交付与验收

| 批次 | 交付 | 验收条件 |
|---|---|---|
| L1 识别可行性（已完成合成实验） | 独立地址提取器、合成面单、离线实验报告 | 区分地址来源、房号归并、负样本和失败样本均记录；不能把合成图准确率当真实准确率 |
| L2 搜索页原型与原生接入（本批） | S01相机/确认状态，单张拍摄，现有联想/地图链路 | iOS/Android同状态对照；取消/拒绝权限/弱网/重拍/后台返回/不移动蓝点通过 |
| L3 真机可用性 | 获明确授权的脱敏多承运商面单与真实手机拍摄 | 至少30张、3种布局，含两栏、褶皱、倾斜、反光、模糊、手写覆盖；单列门牌错误、寄收混淆、重拍率、耗时和完成率 |

L3建议试点门槛：清晰样本正确收件楼宇地址候选至少95%，负样本不得自动选错目的地；正常光照手机端识别等待 p95 不超过3秒。必须记录实际分母、设备与图片条件；30张只是起点，不是总体准确率证明。另比较同一组地址“手输联想”和“拍照核对”的中位完成时间，确认拍照确实更省事后再开放常用入口。任何强制门牌猜测、原图上云、自动选错建筑都阻止放行。

当前证据见[实验与门外匹配记录](../technical/D1_门外样本核对与面单识别实验.md)。本批不要求用户提供真实面单，也不把已附照片复制到仓库或发送给地图服务。

L2实现与实际验收见[拍面单搜索原生接入](../technical/D1_拍面单搜索原生接入与验收.md)。当前不通过照片推断公寓身份、不改变资料权限、不启用正常库自动认定。

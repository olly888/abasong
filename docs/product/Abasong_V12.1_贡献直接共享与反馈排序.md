# ADD-11：贡献直接共享与反馈排序

2026-10-31，依据用户最新决定。覆盖旧 PRD、截图/私人库补充及技术计划中“每条密码贡献必须人工审核后展示”的规定；首页自动查码仍为最高优先级。

司机到门口需要立即获得信息，贡献者也需要立即看到自己的贡献生效。逐条人工审核既拖慢覆盖积累，也不能替代现场使用验证，因此取消正常贡献的运营审批。

## 司机流程

- 手动添加：选择/确认公寓 → 输入密码 → 确认共享 → 已共享。
- 截图导入：选择图片 → 核对地址与密码 → 确认共享 → 逐条显示已共享、相同记录或失败。文本/表格后续复用相同发布规则。
- 私存转共享：本人主动确认 → 已共享；私人备注、整本资料和截图不随共享公开。
- OCR 的“待确认”指司机自己检查识别结果，不是运营审核。没有匹配到公寓的资料保持待补充，可先私存；不将未知地址或最近建筑静默当成目标公寓。
- 正常成功页不出现“等待审核”；使用“已共享”。共享成功不表示密码已实测有效。

## 排序与反馈

1. 对同一公寓、适用门别的可展示记录，近期存在有效“有用”反馈的排在前组；有效时间窗沿用服务端当前配置。
2. 每组按首次贡献时间从新到旧排列，稳定 ID 只用于同时间打平；不按累计点赞量把老密码永久置顶。
3. 同码同门别合并：保留贡献事件，不新增重复密码、不刷新首次贡献时间、不自动增加有用票。
4. 同一司机对同一记录只有一份当前反馈，可以更改或撤回；有用→不能用后，该司机原有用票不再计入优先级。其他司机的有效有用反馈仍按规则保留。
5. 历史截图的本次上传日期不能被当成最近成功使用日期。已过期、失效、撤回或暂停展示的记录不进入正常查码结果。
6. “不能用”是现场反馈，不等于单次点击即可删除其他司机资料；后续可根据真实反馈样本验证冲突提示或自动降权阈值，本批不凭空制定人数阈值。

首页收起卡展示当前排序第一条；展开卡内按同样顺序查看历史、反馈和添加新密码。本人纠正、撤回及举报异常保留为产品能力，不再作为每条贡献上线的前置工作。本批不声称尚未实现的纠正/撤回接口已完成。

## 实施边界

取消的是每条密码的人工审批，不改变已有登录、共享范围、对象权限和来源确认。没有新增司机操作步骤、运营工作台或审批队列。异常投诉处置与正常贡献发布分开；不把审核接口列为 D1 正常查码的依赖。

新贡献在同一事务中写入密文、创建事件并发布；重复请求重放原结果，不重复发布或生成反馈。旧版历史 pending 保留未发布，本批不批量解密或迁移旧内容；正常新贡献不再产生 pending。已撤回/失效/暂停展示/过期的记录不能借重复上传恢复。

新增 0006 仅记录创建时是否直接发布，保证旧请求和新请求的重试结果可区分；不改变密文版本、原贡献时间或旧资料状态。`created_pending`/`pending` 保留为历史结果兼容，正常新贡献返回 `created_active`/`active`。

## 验收

- 司机 A 手动贡献、私存转共享、确认截图提交后，司机 B 在有查看资格的前提下立即可读，不需要操作数据库批准。
- 无资格、未确认、未匹配公寓不得绕过已有条件；失败与部分成功如实显示，重试不重复贡献。
- 首次发布没有有用票；有用优先、时间倒序、同码不刷时间、反馈覆盖规则一致。
- 记录后来撤回后，重放旧成功请求不使记录重新展示。
- 原生/原型不把“已共享”写成“验证有效”；物理设备和现场自动识别另行验收。

# Abasong V12.1 页面功能、信息与交互规格

日期：2026-10-29。状态：原型制作基线；非已完成页面清单。产品依据：[V12 PRD](../../Abasong_PRD_V12_首版产品需求.md)及[V12.1补充决策](../Abasong_V12.1_需求补充与原型决策.md)。颜色/组件依据：[V3设计系统](../design/Abasong_设计系统_V3_原型制作基线.md)。

## 1. 全局规则

产品只做临时配送支援与灵活运力协作，不设置长期招聘/司机招募流程。根导航固定首页/司机圈/我的；公寓/找活/找人为同一首页路由的状态。二级页面和公共面板可暂时隐藏导航，返回恢复来源视图、选中对象、筛选与滚动。登录后回到发起动作前的对象，但重新读取当前条件，不自动提交过期报名。

每个界面只保留必要信息和一项当前主动作；空/错误/审核/来源/地图归属属于必要状态，设计说明、策略备注、合成数据说明留在原型外壳，不能成为产品首页常驻文案。

普通草稿可保留；密码/进入信息明文只在编辑会话内存保留，不写通用持久草稿。用户切账号、退出或资格被撤销后清理敏感缓存。需求、私聊、进入资料各自鉴权，不因显示同一地图就共享访问权。

菜单按对象权限显示：发布者管理自己的需求，报名者管理自己的报名；司机与DSP不切换客户端或导航。当前没有支付、交接履约、司机排名、会员密码付费墙。

原型使用合成资料和模拟请求；每个状态应可在原型外的场景控制中触发。开发说明/测试开关不出现在产品画面。

## 3. 逐页规格

### A02 · 手机号登录

**载体与入口：** 全屏二级页；保留来源意图；报名、联系、看受控资料或我的登录入口。

**信息顺序：**

1. 返回
2. +1区号选择与手机号
3. 获取验证码
4. 必要协议链接

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 返回 | G03 | 退出登录并回原来源，不丢草稿 |
| 获取验证码 | A03 | 校验格式后请求OTP，禁重复请求 |

**必须制作的状态：** 默认；号码错误；发送中；限流/失败；来源需求已终止。

**接口 operationId：** Auth SDK或纯客户端/来源动作；不新建无业务价值的接口。

**验收：** 登录前后身份变化不复用上一个账号的缓存；无业务资料在此页公开。

**需求映射：** AUTH、V12-15。

### A03 · 验证码与恢复

**载体与入口：** 二级页，同一认证流程；A02发送成功。

**信息顺序：**

1. 掩码手机号
2. 验证码输入
3. 重发倒计时
4. 更改号码
5. 验证错误

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 更改号码 | A02 | 清除验证码并保留安全来源 |
| 验证 | A04 | Auth成功后bootstrap，老用户直接回来源 |
| 重发 | A03 | 遵守供应商限流，不默认每点发短信 |

**必须制作的状态：** 输入；验证中；错误/过期；重发受限；登录成功回跳。

**接口 operationId：** bootstrapMe。

**验收：** OTP不进日志；登录后重新请求来源对象，不能自动提交旧报价报名。

**需求映射：** AUTH、V12-15。

### A04 · 首次最小资料

**载体与入口：** 二级页，仅新账号；A03新账号。

**信息顺序：**

1. 显示名
2. 保存按钮；经验和车辆不强制在首次查码前填写

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 保存 | H01 | bootstrap完成后回原意图，H01只是无来源时默认 |

**必须制作的状态：** 空；保存中；校验失败；资格待审核。

**接口 operationId：** bootstrapMe、patchMyProfile。

**验收：** 显示名不能自带官方核验身份；登录不自动授予密码资格。

**需求映射：** AUTH。

### H01 · 首页·公寓

**载体与入口：** 首页根状态，公寓卡收起/展开；首次启动、首页导航、主动切公寓。

**信息顺序：**

1. 搜索、消息
2. 公寓/找活/找人
3. 定位与公寓建筑
4. 收起：名称/英文地址/首条密码/贡献时间
5. 展开：各条密码、必要门别/时段、实测时间、反馈、添加
6. 独立＋发需求
7. 三项底部导航

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 搜索 | S01 | 带公寓视图 |
| 消息 | M01 | 开统一消息 |
| 点卡/拖手柄 | H01 | 同一面板展开，不新建一层页 |
| 不是这栋 | L01 | 候选/手动纠错 |
| 点密码 | B01 | 大字模式 |
| 有用/没用 | H01 | 作用于本记录；失败回滚，重排保留阅读锚点 |
| 添加/更新 | B02 | 公寓ID带入；新增记录不覆盖历史 |
| ＋发需求 | P01 | 独立于卡片 |
| 定位 | H01 | 主动解除选择锁定后重新匹配 |

**必须制作的状态：** 冷启动；唯一命中收起；历史展开；多候选；暂无密码；无固定码；无资格；定位拒绝；粗略/旧位置；弱网/底图失败；记录失效/撤回；反馈提交失败。

**接口 operationId：** resolveApartment、getApartment、readAccessRecords、feedbackAccess。

**验收：** 首次默认公寓；卡外无有用/没用/更新行，无楼宇/入口/停车菜单；GPS不抢走已选公寓。

**需求映射：** V12-01、V12-02、V12-03、V12-04、V12-05、V12-06、V12-07、V12-08。

### H02 · 首页·找活

**载体与入口：** 与H01同一路由的地图状态；首页切找活。

**信息顺序：**

1. 搜索与消息
2. 区域需求标记/聚合
3. 日期/支援类型筛选
4. 选中卡：配送区、具体日期/时段、数量/人数、最低量、报价单位、截止/缺口
5. 独立发需求与导航

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 点标记 | H02 | 选中并更新卡，不切身份 |
| 卡片 | D01 | 看需求条件 |
| 搜索/筛选 | S01 | 找区域/承运商/支援类型 |
| ＋发需求 | P01 | 统一发布 |
| 列表 | H02 | 同视图切可操作需求列表，不叠新导航 |

**必须制作的状态：** 有需求；列表替代地图；无需求；区域无结果；过期/关闭即时移除；加载失败。

**接口 operationId：** listRequests、listRegions。

**验收：** 地图定位配送区，取件地区另列；所有配送支援明确当次件数与时间，不伪造报价或到场承诺；只有一条可见选中卡。

**需求映射：** V12-09、ADD-01、ADD-03。

### H03 · 首页·找人

**载体与入口：** 与H01同一路由的地图状态；首页切找人。

**信息顺序：**

1. 区域标记/聚合
2. 服务区域/相关经验筛选
3. 司机卡：显示名、声明时段、容量、经验来源
4. 我的可接活入口
5. 发需求与导航

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 司机卡 | D02 | 看最小档案 |
| 搜索/筛选 | S01 | 按服务区/承运商 |
| 设置可接活 | U03 | 本人主动开放 |
| 列表 | H03 | 同状态可操作司机列表 |
| ＋发需求 | P01 | 统一入口 |

**必须制作的状态：** 有效可用司机；列表替代；无人可接；司机未在线但声明有效；时段刚到期；加载失败。

**接口 operationId：** listAvailableDrivers、listRegions。

**验收：** 不画精确车点/轨迹；不以关闭App判不可用；区域中心不叫司机当前位置。

**需求映射：** V12-13、V12-14。

### S01 · 搜索与筛选

**载体与入口：** 二级搜索页，依来源切内容；H01/H02/H03搜索。

**信息顺序：**

1. 返回/输入/清除
2. 公寓：自有地址名称，外部临时候选独立来源
3. 找活：区域、承运商、支援类型、日期
4. 找人：区域、承运商经验
5. 结果列表/空态

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 返回 | H01 | 回原地图视图与选中对象，非固定切公寓 |
| 选择公寓 | H01 | 锁定用户选中公寓后查权限与记录 |
| 选择需求 | D01 | 展示当前版本 |
| 选择司机 | D02 | 展示最小档案 |
| 选择外部地址 | L01 | 仅用于当前定位候选，不默认入永久库 |

**必须制作的状态：** 空查询；输入联想；自有结果；仅外部地址；无结果；失败；筛选后无结果。

**接口 operationId：** searchApartments、suggestAddresses、retrieveAddress、listRequests、listAvailableDrivers。

**验收：** 不持久保存敏感搜索历史；切来源调整字段，不用全站万能搜索混放私人账号。

**需求映射：** V12-02、V12-08、V12-18、ADD-03。

### L01 · 选择正确公寓

**载体与入口：** 地图底部选择面板；多候选、不是这栋、外部地址选择。

**信息顺序：**

1. 当前候选地址/名称
2. 地图候选对应高亮
3. 手动搜索
4. 没有这栋/纠错

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 选这栋 | H01 | 锁定并查询，不拿最近邻码代替 |
| 搜索地址 | S01 | 带当前搜索词 |
| 没有这栋 | B02 | 先提交公寓提议再贡献，均待规则核验 |

**必须制作的状态：** 多栋；仅地址无公寓；候选已撤回；提交纠错失败。

**接口 operationId：** getApartment、proposeApartment、correctApartment。

**验收：** 外部临时地址不自动变有权长期存储的自有公寓；无匹配能退出。

**需求映射：** V12-02、V12-08。

### B01 · 密码大字

**载体与入口：** 轻量全屏/弹层；H01点单条密码。

**信息顺序：**

1. 所属地址
2. 该条密码/进入方式大字
3. 必要适用范围
4. 关闭

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 关闭 | H01 | 恢复原展开位置 |

**必须制作的状态：** 正常；记录已撤回/资格失效；重新加载失败。

**接口 operationId：** readAccessRecords。

**验收：** 退出清敏感内存；不提供批量复制/分享密码按钮；不把已失效缓存继续显示。

**需求映射：** V12-07、V12-17。

### B02 · 贡献密码/进入方式

**载体与入口：** 编辑面板，可随键盘展开；H01添加/更新，L01无这栋。

**信息顺序：**

1. 固定所属公寓/纠错入口
2. 密码或进入方式
3. 可选门别/时段
4. 有权分享来源确认
5. 保存；未知公寓先提议地址

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 保存 | H01 | 新增待审核/可用记录或同码验证；不覆盖原记录 |
| 取消 | G03 | 未提交内容仅内存保留，本轮不将明文草稿持久化 |
| 改公寓 | L01 | 先确认目标再提交 |

**必须制作的状态：** 空；同码验证；新记录；来源未确认；权限不足；待审核；保存失败；公寓提议待审核。

**接口 operationId：** contributeAccess、proposeApartment。

**验收：** 保存成功状态准确，不将pending放进可用首码；0/O、1/I、#/*可辨；请求重试复用幂等键。

**需求映射：** V12-04、V12-05、V12-06、V12-07。

### P01 · 统一发需求选择

**载体与入口：** 首页工具展开面板，合并旧P02；任一地图＋发需求、司机圈发需求。

**信息顺序：**

1. 配送找人/车辆求助/其他配送求助
2. 配送子类：部分包裹/整条线路/增加司机
3. 增加司机指本次配送临时缺人

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 配送类型 | P03 | 创建对应表单，保留类型草稿 |
| 车辆/其他 | P04 | 打开共用短表单 |
| 取消 | H01 | 恢复来源视图 |

**必须制作的状态：** 一级类别；配送子类；已有草稿选择。

**接口 operationId：** createDraft。

**验收：** 司机DSP共用，无角色工作台；发布后改类型走复制新草稿。

**需求映射：** V12-09、ADD-01。

### P03 · 配送找人发布/编辑

**载体与入口：** 全屏表单；类型内短分组；P01或P09编辑/复制。

**信息顺序：**

1. 基础：承运商、配送区、单一取件区
2. 时间：具体日期、开始时段与有效截止
3. 数量：当次总量/人数/拆分/最低量
4. 报价金额+单位或议价
5. 理货/接手条件
6. 相关配送经验要求
7. 可选：车型/特殊配送条件与私下付款约定
8. 提交摘要与发布

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 发布 | D01 | 先校验和摘要确认，再发布成功回本人详情 |
| 保存草稿 | U04 | 仅本人可见 |
| 返回 | G03 | 选择保留草稿或放弃，不丢状态 |
| 切换类型 | P01 | 仅未发布可切；已发布不提供此项 |

**必须制作的状态：** 部分包裹；整线；临时增人；联系议价；最低量错误；不同取件/配送区域；编辑版本冲突；提交中/失败。

**接口 operationId：** createDraft、updateRequest、publishRequest。

**验收：** 每条配送支援明确当次件数/时段；不设招聘周期/试线/带教流程；无代收/支付选项；未填金额不显示$0。

**需求映射：** V12-09、V12-11、ADD-01、ADD-02、ADD-03、ADD-04。

### P04 · 车辆/其他配送求助

**载体与入口：** 复用简短发布表单；P01车辆/其他。

**信息顺序：**

1. 求助类型
2. 大致区域
3. 时间/截止
4. 必要说明
5. 联系入口

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 发布 | D01 | 创建普通同行求助，不承诺专业到场 |
| 返回 | G03 | 保留或放弃草稿 |

**必须制作的状态：** 车辆；其他；缺字段；发布失败。

**接口 operationId：** createDraft、publishRequest。

**验收：** 车辆修理和包裹找人是两类需求，用户可另发配送找人，不自动生成专业维修订单。

**需求映射：** V12-09。

### D01 · 需求详情

**载体与入口：** 二级页；本人/他人不同动作；H02、司机圈需求卡、通知、我的、分享登录回跳。

**载体与入口：** 公共分享面板，仅发布者；D01/P09本人分享。

**信息顺序：**

1. 将公开的需求摘要
2. 复制链接/系统分享
3. 撤销链接
4. 来源状态

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 生成/复制 | G02 | 生成token并系统复制，用户自行发微信 |
| 系统分享 | G02 | 调用OS分享，不保证存在微信专用按钮 |
| 预览 | X01 | 看游客公开摘要 |
| 撤销 | G03 | 立即使token不可用 |

**必须制作的状态：** 未生成；可分享；公开字段待核对；生成失败；链接已撤销；需求已结束。

**接口 operationId：** createRequestShare、revokeRequestShare。

**验收：** 不默认发朋友圈；无电话微信/精确集合点/报名名单/门码。

**需求映射：** ADD-05。

### X01 · 外部公开需求摘要

**载体与入口：** H5公开页，App深链/登录桥接；用户主动分享的token链接。

**信息顺序：**

1. Abasong标识
2. 只读公开摘要
3. 状态/有效期
4. 打开App、报名/联系入口
5. 未安装时分发入口

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 报名/联系 | A02 | 保存token+意图，登录后查最新需求再进入D01/P08 |
| 打开App | D01 | 深链成功后仍查当前权限与状态 |

**必须制作的状态：** 开放；已结束仅终态；token无效/撤销；登录回跳条件变化；未安装App。

**接口 operationId：** getPublicRequestShare。

**验收：** 游客不访问完整Request接口；不能通过token读私聊、司机库或公寓码；首版不承诺H5完整报名工作端。

**需求映射：** ADD-05。

### G03 · 确认/错误/恢复

**载体与入口：** 全局组件状态，不是独立路由；表单退出、撤回、关闭、删除、错误。

**信息顺序：**

1. 明确对象与动作
2. 必要结果说明
3. 主动作/取消或重试

| 元素/动作 | 目标 | 操作结果 |
|---|---|---|
| 确认 | G03 | 执行来源动作，成功返回来源状态 |
| 取消 | G03 | 不改变业务 |
| 重试 | G03 | 复用幂等意图，不清空输入 |

**必须制作的状态：** 未保存退出；关闭需求；撤回记录/报名；删除草稿/动态；退出/删账号；服务错误/版本冲突。

**接口 operationId：** Auth SDK或纯客户端/来源动作；不新建无业务价值的接口。

**验收：** 不弹长段教学；危险操作用明确名称，非统一写确定；共享组件按来源完成回跳。

**需求映射：** V12-07、V12-11、V12-12、V12-15。

## 4. 制作与变更规则

36个节点包含首页状态、面板、H5和全局组件，不等于36条原生独立路由，也不是所有状态各复制一页。原有V1.1的B03/P02/P06/P07/C05/M03/U07/U12–U14在本版合并；C04生活专用表单/U09综合收藏/完整组织成员管理继续后置。

每个动作目标必须能到达，空白按钮不得伪装完成。接口由openapi-v12.yaml提供，operationId在目录中可机器检查；该文件保留名称，版本升为12.1。新增功能需更新补充决策→页面目录→接口/数据→原型与验收，不在画稿时临时加业务。

后续先做公寓完整闭环，再做找人找活/分享，再做消息与常联系，最后补最小社区/我的；所有批次遵循同一套品牌和组件，不把多个历史版本混在同一原型。

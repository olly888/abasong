# 首页自动查码：场景、交互与验收基线

2026-10-31。用户批准本批为最高优先级（ADD-10）。优先于此前统一空卡、卡片展开暂停定位等实现；账号资格和来源许可继续适用。正常贡献的逐条人工审核已由 ADD-11 取消。此文规定目标，执行证据见工程状态。

## 核心流程

首页前台持续接收设备位置 → 可靠识别公寓/社区或已核对入口到达区域 → 同一底部卡片显示地址和有权共享资料。打开时主动读取；不用搜索作为默认起点。地图底图、设备GPS、公寓关联、共享资料是独立职责。无密码不表示没有门禁，无候选不表示不是公寓。

蓝点、相机和卡片分别控制：蓝点在首页前台持续更新；用户拖图后不自动拉回；展开或手动选择锁定阅读而不停止定位。定位按钮回到新鲜蓝点并解除选卡锁定。后台/离开首页停止采集；恢复前台重新检查权限。过期位置不冒充实时位置，读取失败不冒充暂无密码。

读取失败后的重试保持原有自动或手动阅读状态，不因为重试锁住自动卡片，也不强制折叠卡片。自动卡片在匹配失效、配置改变或位置不再可信时清除；进入下一公寓重新完成稳定停留。不能让上一栋的密码在新位置继续显示。

## 场景与信息层次

| 场景 | 底部卡片 | 操作 |
|---|---|---|
| 位置获取中 | 低高度“正在定位” | 不重复搜索或定位按钮 |
| 可信范围/入口稳定命中、有密码 | 名称、完整地址、首条密码、时间 | 点开历史/反馈；添加位于展开顶部 |
| 已命中、无共享密码 | 地址、“暂无共享密码” | 直接添加，带入公寓ID |
| 无资格或读取失败 | 保留所选地址，对应资格/失败状态 | 不当成空密码；失败可重试 |
| 附近候选、未确定目标 | “附近公寓”，少量名称及地址，不显示密码 | 点选；全部候选可滚动查看 |
| 多个可能入口/公寓 | “选择公寓”，名称和地址 | 一次确认，不按最近距离猜测 |
| 街道、普通house、商业地点且没有相关候选 | 低高度“共享公寓密码”入口 | 顶部搜索和地图右下定位仍可用，无错误文案 |
| 数据覆盖未知 | 同上述中性状态，不宣布“不是公寓” | 不伪造地点类别或门牌号 |
| 定位拒绝/关闭/过期 | 简短、对应原因的状态 | 仅开启位置/系统设置/刷新 |
| 公寓资料查询失败 | “公寓资料暂时无法加载” | 重试资料，保留新鲜蓝点 |
| 读卡时GPS移动/漂移 | 保持用户选择 | 蓝点继续更新；主动定位恢复自动选择 |
| 自动卡离开目标 | 清除旧自动卡，进入附近/中性状态 | 不持续显示上一栋的密码 |

正常无候选态不显示“附近暂无已收录公寓，请搜索地址”、大空态图标或第二个搜索入口；模式不会自动跳到找活/找人。附近卡只代表候选，不是当前位置断言。建筑轮廓缺失时仍可显示正确地址卡，不能伪造轮廓。

## 门外识别

入口到达区域与建筑足迹分开。门外区域必须有明确公寓ID、核对时间、持久使用许可来源和可撤销状态；它可以位于建筑外的人行入口前，不以建筑全域缓冲或最近POI替代。普通用户不能直接把候选标为已核对入口。

自动匹配仍须新鲜、精准位置、唯一可信区域、稳定重复观测与启用的版本化配置。精度范围触及其他公寓/入口时只给候选；不串用同社区不同楼栋密码。未验证的入口、地址-only、过期来源和粗略位置不能升级自动认定。区域内的建筑高亮只使用已有正确建筑映射，不能把门外到达区域涂成建筑。

范围逐栋生效：每个已验证公寓分别记录建筑内/门外适用范围、依据及有效期；只有全局开关不构成启用条件。范围外或到期仍提供附近候选；相邻公寓即使未启用也参与歧义判断。该配置属于地图识别的工程验证，不增加密码贡献审核或司机端操作。实施证据见[限定识别与共享闭环](../technical/D1_限定公寓自动识别与共享闭环验收.md)。

## 交付顺序与验收

1. 原型及机读页面同步上述状态，保留截图贡献主入口。
2. 前台持续定位与查公寓解耦；串行查找合并新观测，旧响应不能覆盖新位置；手动阅读不被自动结果覆盖。
3. 增量入口区域存储/只读权限、匹配契约及本地HTTP/PostGIS边界测试；不应用云迁移。
4. 双端模拟器验证持续蓝点、卡片锁定、回位、到达/离开、无候选、无密码、失败及多栋歧义；合成资料明确TEST。
5. iPhone现场验证真实门口、相邻建筑、耗时和漂移；Android真机仍待设备。测试坐标/合成码不能冒充现场验收。未通过现场证据不开放全域自动匹配；开发测试须有明确样本范围。

成功定义：有读取资格的司机在有已共享资料的目标公寓门口打开App，不搜索即可看到正确公寓的密码。没有资料时准确显示地址和直接贡献入口。正常贡献确认后直接共享，不逐条人工审核。该成功定义必须独立于截图导入测试数量验收。

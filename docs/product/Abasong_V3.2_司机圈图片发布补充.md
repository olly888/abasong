# V3.2 司机圈图片发布补充

2026-11-06。用户批准首版文字加最多 3 张图片。UP14/UX12、G17/D17 已接通本地接口及原生 App，见[B5-04 实施验收](../technical/B5_04_司机圈私有图片实施验收.md)。

## 1. 目标和边界

司机用入口、通道或配送问题照片说明情况，同行更容易理解。文字必填（1–2000字），图片选填（0–3张），基础回复仍只用文字。图片不是发帖前提；按用户选图顺序发布，不做拖拽排序、视频、滤镜、涂鸦、图片评论或九宫格。3张是本项目首版范围，不是行业标准。

密码仍走受控贡献入口。面单、收件人、住户信息和门禁码不作为公开动态内容，选图区仅一行简短提示。客户端提示/示例正则不保证识别全部敏感信息；不新增图片OCR或逐张人工审核工作台。正常内容复用举报、屏蔽、本人删除；发布前可移除/补选图片，发布后首版按删除整条本人动态处理，不新增编辑已发布图片流程。

帖子图片用于讨论，不能自动成为经核实的入口或密码范围。长期入口图片关联公寓、确认适用地址及归档是后续能力；首版不新加“关联公寓”字段、不凭GPS或照片猜绑、不将社区某个入口套给全部建筑。

## 2. C01–03交互和视觉

| 场景 | 首版行为 |
|---|---|
| C03正文下方 | “图片 选填”和N/3，缩略图及添加格；拍照/从相册选择复用系统交互目标 |
| 选择/拍照 | 用户主动操作；取消保留全部原输入；拍照确认后才加入；保留选择顺序，补选追加，最多3张 |
| 发布前 | 可预览、移除、补选。文字/标签/地区/引用需求均保留，地区不读取GPS |
| 正在发布 | 图片未就绪不能假成功；禁重复提交和修改本次内容；技术状态不作为多层用户菜单 |
| 部分图片失败 | 图片标失败，错误处显示“图片未上传成功，请重试或移除”；主动作“重新发布”，仅处理失败/未完成图 |
| 图已上传、发帖失败 | 保留全部字段和已就绪图；重试同次提交，不重复发帖、不重传有效图片 |
| C01/C02阅读 | 正文→图片→同ID需求→回复。单图16:9缩略图、宽度适应、最高220逻辑像素；2/3图同一行紧凑方格，间距6、圆角12；大图完整显示不按缩略图裁剪 |
| 图片查看层 | 黑色背景、顶部关闭和位置；左右滑动/按钮切换、点击放大缩小；关闭回同一动态/编辑页及原阅读位置 |
| 图片失败/无权 | 有文字与重试；保留帖子其他内容；已删除/被屏蔽目标不展示原图，无权不能通过旧ID读取 |
| 回复 | 没有图片入口；现有文字发送/失败保留/通知规则继续有效 |

所有点击目标至少48，发布操作52；移除与预览的点击区域不可互相遮挡。原型 320/390/430 默认字号有合成检查。双端原生相册、Android 虚拟相机和按钮缩放已核对。真机拍照、双指缩放、200% 字号和读屏待专项复验。单图与网格改变信息流高度，不套地图192px外框或滑卡。

## 3. 草稿、恢复与删除

文字和选图引用仅当前账号会话，不上传前自动公开、不提供跨设备草稿。选图取消/查看图片/短暂切换不清空；保留本次草稿并返回可继续；放弃/注销清除本机引用；本次内容含仅图片也须询问退出，不能因正文为空直接丢图。截图密码贡献仍是原单次流程，无跨次续填。

客户端中断或账号变化不能在后台补发一条司机已离开的动态。真实网络请求可能已经被服务端接收，B5须用同一client_submission_id核对结果后重试；不能仅靠取消请求宣称服务端未写入。未发布上传按限期清理，已发布图片随帖子对象权限控制。

## 4. B5技术目标

详见[技术增量](../technical/V12.1_地图协作架构增量方案.md)。D17 接入私有媒体上传、读取及清理，createPost 已支持有序 media_ids。选择图片的界面经验可复用，截图OCR/密码批次不能当社区图片业务实现。

提交必须验证所有媒体属于本人、已就绪、未失效且数量≤3，同事务关联帖子，幂等防重复。服务端真实解码/大小校验和重新编码，去EXIF/GPS元数据；不相信客户端扩展名/MIME，不直接公开原图。错误保留本次本地图，资格/屏蔽/删除在服务端控制，缩略图和原图同权限。首版不创建公开图床或任意外链图片字段。

本地已应用 0022 并使用隔离图片目录。云端私有桶、费用及运行权限在实际部署前单独确认。原生真实图质量仍需获授权、不含面单/住户的样本验，不以TEST图代替。

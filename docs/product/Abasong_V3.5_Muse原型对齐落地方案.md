## 1. 结论与优先级

采用 Muse 的主要布局和信息组织：首页变为**上方地图＋下方纵向独立卡片列表**，列表顶部固定「查码／找活／找人」，底部仍为「首页／司机圈／我的」。不再用全屏地图叠横向滑卡作为新版首页。

这一变化让司机可以同时比较相邻地址、不同配送需求或可接活司机，减少逐张横滑；地图负责确认空间关系，列表负责阅读和行动。真正值得采纳的是清楚的任务分区、连续的阅读顺序、统一的卡片骨架和克制的品牌使用。

这也有代价：地图可视面积变小，长卡容易挤压列表；同时展示多个门禁码需要新的按需读取机制。实施先解决这两项，避免只复刻截图。

裁决顺序：本次用户明确指令 → 本方案明确标注的采纳项 → 既有产品和权限规则 → Muse 附件示例。未被本次明确改变的业务继续按现行基线执行。

**立即替代的旧目标：**横向露边滑卡、固定 192 高度、地图/列表二选一的首页结构；“公寓列表仅为 P1”不再适用于新版首页，因为纵向列表成为核心交互。既有独立管理列表不因此删除。

**不随界面改版自动引入：**团队成员、团队私有码、团队审核、接龙、分拣招聘、评分/爽约体系、邀请码追踪、付款结算和自动派单。

| 附件位置 | 内容 | 本轮处理 |
|---|---|---|

| 6 页 | 三类卡同骨架、信息条、底部分隔、整卡进入详情 | 采纳；同间距和层次，自适应高度，不把三类字段硬塞进同一固定高度 |

| 14、16 页 | 从业年限、日均件量、完成率与爽约等 | 有真实自述字段才展示；既有容量不冒充实绩。暂无可靠履约事件，不上线完成率/爽约数 |

| 15–16 页 | 清楚的动态流、轻量个人头部、本人资料预览 | 采纳视觉层次；保留最多 3 张私有图片/文字回复/举报/删除。本人对外预览作为后续小项，不泄露私有联系方式 |

```text
系统安全区
┌ 上方地图区域 ────────────────────┐
│ 官方字标                     消息 │
│ [ 与当前模式对应的搜索框       ] │
│                                  │
│ 公寓建筑 / 配送区域 / 声明服务区域 │
│ 比例尺                回到定位 ○ │
│ Mapbox 标识与 attribution         │
├ 下方内容区域 ────────────────────┤
│ [ 查码       找活       找人    ] │ ← 固定
│ 分区标题 · 真实结果数    主要操作 │ ← 固定
│ ┌ 独立卡片 A ─────────────────┐ │
│ │ 主信息 / 核心信息条 / 次信息 │ │
│ └─────────────────────────────┘ │
│ ┌ 独立卡片 B ─────────────────┐ │ ← 纵向滚动
│ └─────────────────────────────┘ │
└──────────────────────────────────┘
       首页        司机圈       我的
```

### 4.1 尺寸、布局与手势

- 初版建议地图约占可用内容高度的 **42%**，列表约 58%；可用高度已扣除系统安全区与底部导航。M1.1 已在 320/390/430 宽验证完整首卡及下一卡预览，不是所有设备固定像素。
- 在常见 390×844 尺寸中，目标为能读完第一张卡，并看到下一张的开头；320 宽、大字号和横向屏幕采用内容自适应，不能截断关键按钮来守比例。
- 上方地图有自己的实际布局高度，下面是白色内容区。列表不覆盖全屏地图；地图镜头、可视查询与控件都按真实地图尺寸计算。
- 三模式在内容区顶部，仅出现一处。取消原首页另一组模式切换和地图/列表按钮；首页本身已同时具备两者。筛选用分区行内带文字的次级按钮；有条件时在列表顶部显示可清除摘要，保留日期、区域、类型等既有能力。
- 普通纵向滚动只滚列表，地图固定；地图双指缩放和拖动仍由地图处理。第一批不增加抽屉多档拖动，不画不可操作的拖拽柄。
- 空态沿用统一上下结构，内容区显示简短状态和一项适合当前任务的行动；不堆多个大白卡或反复浮动 CTA。地图定位、搜索一直可用。
- 模式间保存各自筛选、选中对象、列表位置和镜头；从详情返回不重置。真正冷启动默认查码，短暂切后台不等于冷启动。

### 4.2 顶部与模式操作

| 区域 | 目标 |
|---|---|
| 顶部字标 | 官方 SVG/PNG，按比例展示，不用文字重新描绘；不加口号和“我的”标题横幅 |
| 统一消息 | 可使用统一铃铛图标，进入现有消息中心（会话＋通知），不再加第二个入口；无障碍名称“消息” |
| 查码搜索 | “搜索公寓或地址”，保留拍面单识别、Mapbox 联想、点选及地址核对 |
| 找活搜索 | “搜索区域或快递公司”，不让司机误以为能搜索公开仓库精确坐标 |
| 找人搜索 | “搜索区域或配送经验”，接口只筛实际支持的字段，不显示无法查询的条件 |
| 查码分区 | “附近公寓”，右侧“共享门禁码”；已搜索单个地址时标题用搜索语义 |
| 找活分区 | “配送需求”，右侧“发需求”；列表给出区域/日期筛选状态 |
| 找人分区 | “可接活司机”，发布找人入口仍可达；本人接活开关保持在“我的”核心位置，不挤进每张卡 |

邀请司机保留在“我的”。首版不为了照搬截图把邀请放到每个发现区域的首要位置。找人页可保留次级“发需求”，避免 DSP 找不到可用司机时没有下一步。

## 5. 三类卡片与空态

### 5.1 共用骨架与视觉

复用 `DiscoveryCard` 外框、内边距、选中态、信息行、分隔线和尾部入口，公寓/需求/司机保留各自内容组件。初始目标：外圆角 16、内边距 16、卡间距 10–12；选中边框不改变尺寸。常态以细边框为主，轻阴影只用于当前焦点。

品牌蓝 `#1769FF` 用于选中、主操作与少量重点；不把全部地址、标签、按钮都涂蓝。继续官方语义色和 Lucide 图标，不混 Emoji/另一套线宽。原型建议的 11.5px 不能直接当成原生阅读标准：正文 14–16、辅助 12–13、触控区域至少沿用现行 48；对比度和放大字体单独核对。

PDF 的 22px 高字标可能低于现行最小展示宽度。按正式资产长宽比与最小 120 宽执行，必要时调整顶栏高度，不压扁或裁切标识。

### 5.2 公寓卡

1. **地址行：**门牌数字重点加粗、后续街道常规字重，同一行；右侧固定米制近似距离。长街道优先保留门牌和方向，单行省略，详情及无障碍读出完整地址。
2. **辅助行：**城市用弱层级；不把完整州/邮编硬塞首行。搜索跨城市或同名街道时必须能辨认城市。公寓名退到详情及搜索。
3. **门禁信息条：**完整门禁码＋明确的门别；符号/前导零不改写。门别未知不猜。单条有用数只显示真实数据，空间不足时优先保码。
4. **来源行：**贡献时间和用户名保留，M1.1 与可见条数合并在尾行；不为套三行模板删除出处。
5. **底部：**可见信息数量与详情入口只在接口有可信统计时显示；没有可靠统计就用“查看门禁信息”，不捏造“司机确认过”。

有内容的整卡进入详情。无共享码卡片保留地址，直接提供“添加门禁码”这一主操作，进入同一表单且预填公寓；避免整卡点击和内嵌按钮同时触发。地图焦点不代表已确认配送目标，不贴“已到达/入口正确”。

### 5.3 找活与找人卡

| 卡片 | 主信息 | 中段 | 次要信息与点击 |
|---|---|---|---|
| 配送需求 | 仓库找司机 / 途中找代送；真实报价 | 派送区域、到场时间、件数口径与还需人数 | 快递公司、发布身份和取件区域；点击详情报名。仓库完整地址在有权详情显示 |
| 可接活司机 | 昵称＋当前有效可接时段 | 愿去区域、真实填写的容量/配送经验 | 经本人开放的资料；点击档案再联系。不把自报容量写成日均完成实绩 |

价格有条件才计算：确定数量且按件报价时可显示“按所填件数估算”，不能称为保证收入；约数、议价、待确认仍有对应表现。保持手工剩余缺口，报名不自动减少它。

找人不显示到某位司机的精确距离；服务区距离也不能缩写为“距你 XX m”。找活若当前只有区域展示点，显示区域，不给它伪造仓库行车距离。未来增加通勤估算应从已获权取件点独立计算并命名。

### 5.4 必须区分的页面状态

| 状态 | 展示与行动 |
|---|---|
| 人在 house，但附近有公寓 | 正常显示附近公寓列表；当前位置建筑类型不阻断发现 |
| 附近查询成功无结果 | “附近未匹配到公寓”；搜索/拍面单入口可达，次级“共享门禁码” |
| 单栋公寓无共享码 | 地址、距离仍在；“暂无共享门禁码”＋“添加门禁码” |
| 单栋读取失败 | 只该卡显示“门禁信息暂时无法读取”＋“重试”；不标暂无 |
| 暂停共享 / 无查看资格 | 分别使用现有专属状态，地址保留，不露内容或受限数量 |
| 定位关闭 / 低精度 / 过期 | 独立说明位置问题，距离弱化或隐藏；可搜索，不用示例位置顶替蓝点 |
| 无配送需求 / 无可接活司机 | 对应简短空态；有筛选时提供“清除筛选”，无筛选不展示无效清除 |
| 底图失败但业务成功 | 保留有效列表、提示地图不可用；不把业务结果一起清空 |
| 数据刷新失败 | 有时效的旧公共地址可保留并说明；失去权限的门禁正文立即隐藏，不用旧码冒充刷新成功 |

## 6. 地图、列表、距离与选中规则

### 6.1 联动与阅读保护

- 默认第一张公寓为当前发现范围内最近候选；查询排序与卡片距离使用同一次定位观察，不能各自计算。
- 点地图公寓 → 列表滚到对应 ID，卡片与建筑同时高亮；点需求区域按现有明确筛选行为执行，不悄悄改成全部区域。
- 列表停稳后选出最靠近焦点线的卡（约位于列表可滚动区上方 42%）；高亮针/建筑。滚动惯性未结束时不逐帧移动地图，不重复查码。
- 地图不因每张滚过的卡强制平移。停稳后的目标确实离开可视地图时才温和平移；用户正在拖图时暂缓镜头联动。地图选中引起的列表滚动不能再次触发循环移动。
- 用户看详情、主动滚动或拖图后，GPS 更新不重新排序并抢走当前对象。回到定位明确恢复附近推荐；找活/找人的定位仍保留用户筛选。
- 返回页面按稳定对象 ID＋列表偏移恢复；目标被关闭/停显/删除时显示真实变化并选择邻项，不套用旧内容。模式记忆不持久化门禁正文。

### 6.2 公寓范围：受控扩围规则及本地实现

保留200m作为第一档。**当前档成功且覆盖判断允许继续、不同候选不足3个时，依次尝试500m、1000m；最多三档、最多20个候选。** M4-01已同步实现客户端、API契约与空间查询，通过本地合成服务及PostGIS验证；尚未部署或在双端完成本批原生验收。

- 排序依然距离优先，不因有码排到更近地址前；大型社区按真实边界与地址适用范围去重。
- 不增加距离档位按钮；扩到 500m/1km 时，在弱层级分区行写实际范围，不无声把远处结果称为楼下。
- 定位无效、底图分类未加载或供应商失败，不算成功无结果，不无限扩围/重试。
- Mapbox 建筑可视查询只覆盖已加载的地图内容；上方地图缩小后尤其不能把未加载范围当成“没有公寓”。已有业务库和合法可用的供应商查询分别记录覆盖，缺覆盖时允许“不完整”，不宣称全范围查遍。
- 复用现有定位位移阈值、请求合并与取消逻辑；扩围作用于一次发现周期，不由每次滚动或每个 GPS 回调触发。记录请求数量和延迟，先用公开地址和合成边界验证。
- `nearby-policy.ts` 与空间查询已同步允许三档；新版workspace显式请求扩围，旧调用保持200m。一次周期最多3次catalog、7次Tilequery、4次临时逆地理和1次元数据，供应商共享8秒中止预算。
- Tilequery有九瓦片地理边界和50条上限；用实时元数据判断覆盖，不因HTTP成功就假定整个圆已遍历。不完整时停止继续扩围并显示实际档位及状态，因此不保证每个地点都能查完整1km。
- 找活/找人不使用这套公寓半径。保留区域、日期和声明时段规则；“按距离”只能用于确有同源地理依据的结果。

### 7.2 同时可见多栋公寓：本轮关键数据改造

现有 `HomeApartments` 维护单份 `records` 和请求序号，切选中会清空并读取当前公寓。直接拿它渲染纵向列表，会让其他可见卡缺内容，或错误复用当前码。

目标将三个概念分离：

1. **发现集合**：地址、稳定公寓 ID、分类依据、距离及合法关联，不包含未经授权的门禁正文。
2. **可见卡集合**：需要阅读内容的公寓 ID。每张卡以账号＋权限世代＋公寓 ID 管理独立状态与请求。
3. **地图焦点对象**：只负责高亮/必要镜头变化，不决定其他可见卡能否读取。

实现第一版优先复用现有鉴权读取接口，不先建“批量下载附近全部密码”接口。停留可见约 250ms 再请求；普通手机首屏目标最多 3 张数据卡，并发不超过 2，其余按可见性排队。若大屏显示更多卡，继续按需队列加载，不用第一个公寓的内容填充其他行。

地图上下文仅为当前焦点读取；收藏/私人状态按详情需要读取，避免每张卡重复调用当前选中链路的全部接口。响应必须校验对应账号、权限、对象与请求版本，迟到响应不能污染另一行。

页面不可见、退出/换号、资格撤销、已知停显时清除相关正文；离开可见区及时释放非必要正文。短时内存复用要有明确时效，不能以缓存跳过权限复核。不得把门禁内容放入导航参数、日志、持久化列表位置或通用分析事件。

贡献/纠正/反馈成功只失效并重读对应公寓；原公寓即使不在最近范围，也按“刚操作的地址”回显，不能返回后误展示另一栋的码。它不永久污染附近列表排序。

### 7.3 契约、数据库与服务边界

- 首批布局不要求数据库迁移；现有鉴权、KMS、幂等和版本保护保持。
- 若扩围或可见计数需要新字段，先更新 OpenAPI 源/生成器及客户端；明确距离依据、范围、查询覆盖和当前结果数。不只修改生成类型。
- 列表数不是全城库存数，区域点计数不是全区在线人数，门禁数量只计有权可见来源。没有统计接口时不显示虚假合计。
- Mapbox 临时候选仅用于会话；未收录地址贡献继续先核对和完成合法持久化关联，不能把临时搜索结果批量落库。
- 团队成员/私有码会引入新的授权模型，明确不混进本轮 UI 迁移。当前“本人 DSP 团队资料”仍是发布身份，不等于成员权限。
- 不新建云资源、不改线上资格、不接受新的协议；若后续确需部署，按具体变更与既有授权范围执行。

## M6-02 现行补充：消息与邀请

- 首页消息保持统一入口。对话、通知采用等宽分段切换，数值角标与点状未读统一组件；司机圈的回复计数只作为通知子集，不能与通知总数再相加。

- 邀请沿用正式品牌原件、三条核心价值和原有分享/保存/复制入口，不新增奖励、人数或成员功能。普通构建仍关闭正式分发；本机预览取消分享不显示“邀请成功”，接收页不授予查码资格。

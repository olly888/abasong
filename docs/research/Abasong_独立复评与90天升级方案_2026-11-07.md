## 2. 独立复评与升级重点

1. **先解决「能安全查」，再提高「能查到」。** 当前 `FORCE RLS` 隔离数据库服务角色，逐账号、逐对象访问仍依赖 API 资格和对象校验。内部停显命令已有 MFA、版本和审计，范围是单条贡献来源。升级应复用它的权限和审计语义，增加物业投诉受理、按楼栋或明确门别暂停共享、处理期间阻止同范围重复发布、确认后恢复，以及读取审计的受控查询。真实资料入库前应能回答授权方、共享对象、适用门别、有效期和撤销方式。用合成数据演练越权、同一码多来源、在途请求、下架后重新提交和复启，审核日志只记录必要标识与结果。法律及承运商许可由试点负责人安排复核。[数据库权限](../../database/migrations/0001_v12_initial.sql#L282) · [现有停显命令](../../apps/api/src/operations/stop-contribution.ts#L7) · [查码服务](../../apps/api/src/apartments/apartments.service.ts#L808)。
2. **把地图供应商许可变成可核查的数据来源。** 代码已有 Search Box 临时使用、永久地理编码开关和永久地址写入来源。逐路径核查搜索结果、地图附近结果、地址匹配、业务库、导出和日志，记录各自的数据来源、用途和保留方式。保留现有许可校验，使用有明确许可的来源填充试点。Mapbox 说明 Search Box 结果用于临时用途，临时地理编码结果不可缓存，永久地理编码另有条件。建议在选片区后测覆盖和调用量，用实测决定优化点。[Search Box 官方限制](https://docs.mapbox.com/api/search/search-box/#search-box-api-restrictions-and-limits) · [Geocoding 官方存储说明](https://docs.mapbox.com/api/search/geocoding/#storing-geocoding-results) · [永久地址来源](../../apps/api/src/apartments/apartments.service.ts#L1344)。
3. **用实际结果区分「查码」、「有用」和「进门」。** API 返回记录只能证明读取成功，用户点「有用」代表反馈，经许可实际使用才计进门成功。附件建议给贡献者发送首次使用回执，宜等能准确识别反馈归因后再考虑；若只收到有用反馈，文案只反映反馈。截图识别先比较配对错误与核对时间，低置信可突出显示，地址、门别与共享范围仍要让用户可见且确认。现有 iOS Vision、Android ML Kit 和过期草稿清理可复用，试验重点是脱敏真值、两端差异和误共享风险。[原生 OCR 接口](../../apps/mobile/src/imports/recognize.ts) · [过期草稿清理](../../database/migrations/0004_import_batches.sql#L33)。
4. **协作先验证一来一回。** 对两个现有场景分别记录正式发布、首次有效报名、首次双向联系、实际到场或完成交接、最终关闭。现有服务有需求版本快照和报名、消息事件，先用这些生成时间线，避免把草稿创建时间当成发布时间，把关闭当成实际填满。已有短轮询和推送 worker，先验报名与新消息两种通知。设备实收和点击到正确对象为通过，供应商回执只记传输状态。验收覆盖锁屏文案、账号切换、过期绑定和退出后停止推送。承运商临时账号以各 DSP 和承运商实际规则确认，试点记录只记交接是否顺畅。[发布与重开](../../apps/api/src/requests/requests.service.ts#L681) · [推送分发器](../../apps/worker/src/push-dispatcher.ts#L23)。
5. **把健康检查扩展到能定位试点失败的程度。** 已有脱敏请求日志和 CPU、内存、健康目标、错误告警。补最小业务事件，区分未找到地址、正确地址无资料、权限拒绝、查询失败和错址绑定；为 KMS 错误、推送积压、异常 403／429 和 Mapbox 调用失败设运行检查。先用现有服务汇总，事件保留时限由试点方案明确。分析事件只使用必要的结果、版本、粗粒度片区和匿名试次标识。业务联系人、原始门禁码、截图、消息正文和精确定位留在各自授权的数据流程里。S3 上线有过短暂 503，下一次变更安排在测试窗口外，用就绪检查和回退演练验收。[脱敏 HTTP 日志](../../apps/api/src/common/cloud-http.ts#L10) · [云端图片变更记录](../technical/B6-03_私有图片S3变更方案.md#执行记录)。
6. **把公开分发视为独立交付。** 冻结候选已有短信登录，仓库可见账号删除规格和数据库任务表，尚未找到完整的移动端发起删除及后台完成链路的验收证据；登录页隐私与条款地址依赖配置，正式链接也需实测。公开分发前补齐 App 内账号删除、最近重新认证、数据留存规则与回执；司机圈如保留则验证内容过滤、举报响应、屏蔽与支持联系入口。同步核对正式图标、深色资产及邀请落地页。[账号删除规格](../product/Abasong_V12.1_页面功能信息与交互规格.md#L894) · [Apple 账号删除要求](https://developer.apple.com/go/?id=ar-ad-support) · [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)。

真实工作的对照组建议用司机或 DSP 当时实际使用的办法，比如物业前台、已有承运商指引或微信群，记录两种流程的时间与结果。Beans Access 和 Amazon Key 可作为物业授权访问模式的参考，试点自身的替代效果由观察数据判断。[Beans Access](https://www.beans.ai/access) · [Amazon Key for Business](https://aws.amazon.com/blogs/iot/building-a-virtual-fob-with-amazon-key-for-business-and-aws-iot/)。

## 3. 试点顺序与责任

| 窗口 | 负责人建议 | 交付与验收 |
| --- | --- | --- |
| 第 1–7 天 | 产品负责人安排观察，工程负责人整理候选 | 用现有 B6-01 合成原型约 1 名司机和 1 名 DSP，选定 1 个现有司机常跑片区并定好分母。保存第一份观察，按问题严重度归档。工程提交 PR 依赖、候选差异与逐批 CI 计划，并用合成数据走一次投诉停显预演。 |
| 第 8–30 天 | 产品、运营、工程与授权复核人 | 做满 5 名司机和 2 名 DSP 的主持任务。司机每项核心任务至少 4/5 无提示完成，DSP 关键任务各 2/2 无关键误解。同步准备约 10 张有授权、已脱敏且核对真值的截图，建议覆盖至少两种承运商版式。授权资料入库前演练投诉、暂停、访问撤销及回执；覆盖与耗时先建立基线。 |
| 第 31–60 天 | 试点运营和工程 | 条件齐备后记录同一片区的正常配送现场试次，建议先覆盖 10–20 个常跑公寓样本。对至少一台 Android 实体机补验定位、相册回程、上传和读屏。推送在授权测试机上完成实收与回流后，再测两种缺口的自然响应；分别记录发车前、交接前的有效窗口。对首轮观测到的无障碍或单手阻塞做定向复测。 |
| 第 61–90 天 | 产品负责人 | 复核第 2 周、第 4 周有配送机会的司机是否回访，结合有用反馈和实际进门样本判断。完成至少两次真实缺口的 DSP 可参加付费意向访谈，记录愿付范围、计费周期、服务和原因，分别标注口头意向、书面意向、付款和续用。只有首片区证据与治理验收充分后再决定是否复制。 |

### 记录口径

| 要回答的问题 | 建议口径 |
| --- | --- |
| 到门口能否找到目标 | 附近匹配正确目标次数／符合预检且尝试的次数；搜索补救另记。记录中位时间，定位故障、网络失败、未获资格和错址各自单列。 |
| 正确地址有没有可用资料 | 成功完成权限及读取检查的正确地址中有资料的次数／可比试次。实际进门成功仅计经许可使用的试次，注明门别和覆盖，不以读码或反馈替代。 |
| OCR 是否节省核对时间 | 分平台、版式和清晰度记录地址、字符、地址与值配对的正确数／可评分数、误提取、修改次数和核对耗时；错配或误共享阻断扩量。 |
| DSP 是否得到及时支援 | 分场景记录首次有效报名、首次双向联系中位时间，实际到场或完成交接次数／真实发布数。用各需求实际的发车或交接时限判断；单列无人响应、过期和通过其他渠道解决。 |
| 回访是否来自实际任务 | 分第 2 周、第 4 周，记录仍有对应配送机会的司机中真实复用人数／有机会人数；同时报告原始队列、机会数和缺失值。小样本使用人数与次数，不外推市场比例。 |

**复盘条件。** 出现错楼或错门别泄露、未核对即共享、授权投诉时，暂停对应资料或流程并处理。两轮修复后核心任务仍低于门槛，先缩小或调整任务；响应持续错过实际窗口，先排查通知、供给和现有渠道，再决定是否收缩该协作场景。若进度主要卡在招募，优先调整招募方式和片区。

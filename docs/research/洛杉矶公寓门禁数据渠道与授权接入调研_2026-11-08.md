# 洛杉矶公寓门禁数据渠道与授权接入调研

日期：2026-11-08。范围：第三方服务、物业系统、司机/DSP 自有工具及公开开发者文档。本文是研究结果与后续建议，不是供应商采购、数据导入或新功能批准。

## 1. 结论

确实存在管理和分发公寓门禁信息的产品，且已找到明确包含可选门禁码字段的商业 API：Beans.ai。司机个人/团队积累并导出资料的工具也存在，例如 OpenSesame。因此 Abasong 的冷启动不必只依赖司机逐条新建贡献。

但本次未确认一个具有明确开放许可、覆盖洛杉矶所有公寓、且可直接导入 Abasong 的有效门禁码库。需区分：地址与地图覆盖、入口资料覆盖、存在门禁凭据、允许本产品展示这些凭据。供应商有 API 或在洛杉矶有客户，均不能替代后两项证据。

近期优先评估两条路径：明确获准用于 Abasong 的 DSP/司机自有资料导入，以及 Beans.ai 商业合作适配。物业直接授权可作为小范围补充。暂不因研究扩展成门禁硬件控制、订单派发或物业管理平台。

## 2. 已核实渠道

| 渠道 | 已核实能力 | 洛杉矶证据及缺口 | 对 Abasong 的建议 |
|---|---|---|---|
| Beans.ai Enterprise API | 路点数据含可选 `code` 字段；另有地址分类、入口及路线资料 | 尚未取得 LA/West Covina/Pasadena 的实际可用门禁覆盖清单 | 优先商务与技术核对，不能按地图覆盖数估算密码覆盖 |
| Beans Access | 物业录入资料，面向经验证伙伴、订单、司机及配送窗口开放 | 官方列出 SpeedX 等伙伴，但未独立验证合作范围或 LA 覆盖 | 确认跨承运商辅助 App 是否符合接入条件 |
| OpenSesame | 司机保存地图点、密码、照片和备注；个人/团队资料可导出和分享 | 未确认有预装 LA 数据库，也未确认提供数据销售 API | 作为授权团队资料迁移来源及产品参考 |
| ButterflyMX | 物业/住户授权的 API、配送通行凭据 | 有洛杉矶 Brentwood 的物业案例；不是全市数据授权 | 有合作物业时再评估单物业集成 |
| Nimbio | 社区管理者授权的开发者接口，数字钥匙及访客访问能力 | 本次未确认 LA 可授权物业清单 | 后续物业合作候选，不能作为公共密码库 |
| GateXS | 面向配送司机的门禁信息产品构想 | 官方仍标记开发中；无已验证覆盖、数据出口或 API | 竞品观察，不计入可用数据源 |

### 2.1 Beans.ai：最值得进一步核对的商业渠道

Enterprise API v2 将 `code` 定义为可选路点字段，仅在该点需要且有资料时提供；它也公开了入口资料与地址分类结构。由此能确认存在相关接口设计，不能确认任意企业账户均有权读取该字段。[官方 API 文档](https://www.beans.ai/enterprise-api-v2)

Beans Access 的官方描述是：物业提交资料，供应商核验合作伙伴、真实订单、被派出的司机和配送窗口后分发访问资料。官方伙伴展示包含 SpeedX；这只是供应商声明，不代表 Abasong 或所有 SpeedX 司机已经有访问权。[Beans Access](https://www.beans.ai/access)

**适配风险：**Abasong 当前不管理承运商订单与派单，自己的登录/内测资格未必满足供应商的订单校验要求。应先确认是否允许辅助工具接入、是否有物业直接授权路径。不要为了接入而增加包裹扫码/POD或自动派单。

另外，“访问到期”需要问清是页面读取权限失效、临时凭据失效，还是实体键盘码轮换，不能将宣传用语直接写成我们的安全承诺。

### 2.2 OpenSesame：证实了司机团队已有资料的迁移路径

官方说明支持将门禁信息保存到地图，导出资料库，并通过云盘链接与配送团队共享；官网也明确表示不将个人门禁码聚合成企业数据池。App Store 描述确认了本地资料和导出能力。[产品官网](https://open-sesame.app/)、[App Store 产品说明](https://apps.apple.com/us/app/opensesame-gate-code-manager/id6758457219)

这适合作为“有权提供资料的团队主动迁移”的候选来源。尚未实际下载导出文件，文件格式、许可与版本兼容性待核对，不能声称已实现导入。产品存在也不等于开发者拥有可出售的全体用户资料。

用户此前提到的 TDS 自建工具同属团队资料线索；该任务已暂停，本次没有重新登录、导出或复制其中内容。获得浏览密码不自动代表同意将团队资料发布给 Abasong 全体司机。

### 2.3 物业与门禁服务：真实存在，但授权按物业和访问范围处理

ButterflyMX 的官方 API FAQ 明确区分 Building Admin 和 Tenant 授权，单栋物业集成需要物业批准。其洛杉矶 Brentwood 的 Chenault Villas 案例证明本地有实际部署，不证明开放密码库或区域批量授权。[API FAQ](https://apidocs.butterflymx.com/docs/faq)、[洛杉矶物业案例](https://butterflymx.com/resources/case-studies/chenault-villas/)

其 Delivery Pass 还证明一个关键区别：配送凭据可以是一次性的，使用一次或到期即失效。这类凭据不能按长期共享门禁码导入并反复推荐。[官方 Delivery Pass 说明](https://help.butterflymx.com/hc/en-us/articles/36700195156116-How-to-Create-and-Use-Delivery-Pass)

Nimbio 官方开发者说明也将 API 权限放在业主、物业管理者或集成商一侧，社区级授权由管理员管理。它是受控访问集成能力，不是仅凭地址就能查询任意社区密码的接口。[Nimbio 开发者说明](https://nimbio.com/knowledge-base/developer-api-getting-started/)

### 2.4 个人开发者、社交分享与公开地图

GateXS 官方仍将产品标为开发中，界面是概念预览；不能据此认定已有数据或有效密码覆盖。[GateXS 官网](https://www.gatexs.com/)

本次中英文公开检索没有确认可商用的洛杉矶公寓门禁开放数据集。没有进入私人微信群、登录受限社交账号或下载地址—有效门禁码清单，因此这不是对“全网不存在”的结论。个人帖子即便公开，也仍缺少用途范围、更新有效性及数据再分发证据；可用于寻找愿意合作的贡献者，不直接成为基础库。

Mapbox Search Box 解决地址、地点、POI 搜索；已核对的官方能力说明没有提供公寓共享门禁码数据服务。其搜索结果的持久化还有单独条件，不能因为地址可查就把供应商结果和第三方门禁资料一起整批存库。[Mapbox Search Box 文档](https://docs.mapbox.com/api/search/search-box/)

## 3. 针对洛杉矶的核对方法

下一次供应商覆盖核对优先限定 West Covina、Pasadena、City of Industry 及用户熟悉线路，使用公开物业名称/地址，不提交用户住址、司机实时位置、包裹或收件人资料。

既有 Del Mar Apartments 与 Woodside 可作为公开样本线索。样本用途是问清覆盖与适配，不是先人工建立全城公寓库。当前没有向供应商发送样本或询价。

覆盖结果必须分别记录：

1. **地址识别率：**样本中能识别出目标物业的比例。
2. **入口资料率：**能关联明确入口/通行说明的比例。
3. **授权可展示率：**在 Abasong 的实际使用模式和合同范围内可展示的比例。
4. **现场可用率：**司机在获准配送场景下实际完成进入的比例；目前未测。

不能将公寓单元数当作社区数，也不能把“有门禁设备”“有地图”或“API 返回一个字段”计为有效查码成功。大型社区应单列地址与门别范围，避免同主地址不同入口相互覆盖。

## 4. 供应商尽调问题清单

| 问题 | 需要的具体答案 |
|---|---|
| 本地覆盖 | 上述地区多少物业有地址、入口资料、可授权访问凭据；按物业/入口分别计数 |
| 产品适配 | 无自有承运商订单、服务多家公司的司机工具能否接入；需要哪些可核验授权 |
| 使用许可 | 是否允许原样展示、缓存、永久保存、用户纠正、与司机来源并列及向注册司机提供 |
| 凭据类型 | 长期共享资料、一次性码、限时码和访问链接如何区分；是否存在实体轮换 |
| 更新与停显 | 更新时间、撤销通知、物业暂停、错误绑定处理方式及接口故障语义 |
| 计费 | 是否单独计入口/访问请求，最低消费、试点价、测试环境、服务限制和终止后的数据处理 |

未取得正式报价，不估算采购成本；未取得授权，不把可选字段存在当作数据交付承诺。

## 5. 对 Abasong 的可执行建议

### 第一优先：获授权团队资料，加快冷启动

用户有约 10 个 DSP 联系渠道。可先由其中愿意合作的团队确认其可用于 Abasong 的资料范围，再通过现有截图核对或后续文件导入接入。不能仅因为团队持有承运商 App 截图，就假定承运商或物业允许广泛转发。

只需要让司机核对地址、门别、密码及共享意图，来源、导入时间等尽量自动记录。维持现有正常贡献直接共享规则，不新增逐条人工审核或团队成员管理。文本/表格仍为 P1，获得真实授权文件格式后再决定是否提前做最小适配。

### 第二优先：核对 Beans 商业适配，再决定试点

先取得不含真实密码的覆盖说明、字段示例、接入条件与报价。只有确认 Abasong 可使用的范围，才进入沙箱适配。数据源是补充，不替代现有 Mapbox 地图和司机贡献。

### 后续：少量物业直接合作

如果具体物业愿意提供送件说明或访问能力，再比较静态共享资料与物业授权链接。暂不开发一键开门、门禁设备控制或管理平台。一次性/限时凭据不进入公开共享库；如未来接入，应有单独的受控展示规则。

### 数据设计保留最小边界

现有公寓关联、独立来源、加密、资格和停显机制继续保留。即使使用第三方资料，Abasong 仍需保存业务关联、来源许可范围、适用入口、有效期和司机反馈，不能用供应商的一条记录覆盖其他司机来源。

若后续批准供应商接入，按来源适配而不是按供应商重做页面：有授权资料显示对应内容；无授权/无资料/请求失败分别表达，不把失败伪装成暂无密码。三门别仍为行人门、车库门、大堂门，不增加司机填写负担。

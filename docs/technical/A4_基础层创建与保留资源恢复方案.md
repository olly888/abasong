## 失败、定位与修复

初次CloudFormation创建失败：DataKey provider只返回null/InternalFailure，其他资源标记取消；实际两仓库已创建，密钥/日志组当时不存在。有界CloudTrail查询未获得对应CreateKey事件，没有将这个不明确错误直接断言为唯一权限原因。

确认并修复三处工程问题：

1. KMS CloudFormation模板混用了KMS API的TagKey/TagValue，实际模板应为Key/Value。后续IMPORT_FAILED提供了明确字段校验错误；官方describe-type Schema验证也重现旧结构失败。源码现已修正，6项资源属性通过4种实际AWS provider Schema的Draft7校验。
2. 创建脚本使用on-failure DO_NOTHING，实际AWS明确拒绝该CREATE_FAILED原地update，要求创建时disable-rollback。一次恢复前置断言先行拒绝，之后AWS校验拒绝更新，未启动更新；脚本改为--disable-rollback，不增加自动删除或重建逻辑。
3. 初始TagResource权限依赖尚不存在的ResourceTag。AWS要求带标签创建密钥时具备IAM TagResource权限；补严格创建标签权限，5个实际IAM模拟覆盖正常/已有其他项目/缺标签/错区域/额外标签，所有数据访问、禁用和删除仍explicitDeny。Access Analyzer findings0。[CreateKey官方权限说明](https://docs.aws.amazon.com/kms/latest/APIReference/API_CreateKey.html)。

同一受限角色直接完成唯一密钥/别名/日志组，已有仓库仅补齐生命周期，没有重复创建资源。原创建选项与标签字段均属工程缺陷，已修复；模板格式validate-template不能替代provider属性校验。

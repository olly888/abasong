[完整策略生成源](../../scripts/cloud/runtime-identity.ts)、[固定目标初始化执行器](../../scripts/cloud/bootstrap-runtime-identity.ts)。真实账号和告警邮箱只在本机忽略目录的0600配置/策略中替换，不提交到公开仓库。

新部署角色不能直接读取Secrets正文、调用业务KMS、修改IAM、创建EC2虚拟机/NAT/RDS或升级账户计划；PassRole只允许四个已批准的ECS运行角色，且目标服务必须为ECS任务，不允许传给CloudFormation。已有foundation角色权限保持。

**这是持续的项目部署权限。** 持有该角色可发布本项目镜像和更新服务，故能改变最终运行的代码；拒绝直接读取秘密不等于没有通过应用运行间接接触数据的能力。需要由本人MFA会话使用，并保留代码审查、固定digest与CloudTrail审计。IAM角色和两份策略不会随着一次会话到期自动删除，结束后可受控撤销。

EC2网络管理使用Project=Abasong、Environment=pilot-dev标签边界；ECS/ALB/ECR/告警按固定名称/ARN范围。模板进一步限制单API/worker和计算规格，IAM不构成费用硬上限；预算提醒仍有延迟。

## IAM 初始化与实际资源执行分开

1. 当前隔离的root bootstrap短期会话仅用于这份清单的IAM初始化、四个已批准运行角色及必要服务关联角色；不创建ECS、网络、ALB或其他计费运行资源，不变更root/user MFA或创建长期key。
2. 从原identity蓝图拆出五秘密stack，使用新MFA部署角色创建。四个服务角色保留原逐项权限，在独立IAM-only初始化模板中使用实际五秘密ARN；不把一般IAM修改权交给日常部署角色。
3. 日常运行层的CFN、秘密配置、镜像发布、证书/预算及ECS/网络操作使用新项目角色。IAM-only及foundation stack不在该角色的CFN管理范围内。
4. 不覆盖已有不匹配的策略/角色；如果发现额外managed/inline policy，执行器停止，不自动删除未知权限。新增operator授权用单独inline策略，不重写旧策略。
5. 两个服务关联角色当前只读检查不存在，后续仅创建这两个AWS标准服务名；它们是AWS服务的账号级基础能力，并非可以限制为单一应用的普通task role。已有角色不删除/重建。

这项IAM初始化没有独立IAM使用费，不改变已批准的约62–75美元/月运行规模；按量资源仍按前一份方案单独核对。没有Paid升级、Organizations、Root Access Key或CloudFormation管理员service role。

# B5-02 本人 DSP 团队、业务联系方式与发布身份

2026-11-06（洛杉矶）。依据 [V3.2 我的与团队资料补充](../product/Abasong_V3.2_我的与团队资料补充.md)和[原型 U10 / P03 / D01 / D02](../../design/abasong-independent-v1/v12.1-experience/index.html?v=r3-simple&task=me)。本批交付统一账号下的本人团队，不产生发布资格，不增加成员管理或收费。

| 流程 | 现行行为 |
| --- | --- |
| 我的 / 个人资料 | 已有团队或声明 DSP 用途时，“我的”在主要工具后显示“我的团队”；个人资料也能进入同一个团队表单。 |
| 团队资料 | 团队名称、多家合作快递、最多 5 个主要配送区域。联系人取本人的当前显示名；在个人资料保存显示名后，返回团队表单仍保留本次未保存的编辑。业务电话和微信选填，与个人联系方式、短信登录号码分开。 |
| 业务联系方式 | 默认关闭。开启需至少一项有效信息；仅有权读取相关需求或司机详情的登录用户可以主动打开。每次打开和复制重新鉴权，面板打开时每 8 秒复核，未能及时更新的值至多保留 12 秒。离页、进后台和切账号清除面板。公开链接、地图、列表与身份快照不包含联系方式。 |
| 发布身份 | 草稿可选个人或代表本人可用团队；首次补建团队后返回原草稿并选中新团队。复制需求从个人开始。发布核对页固定所选身份，团队发生变化要求重新核对，仓库、线路、数量和报价等保留。 |
| 历史发布 | 需求顶部使用发布时的身份；当前团队资料独立标明。改名、关闭分享、停用均不回写历史；停用后不能继续用该团队发布。已有旧版本需求无快照时使用保留的旧团队名，不补造发布时间。 |

`0020_dsp_team_profiles.sql` 增加本人团队资料版本、启用状态和独立的加密业务联系方式。原有组织历史保留；多个旧归属不自动挑选其一。本人写入使用期望版本与幂等键；密文表启用强制 RLS，普通 API/worker 角色不可读取，敏感服务只在本人或相关详情通过鉴权后处理密文。拒绝伪造认证状态、跨账号编辑、过期会话和双方任一方向屏蔽。发布事务核对团队所有权、状态、版本和发布资格；已发布团队 ID 与快照均受数据库保护。

新增 `GET/PUT /v1/me/organization`、仅元数据的 `GET /v1/me/organization/summary`，以及 `/v1/{requests|drivers}/{id}/team` 与其独立 `/contact` 读取。联系方式正文不进入常规摘要、访问日志和重试回执。部署环境需先执行 0020；缺少迁移时 API 就绪检查失败。

双端最终 Hermes JS 包导出通过。隔离库实际留下两条已发布 TEST 需求、0 条消息；已核对临时数据库与角色均为 0。见[执行证据](B5_02_执行证据.json)。

测试使用原生开发容器和本机隔离 API/PostgreSQL，两账号均为合成身份。真实账号、真机、云端部署、外部付款和小样本测试仍由相应阶段验收。本批无需登录、短信或真机补测。下一批 B5-03：司机圈文字动态、回复与通知。

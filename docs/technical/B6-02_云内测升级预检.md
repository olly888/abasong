## 云升级执行顺序

1. 审阅目标环境、0010–0022 的准确文件与 SHA-256，保留升级前数据库版本与安全权限快照。迁移依次覆盖消息及推送表、配送任务、资料与 DSP 团队、司机圈文字和图片元数据。使用已有 SQL 文件，复核可用的备份或恢复点，以及现有 API 和 worker 的部署回退版本。
2. 以现有 API 和 worker 的运行条件准备 `linux/amd64` 镜像。正式变更前确认冻结的源码提交、不可变 ECR 镜像摘要及当期扫描结果。审阅现有 ECS 服务的变更集，预期范围为 API 和 worker 的任务定义及服务滚动更新，继续使用已有密钥、受限角色和 HTTPS 入口。旧有 bootstrap 配置更新脚本只适用原配置变更。
3. 在已确认的 DevWest 维护窗口顺序应用 0010–0022。每一步核对版本回执。失败时停止后续步骤，记录最后已应用版本和具体失败项。迁移完成后比对原有记录、强制 RLS 和受限登录。确认这些结果后才切换新镜像并检查 API、worker 及业务就绪。若镜像切换异常，先按已核对的兼容性回退任务版本，再评估数据库修复或恢复。恢复数据库须单独审阅数据影响。
4. 用两条本人可控的真实短信登录会话完成验收。由本人在本机页面填写验证码，首次资格仅限两个明确账号和两小时内。使用隔离的合成测试值验证贡献、另一账号读取与反馈、本人纠正，以及私存和导入跨账号隔离。业务通过后由有权操作者按本次操作号撤销资格，实际用新请求确认拒绝，再收尾本次测试数据。
5. 核对实际部署配置、测试记录的 KMS envelope 格式与必要的调用证据。最终验收同时记录双账号 HTTP、KMS 核对、撤销及清理。现有 HTTP 脚本的成功输出覆盖业务往返，撤销和清理由独立步骤核对。

用户已授权在 DevWest 应用 0010–0022，以及更新北加州现有 `pilot-dev` API 与 worker。司机圈私有对象存储、真实推送与邀请分发各按 B6-03 推进。源码的 `pilot-dev` 图片服务需要配置私有对象存储。远程推送默认关闭。

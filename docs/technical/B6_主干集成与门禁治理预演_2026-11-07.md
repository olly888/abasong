## 门禁停显演练

在干净候选 `477e7ec` 运行 `./scripts/dev verify:library-api`。脚本使用已核对的本地 D0 连接，创建一次性 PostGIS 数据库和合成账号。295 项真实 HTTP／数据库检查通过，覆盖管理员 MFA 和资格、预览无写入、单条来源停显、审计、版本竞争、幂等重放、跨账号读取及资格撤销。脚本按既有清理流程退出，本次临时连接配置已删除。Mapbox 和 KMS 上游使用合成替身。[停显命令](A1_管理员停显命令.md) · [停显验收用例](../../scripts/d1/verify-contribution-management.ts#L291)。

现有工具的处置对象是贡献来源。另一个仍有效的来源可以让同一条记录继续展示，现有流程也允许用户再次共享。因此物业提出楼栋或门别暂停时，需要单独的范围级状态。试点前优先按确定的公寓 ID 和服务端规范化门别标识设计，先明确对已有多来源、门别未知和地址变更的处理规则。审核后再决定具体实现及界面文案。

进一步核对了共享写入口。手填、截图导入、私存转共享和纠正新值最终汇合到 `contributeTx`。共享读取通过 `readShared`，本人贡献详情还可单独读取当前共享值。工程首批建议先按已核对的公寓 ID 暂停，在写事务的公共入口与两条共享正文读取路径检查状态。现行 `scope_key` 基于用户填写的门别文字，默认值是「大门」。门别级暂停需要稳定的入口标识与旧标签映射，防止改写标签后重新公开。旧幂等回执、批次里的部分成功及暂停与发布并发须纳入隔离验收。[共享写入入口](../../apps/api/src/apartments/apartments.service.ts#L620) · [共享读取入口](../../apps/api/src/apartments/apartments.service.ts#L755) · [本人贡献详情](../../apps/api/src/apartments/apartments.service.ts#L1026)。

| 范围暂停验收 | 判定 |
| --- | --- |
| 读取 | 指定公寓或门别的共享记录统一停显。其他公寓和门别按原规则读取，地图地址仍可辨认。 |
| 写入 | 手填、截图共享和本人纠正都遵守同一范围状态。并发请求和旧幂等回执均不得造成重新公开。 |

| 演练 | 用合成数据覆盖同码多来源、相邻门别、未知门别、暂停期间重传和解除后的恢复。完成后记录参与角色、预期与实测结果。 |

### 公寓级停显实现与本地验收

迁移 `0023` 保存公寓级暂停及恢复的操作历史。共享服务与管理员命令使用同一公寓事务锁。暂停后，共享正文读取返回空列表和 `sharing_paused`，本人详情只保留贡献历史。新的共享、纠正和反馈返回 `APARTMENT_SHARING_PAUSED`，包含手填原请求重放、按地址共享、私存转共享及截图提交的共享阶段。司机端在重新读取时保留地址，并提示该公寓暂不共享门禁码。

本机通过 `./scripts/dev check` 的 512 项测试，以及 317 项公寓、125 项截图导入、622 项业务 HTTP／数据库检查。覆盖同码两个来源、不同门别、相邻公寓、操作预览、MFA 与权限拒绝、版本竞争、并发发布、旧回执重放、恢复排序与反馈、截图保留私存及恢复后重试。缺少 `0023` 时新版 API 就绪检查拒绝接流量。使用一次性数据库与合成数据，云环境与真机验收仍待后续。[操作手册](A1_管理员停显命令.md#公寓级暂停与恢复)。

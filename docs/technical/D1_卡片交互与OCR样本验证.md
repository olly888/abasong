# D1 卡片交互与 OCR 样本验证

日期：2026-10-30。分支：`codex/d1-card-acceptance`。依据：用户批准的 UI/UX 评审第1–3项与截图样本并行验证；V12.1-import 公寓卡片及 ADD-08、V3 令牌。原认可原型未覆盖修改。

## 本批实现

- 真实首页与开发验收页复用 ApartmentSheet：收起显示地址和首条进入信息，展开后顶部添加、收藏、历史与逐条反馈；长地址换行。反馈不会令全部记录进入读取中。
- 数字键盘、前台登记、数字钥匙、无固定码等分别表达；入口标签和实际适用周几/时段/时区来自记录，贡献时间显式转换为记录时区（缺省洛杉矶），不写死“今天”。
- 点击进入信息可放大并返回；大字页仅持有记录ID，不把正文写入路由。失去读取资格、页面失焦、后台或账号切换时敏感组件卸载。
- 搜索选择和私人库公寓入口回到首页，通过 apartment_id 重新请求元数据及权限，不再维护第二套查码详情。无定位、位置过期、网络/精度失败提供搜索与适用的重试入口。
- 收藏读取本人实际私人库状态，提交版本控制并防重复；取消收藏保留私人记录。新增本人库可选 apartment_id 过滤，严格UUID校验与owner条件；源 OpenAPI 和生成类型同步。无数据库变更和云端迁移。
- 未开放消息/支援以禁用态显示；找活/找人说明暂未开放。40px模式按钮补上下触摸区域。卡片支持手柄点击及垂直手势、逐条反馈状态与排序后的记录锚点恢复。

## 验收方法与证据边界

开发专用 `/design-lab` 使用 TEST 合成地址/进入信息，与实际首页共用呈现组件；只在 `__DEV__` 可见，生产入口重定向首页。场景本身不调用业务接口、不保存、不授予账号资格。全局鉴权框架仍存在。验收工具栏不是产品菜单，不将此测试页或合成数据当作真实授权业务闭环。

现有 iPhone18Pro/iOS27 和 Android17/API37 原生开发构建加载本批 JS；不是网页替代原生。截图本地保存在忽略目录 `.tooling/card-acceptance/`，对照页 http://127.0.0.1:8772/cards.html 。

| 场景 | iOS | Android |
|---|---|---|
| 有密码/多记录 | 观察；有用记录优先，反馈后重新排序及选中态观察 | 观察布局与顺序 |
| 大字查看/返回 | 工具实际点击通过 | 用户亲自操作确认“能放大并返回” |
| 无密码 | 直接添加按钮观察且触发合成添加动作 | 直接添加入口观察 |
| 前台登记 | 独立进入方式观察 | 独立进入方式观察 |
| 无资格 | 共享正文隐藏 | 共享正文隐藏 |
| 读取失败 | 失败显示、点击重试恢复 | 失败/重试入口观察，未自动点击验收 |
| 长地址 | 换行且密码仍可见 | 换行且密码仍可见 |
| 时段限制 | 周几/08–18/洛杉矶时间观察 | 同字段观察 |
| 收藏/反馈失败 | 本地收藏状态切换；失败提示且旧记录保留 | 布局观察，未逐项点击验收 |

Android 镜像点击/焦点不稳定，不能用反复工具尝试替代触摸验收。除了用户确认的大字场景，其余 Android 行为仍需人工补测。真实搜索→首页、真实收藏操作、后台/账号变化、读屏、大字体、真机、拖动及弱网恢复没有在本批全部完成原生端到端验收。反馈锚点有算法测试及iOS排序观察，未声称像素不变（内容不足一屏时受滚动边界限制）。

## 实际执行检查

- `./scripts/dev check`：lint、工作区/脚本类型、10项单元测试、构建通过。新增4项覆盖时间/时区、方法、时段和锚点边界。
- `./scripts/dev verify:library-api`：82项真实HTTP/隔离PostgreSQL通过，含按公寓筛选、跨用户隔离、错误ID、取消收藏后私存保留及版本冲突。
- `./scripts/dev verify:auth-api`：54项通过；`verify:access-ranking`：16项真实PostgreSQL排序场景通过。
- 全量 OpenAPI/SQL 静态校验通过（既有隔离Python依赖）。iOS/Android JS export 通过；没有重复进行 Swift/Gradle 二进制编译。
- 无新增运行时依赖、真实短信、账号提权、生产数据或云端变更。

## OCR 首批实验

可复现脚本：`scripts/ocr/sample-lab.swift` 与 `evaluate-samples.py`。Swift/AppKit生成8张完全合成图，Apple Vision准确识别模式、en-US、关闭语言纠正；随后用明确 Gate/Access/Entry code 标签和地址段落作保守关联。没有第三方上传或真实快递截图。

| 样本 | 结果 |
|---|---|
| 前导零、符号、同图两组地址与码 | 通过 |
| 电话/邮编/站点/房号/WiFi干扰 | 通过；该负样本未误提取 |
| 无地址、有多个候选地址 | 通过；保留待确认/歧义，不强配公寓 |
| 字母大小写 | 失败：识别到码但大小写错误 |
| 小字号 | 失败：未提取候选 |

**8个场景中6个密码集合和配对/状态完全匹配。** 不是实际业务准确率：缺地址场景的通过表示正确标记缺失，不是成功匹配公寓。单机识别54–169ms仅是Mac上识别耗时，不是手机/网络/批量端到端性能。

结论：保留逐项核对地址和密码、字符大小写及符号；缺地址/歧义不能自动公开。此实验不足以选择生产OCR供应商或上线。下一批加入低清/压缩/多栏/中英文/不同设备及获得许可的脱敏真实样本；按字符、配对、拒识、误提取、纠正时间分别评估。当前未实现原生图片选择、OCR服务、上传草稿或批量提交；截图P0仍优先。

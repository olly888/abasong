# D1 原生登录接入记录

日期：2026-10-29；分支：codex/d1-apartment。此批是账号入口与安全会话基础，不代表 D1 公寓业务闭环或真实短信验收完成。

## 实现范围

- 保留首页、司机圈、我的三导航；登录流程位于导航之外，通过“我的”进入。
- 手机号地区选择、号码规范化与校验、验证码输入/重新发送、首次显示名、真实账号状态及本机退出。
- Supabase Auth SDK 验证短信；没有固定验证码、模拟登录用户或客户端授予资格。
- 原生会话使用 Expo SecureStore；读取/写入/删除失败时显示错误，不回退明文。Web 会话只保存在内存中，刷新后不保留。
- 账号 API 使用契约类型与 Bearer，超时10秒，401最多刷新一次且要求刷新前后用户一致；正式构建要求 HTTPS API。
- 登录变化与退出使旧账号请求失效；失败不显示旧资料。回到前台重新查询当前资格。资料提交对同一意图复用幂等键。
- 验证码只存在页面内存，切换号码/失败时清除；完整手机号不显示在验证码页；不记录凭据、手机号或验证码。
- 重发60秒是界面节流，不能替代短信供应商及 Supabase 的限流与防滥用策略。

## 配置

项目 URL 与公开 publishable key 保存在忽略的 apps/mobile/.env.local，文件权限600。服务端 issuer/audience/算法配置在忽略的根 .env。移动端不得放 service_role、secret key、数据库连接串。示例字段见 apps/mobile/.env.example。

当前项目位于 us-east-1，用户已知；未迁移区域。只读取了项目状态、公开 JWKS 和公开 Auth 设置，未应用云端 SQL 或更改 Auth 设置。

## 验证与限制

- 完整 lint、工作区/脚本类型检查、3项单元测试、构建通过；54项真实 HTTP 身份/账号场景复跑通过，使用隔离本地数据库和临时签名密钥。
- Expo customize tsconfig.json 生成忽略的类型路由，再执行 tsc；用于全新检出和 CI，不提交 .expo/types。
- 新增 SecureStore/Crypto 后双平台 Debug 原生编译通过；Android 安装/冷启动与真实 Mapbox 底图渲染通过。
- iOS 未签名构建虽可启动地图，但 Keychain 读取出现 entitlement 错误；不得以 CODE_SIGNING_ALLOWED=NO 的成功编译认定安全存储可用，随后启用标准模拟器本地签名重新构建/安装，冷启动无安全存储读取错误，地图与三导航正常渲染。签名修复仅覆盖启动读取，真实账号写入/恢复仍待验证。
- Mac 锁屏使 CUA 无法操作，登录表单导航、无效输入与返回暂待交互验证。
- 手机 provider 当前未启用。没有发送短信、创建真实账号或使用真实会话验证安全存储；会话保存/恢复、刷新与退出需后续真实账号测试，包括大体积会话及双账号切换。
- 发布后的服务条款/隐私政策 HTTPS 地址尚未配置，页面不提供虚假链接。外部试点前必须补齐正式文件、手机登录供应商、防滥用与费用规则。

后续按实际执行结果更新本记录；不要把 SDK 接线、单元测试或原生编译当成短信端到端验证。

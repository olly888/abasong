# D1 定位候选与原生首页验证

更新：2026-10-30（America/Los_Angeles）。本批对应 T02/T06/T08/T10/T32 的部分范围，D1.1/D1.2 继续推进；不代表整个 D1 验收完成。

## 本批交付

- 实现 `POST /v1/apartments/resolve`（HTTP 200）：真实 JWT/当前账号检查、严格字段白名单、经纬度/精度/时间验证，使用 PostGIS 索引从自有 active 公寓中查询距离候选，最多20条，距离与ID稳定排序。正文不含密码，不存位置或轨迹，响应 no-store。
- 使用既有 `config_versions` 的完整版本配置；没有有效定位配置时返回503并引导地址搜索，不写入猜测的生产阈值。**没有新增表或修改既有迁移。**
- 首页原生地图接入定位按钮、前台单次位置、当前点/候选点、候选确认、收起密码与贡献时间、展开历史与反馈；添加位于历史之前，收藏图标只在展开卡片。没有密码可直接添加。用户选中公寓后不被后到达的定位结果切走。
- 切后台、离开首页、刷新身份/退出时卸载密码与位置状态并中止请求；不同选择用请求代次隔离。首次权限询问由司机点击触发；已授权后进入首页可获取一次位置。没有后台定位/连续轨迹；当前是前台单次定位，持续前台更新尚未接入。
- `vitest.config.mjs` 明确只发现源码测试，修复先构建再运行检查时误扫描 CommonJS 编译测试产物的问题。

## 配置与边界

`config_versions.config.apartment_resolve` 必须包含：`radius_m`（0–1000，正数）、`max_age_seconds`（0–300，正数）、`future_tolerance_seconds`（0–30）、`max_accuracy_m`（0–1000，正数）。这些是服务端允许的上界，不是生产建议。完整版本须保留其他功能所需配置；普通API角色无权写配置。

测试库使用100米候选半径、120秒最大年龄、15秒未来容差、100米最大精度误差，**仅测试配置**。本机长期D0/云端均未因此写入配置或公寓样本。超精度返回unknown，过期/超前返回stale_location。粗略与精确定位都只返回需确认的候选；T23真实LA阈值验收前不返回自动matched，也不凭最近点静默认定楼栋。

服务端仅匹配自有/授权且已审核active公寓，Mapbox用作底图；不将Mapbox建筑或地址搜索结果自动当作公寓资料库。Web地图预览仍为旧底图，不支持本批原生候选标记/相机交互，不用浏览器代替原生验证。

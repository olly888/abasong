# D1截图多图中断与恢复验收

2026-10-31（America/Los_Angeles），分支 `codex/d1-import-interruption`，承接[洛杉矶样本与弱网批次](D1_洛杉矶样本扩充与弱网恢复验收.md)。本批补强多图长任务、空草稿、退出后恢复已保存结果；iPhone真机继续延期。工程实现与自动化验证已完成。用户解锁后已完成下文双端进程恢复、空草稿及Android草稿超时补验；剩余原生项目单独列明，不等同完整D1或真机验收。

## 问题与最终行为

原有识别循环没有停止入口；某一张OCR迟迟不返回时整批等待。恢复草稿失败时，客户端也可能已经替换批次ID，旧页面却仍显示上一批结果。此外，移除最后一条后无法保存，使再次恢复出现已移除内容。

- 识别中显示已处理/总数与“停止识别”；返回操作在识别中也先停止。停止后保留此前完成图片的结果，当前图片迟到结果不发布，后续图片不继续启动。没有完成结果时留在选图页，有结果时进入核对。
- 单图失败不阻塞其他图片；失败图片单独重试。未完成图片可“继续识别剩余截图”，不重跑已完成图片。手动补充后的图片也不再被整批重试覆盖。若已提交部分结果导致旧批次锁定，“继续处理剩余截图”只把尚未识别/失败的图片转到新草稿，旧结果及旧草稿按原规则保留，已完成图片的本地缓存释放；不向旧提交计划追加来源。该UI分支同样待原生补验。
- 原生识别JS等待上限60秒是本地开发保护，不是正式SLA或CPU硬终止。Vision/ML Kit任务可能继续执行，因此占位保持到它真实结束；不能因为取消/超时就同时启动下一份原生识别。任务结束后的迟到结果丢弃。长时间不结束时明确提示稍后重试；应用进程重启才会重建原生运行环境。
- 停止识别不等于保存草稿。识别字段仅在当前会话，用户主动保存后才进入既有本人加密草稿；退出/系统结束只恢复已落库内容和逐项提交结果，不恢复未保存修改或未上传的照片。
- 恢复现在使用独立目标读取元数据/全部候选，全部成功后才替换当前批次与重试映射。恢复失败保留当前批次，避免旧行被错误绑定到新批次。退出后重新建立客户端时仍重校当前账号、目标公寓及共享资格。
- 恢复视图单独整理：移除行不复活；不存在的公寓取消该行预选，其他行可恢复；网络/鉴权失败继续报错；保留密码字符串、门别、私存ID、共享失败结果和锁定意图，不伪造图片URI/尺寸或声明。
- 已有、未锁定草稿可保存“全部移除”；首次无内容依旧不创建空批次。再次恢复空草稿时回到重新选图，用户实际选图后才开始新的客户端批次，旧批次按有限TTL保留。

没有新增API操作、数据库迁移、依赖、原生模块或权限。复用端侧识别、既有批次15接口和本地保护策略；无云变更、真实码、账号资格授予、短信或正式私人数据写入。新增进度与停止控件属于必要任务状态，不添加常驻设计备注。

| 场景 | 观察到的结果 | 状态与边界 |
|---|---|---|
| iOS十图停止/续跑 | 实际选择10图；处理中停止后核对页保留5条，继续时只处理其余5图，最终10个不同TEST值齐全，无已完成项重复 | 此样本通过；不是准确率、内存、耗电或SLA基准 |

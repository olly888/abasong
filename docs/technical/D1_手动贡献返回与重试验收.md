# D1：手动贡献返回与重试验收

日期：2026-11-01。对应B02、H01、U06和ADD-18。目标是补齐当前公寓添加密码后的返回、提交一致性与错误恢复，不扩大到长期招聘、结算或新运营审核。

## 完成交付

- 已收录公寓原来共享成功后直接`back()`，首页失焦后重建可能重新选最近地址；现在与新地址贡献一样，明确携带实际提交公寓ID回首页读取。没有返回栈也不发送GO_BACK。当前保证同一地址，不声明保留此前整个横滑列表及位置。
- 公寓资料加载中锁定表单；失败显示重新读取/选择其他公寓，不默默转为新建地址。对象ID和请求代际检查阻止旧目标覆盖。重试不清掉填写的密码，明确更换地址会撤销来源确认。
- 提交中的密码、门别、地址和选择目标被锁定，提交意图同步占用，快速重复点击不会发起并行写入。失败保留当前内容和同次幂等键；页面关闭/账号更换时随敏感会话销毁，不增加跨次续填。
- 私人保存分为条目创建、密码写入：第二步失败后只编辑密码时，创建条目的键继续复用，密码键随内容改变。避免为同一次部分失败创建另一个私人地址条目。
- 原型增加两项外部场景控制：贡献公寓读取失败、贡献保存失败。正常产品画面仍为原表单和必要错误/恢复动作，无工程提示。页面生成器同步B02两个状态与验收基准。

无新API契约、数据库迁移、依赖、账号资格或云配置。日常D0只通过正常原生界面创建并移除了本轮一条TEST私人记录；没有共享真实密码、发送短信或变更权限。

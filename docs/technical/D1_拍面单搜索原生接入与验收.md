# D1 拍面单搜索原生接入与验收

日期：2026-10-31。范围：[ADD-16](../product/Abasong_V12.1_拍面单查地址补充.md) L2；延续 L1 合成识别实验。下面区分代码、合成界面、真实接口和用户真机反馈；不宣称 D1、Android 真机或多承运商准确率完成。

## 本批实现

- 公寓搜索框相机入口，单张系统拍摄；仍为 S01，不新增导航、导入批次或识别历史。
- 复用本地 Vision/ML Kit，提取楼宇级地址；同页完整显示、可修改，点击“查找此地址”后才进入现有目录/Mapbox联想，用户再次点候选。相机不移动GPS，不推断公寓类型，不改变共享码资格。
- 多地址先选一个、无地址重拍/手输、拒绝权限/设置、识别取消及旧包更新提示。原生模块版本常量保护未重新安装的旧包。
- Android系统相机临时切后台时，遮住敏感页面但保留当前拍摄；注销或确认账号失效卸载会话，迟到结果不能回填。相机单实例、OCR任务串行；取消JS等待后仍等原生释放文件再清理。只删除当前受控缓存照片，不删除相册原件。
- iOS按图片方向识别；Android根据90/270度旋转校正文字坐标。沿用10MB/2400万像素上限，超过时要求重拍，不后台上传。
- 本轮验收发现并修正“未确认照片地址→重拍无结果→再拍并取消”错误解除确认门槛的问题；现在保持核对，不自动发请求。手动输入路径清除未确认的旧照片草稿。
- 原型增加同页拍照、确认、多候选、失败、取消场景。S01规格/JSON/CSV同源更新为39节点/292状态。新增公开地址TEST拍摄页，用户真实面单附件未复制、未上传、未作为仓库样本。

## 剩余边界与下一步

1. Android已实际打开系统相机、拍摄模拟器无文字图并进入确认页；首次选择“仅这一次”后较长停留，确认返回时观察到首页而非识别结果，再次入口重新请求权限。尚不能确定是相机Activity回收、单次权限生命周期或镜像操作影响，因此不把完整Android拍摄返回/识别计为通过，需专门复测。双端弱网/强杀清理及无障碍仍待；合成权限提示不等于系统权限验收。
2. L3至少30张/3布局的授权脱敏面单、方向/光照/反光/折痕/耗时与误识别分布仍待；iPhone拍摄一张TEST地址不能代表生产准确率，旧L1 macOS11/12也不能替代手机端数据。
3. 系统强杀或文件I/O错误时，未返回的相机缓存只能由系统回收兜底，未承诺即时物理删除。Android Activity被系统回收后的pending result清理需独立实现/验收，不提供跨次“继续识别”。
4. 正常库自动识别仍需可信门外范围与现场证据；本批不以地图地址或门牌标签冒充入口范围，不启用未经验证的自动查码。
5. 保留用户已授权的临时iPhone API3002/Metro8082预览，健康200；本批不恢复TEST共享码或账号能力，不改Supabase/生产数据、不公开部署。Android真机仍无设备。

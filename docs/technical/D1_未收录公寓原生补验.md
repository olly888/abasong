## 补验发现与修正

### 搜索候选标识长度

iOS搜索公开地址145 Chestnut St, Pasadena时，Mapbox真实返回HTTP200/五条候选，生产解析器却报搜索不可用。只读结构诊断定位到其中四条`mapbox_id`超过本项目自设500字符上限；没有输出原始ID、token或坐标。原来整组解析失败，连有效第一项也不能显示。

供应商解析、retrieve DTO和OpenAPI源统一改为4096字符边界，规范化不得截断ID。新增共享常量；保持16KiB请求体、512KiB上游响应、请求超时，以及账号/会话内候选集合校验、固定Mapbox主机和路径编码。4096是本项目的有界兼容值，**不是Mapbox承诺的官方最大值**。它没有让任意客户端ID绕过当前账号和建议会话。

[Mapbox官方交互搜索说明](https://docs.mapbox.com/api/search/search-box/#retrieve-a-suggested-feature)要求使用建议返回的`mapbox_id`取得详情，不能按地址或截断后的ID猜测。源生成器与OpenAPI已同步；生成TypeScript类型执行后无类型差异，因为maxLength是契约验证约束。

新增4项回归：混合长短ID候选可解析并按完整ID取得详情；长ID仍仅限建议账号/会话；超4096输入在供应商调用前拒绝；超4096上游响应仍拒绝。混合候选测试修复前实际失败。修复后iOS真实显示五条候选，选择Pasadena CA的第一项，没有把外州同名结果当成目标。

### 提交失败提示的可见性

原生表单滚动到密码/门别后，提交失败提示留在屏幕上方，司机看不到错误。现将既有`FormError`移至固定“确认共享”按钮上方；内容、权限和重试语义不变，不加弹层或新步骤。既有原型的code表单也将反馈放入已有sticky提交区；其他表单保持原行为。

4. 修正后，错误提示在按钮上方直接可见；截图保留修正前后证据。
5. 恢复原先true配置；不离开表单，双击确认共享。等待期间输入/目标及按钮锁定，成功提示“已共享”。

错误场景使用明确的本机保存开关，不宣称本次真的触发了Mapbox401/断网；上游错误类别仍由前批单元/隔离库测试覆盖。成功时正常生产永久解析器和事务执行，没有向服务注入虚假成功结果。

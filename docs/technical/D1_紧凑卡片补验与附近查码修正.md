## 续批：范围边缘、回位与Android异常补验

本次继续开发发现两个边界问题并修正：

- 旧实现只在新的发现响应返回时筛除200米范围边缘。现在每次新鲜精确定位到达时也按各来源原始边界距离与位移上界筛选；不等待慢查询，过期目录与临时地图结果分别失效，迟到地图结果不能延长目录期限。这是保守筛选，暂时撤下边缘候选不表示已确认它实际距离超过200米；新的服务端空间查询再给出当前候选。
- 点击定位解除阅读锁时，旧候选地址列表也一起清除。查询期间只显示简短加载状态，不能重新留下上一地址列表。主动展开/滑卡的阅读锁继续保留，定位按钮才恢复自动推荐。临时地图候选的稳定选中键也单独保存，定位刷新不会不断重置同一张核对卡。

两项新增定向测试覆盖边缘撤卡和来源独立过期/粗略位置；最终完整check为33文件181测试、lint、工作区类型与构建通过。第一次受限执行的两个HTTP监听测试遇到本机端口EPERM；在既有本地测试授权下重跑通过，不是代码测试失败。此批没有修改API契约、服务端、数据库迁移、资格或依赖，因此没有重复数据库/导入套件，前批HTTP224等保留其原范围。JS导出与静态检查在本批收尾单列记录。

## 本批修正

1. 原附近查询比较器要求经纬度完全相同。慢查询期间持续收到亚米级漂移，响应会一直被丢弃。先以回归复现失败，再允许20秒内、精确且误差不超过100米的观测在15米小范围内兼容。这个15米只处理慢响应/漂移，不确认到达，不增加停稳门槛。明显移动、旧/未来观测、粗略权限继续丢弃。
2. 位置变化时按原候选边界距离加位移的上界保守筛选200米范围，不用大型社区远处质心替代边界。过期临时结果及离开后的旧结果不能恢复卡片。
3. 新收录目录与会话内旧地图候选可能重复同一地址。目录优先于临时候选，地址标准化去重；不同目录ID不因为文字相同就合并密码范围。
4. Mapbox某个建筑缺少type时，旧解析会使整批失败。改为允许缺失/空分类，只保留明确apartments，house/residential仍不晋升为公寓。
5. 收起后重建横向列表，程序scrollTo的momentum事件可能重新选卡、额外查码。新增手势与程序对齐区分；iOS实测102展开/收起前后查码总数保持2。
6. 用户在Android复测发现滑到102/104只剩地址预览。修正松手后尚在吸附时过早使用release偏移的问题：后续scroll更新延后空闲结算，并使用最终偏移。另兼容没有drag-begin的触控板/鼠标横滚；程序对齐先确认目标偏移，不把迟到momentum当用户切卡。用户随后确认102密码、104无密码及展开收起均正常。
7. 当前会话内有效的地图候选继续使用，不固定每30秒重复查询。到期/范围变化后重新发现；没有持久保存临时供应商结果。合成建筑门牌修正为对应100/102/104，避免TEST数据自身串号。

保持192点紧凑等高、单行门牌街道、原样密码和时间/用户名；未增加司机端工程菜单。开发测试页的查码计数只在dev-only合成页面出现，不进入正常产品页面。

## Mapbox外部依赖与纠正

本批只读检查现有控制台，公开token与本机一致；样式接口独立复核HTTP401。账号是受限试用，永久编码配额0。官方规则为试用任一产品达限后暂停全部API，结合两次先前样本请求判断当前限制原因。此前“两次200即支持永久编码”的结论撤回，本机永久编码配置已关闭；没有升级账户、付款、接受协议或创建新token。

因此不能把缓存底图或合成识别当成当前真实Mapbox可用、覆盖准确或双端现场通过。标准账号与成本见[资费与控制](Mapbox_开发期资费与用量控制.md)，由用户本人决定添加付款方式。当前卡片测试可以独立推进，但真实地图、实时地址联想及Mapbox候选复核仍待服务恢复。

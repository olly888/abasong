# D1 · 身份与账号接口

日期：2026-10-29（America/Los_Angeles）。本轮完成账号基础接口，D1整体尚未完成。

## 已实现

- `POST /v1/me/bootstrap`：已验证身份建立本人账号和最小资料，严格校验display_name及Idempotency-Key；不接收客户端actor、管理员、核验状态等额外字段。
- `GET /v1/me`：返回本人资料和数据库中当前有效能力，组合自报与已核验经验。
- JWT按配置验证非对称签名、issuer、audience、算法、有效期/nbf、iat、UUID sub及authenticated角色；拒绝匿名会话、重复认证头及客户端自行声明的能力。
- 每次请求检查本地账号状态及旧JWT失效时间；bootstrap不能重新激活封禁、删除中的账号。旧JWT的iat校验不替代Auth供应商的全局登出/刷新令牌撤销，也不用于敏感操作的“最近重新认证”判断。
- bootstrap事务对同一账号串行化，HMAC请求摘要及当前对象引用支持重试；同key异内容409，并发同key仅一次审计。重放时仍检查当前状态，不缓存整份资料正文。
- 统一`X-Request-ID`及`{code,message,request_id}`错误，无SQL、JWT、连接详情或调用栈；v1响应no-store。JSON请求体限制16KiB。
- 已核验经验只来自服务端核验记录；自报资料中的source不能伪造verified。

当前没有密码读取或其他公寓业务HTTP接口。此处的身份守卫不能替代以后公寓范围、适用时段和具体对象授权。

## 环境变量

后端`AUTH_ISSUER`为项目URL加`/auth/v1`，`AUTH_AUDIENCE=authenticated`，当前项目`AUTH_JWT_ALGORITHM=ES256`。JWKS地址由issuer派生，不接受请求方指定公钥地址。

`env:init`生成/补齐本机幂等HMAC密钥，保留已有非空密钥。86400秒为本机开发保留值；生产有效期须单独冻结。客户端只保存项目URL和publishable key；后端JWT验证不需要service-role、数据库密码或JWT secret。

共享契约包声明先构建，再进行依赖包类型检查，使API可依赖真正的包声明，避免把契约源码编译进API输出目录。

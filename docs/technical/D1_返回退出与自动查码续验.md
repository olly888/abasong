# D1 返回退出与自动查码续验

2026-10-31；分支 `codex/d1-exit-arrival-verification`，基于 `3d6844e`。依据 ADD-10、ADD-11、ADD-12 及用户本次顺序：先返回/异常退出，再完善首页自动识别和查码。此记录补充前批证据，不代表完整 D1 或真机验收。

## 本批修正

- 自动公寓卡片读取失败后，“重新读取”保留原来的自动/手动阅读状态。此前重试复用了手动选卡，导致自动卡片被锁住，离开后不消失。重试也不强制移动镜头或折叠已经展开的卡片。
- 自动卡片的保留同时检查当前有效匹配、可信候选、观测新鲜度和匹配配置版本；失效时清除旧卡片、轮廓及密码，并使旧资料请求失效。主动展开的阅读锁定仍保留，点击定位才恢复自动选择。
- A 公寓切换到 B 公寓时，清除 A 不再清掉 B 首次观测的停留计时；B 仍须通过稳定重复匹配。
- 开发专用 arrival-lab 新增“重试恢复”场景，只第一次读取失败，随后返回 TEST 资料。正常路由不使用该数据适配器，Release 仍拒绝该验收路由。

没有增加司机按钮、跨次草稿入口或新产品流程；原型信息结构不变。没有依赖升级、API/数据库结构变更、真实账号授权、云迁移、部署或真实密码写入。

## 返回与异常退出

设备为 iPhone 18 Pro / iOS 27 模拟器和 Android 17 / API 37 模拟器，使用既有 development build + Metro。

| 场景 | iOS | Android |
|---|---|---|
| 已选 1 张 TEST 图片，原生返回时提示离开 | 用户亲自侧滑确认出现提示 | 经 scrcpy 系统 BACK 快捷键触发，实际观察提示 |
| 取消离开，保留已选 1 张 | 用户确认；随后 AX 也观察到 1 张 | 实际观察 |
| 空白截图流程系统返回，不提示 | 本批工具侧滑不能可靠执行；前批页面返回已通过 | 实际观察返回上层添加页 |
| 已选 1 张，强制终止进程后重开截图入口 | simctl terminate 后重开为空 | am force-stop 后重开为空 |
| 新入口无“继续上次添加” | 实际观察 | 实际观察 |

Android 测的是系统 BACK 事件，不是预测式侧滑动画。退出测试不清应用数据、不退出账号、不提交图片。正常确认退出/重新进入的前批证据继续有效；本批没有把选图后强杀等同于“提交期间被杀死”或系统低内存回收。

iOS 首次重开时，测试命令误把业务路由拼进 Metro 开发服务器 URL，开发启动器报加载失败；使用已配置的开发服务器根地址、再打开 `abasong://apartments/import` 后恢复并观察到空白页。属于验收启动命令问题，不是业务 App 崩溃；未修改运行配置。

## 首页双端验证

两端都使用真实操作系统位置流和相同首页组件；公寓匹配/密码响应为明确标注 TEST 的开发适配器。

1. 注入有界合成位置并稳定停留，自动显示 TEST 公寓地址、建筑高亮/门牌及“暂时无法读取密码”。
2. 点击“重新读取”，显示 TEST 密码；卡片保持折叠，没有因为重试锁定自动选择。
3. 注入离开位置，旧公寓卡片、密码和高亮消失，变为低高度“贡献公寓密码”入口。

以上两端均实际观察并保存截图；不能表述为真实门禁或现场 GPS 通过。iOS 模拟器重复设置完全相同坐标未持续产生新事件，因此验收使用小于 1 米的合成变化；真实设备静止时的更新频率、20 秒新鲜度和 8 秒停留阈值仍须现场核验。测试结束停止注入，不把最后测试点当成 Mac 所在位置。

证据在忽略目录 `.tooling/exit-arrival-evidence/`：android-system-back、ios/android-cold-fresh、ios/android-auto-retry、ios/android-after-departure。只含 TEST 或空白页面，不提交真实用户资料。

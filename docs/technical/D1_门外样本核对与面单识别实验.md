# D1 门外样本核对与面单识别实验

2026-10-31。主线仍是首页自动查码；新增拍面单按[ADD-16](../product/Abasong_V12.1_拍面单查地址补充.md)分批实现。

## 公开入口证据的实际范围

已有6个公开地址/4个建筑映射继续有效。本批只读核对既有官方 OSM 下载文件和物业公开页面，没有启用日常自动识别或修改账号权限。

| 样本 | 发现 | 结论 |
|---|---|---|
| Del Mar | 物业站点确认地址并列 gated；已有范围内没有入口节点 | 公寓和建筑可以手动选择，具体门外到达区域仍缺证据 |
| One Santa Fe | 物业站点确认主地址 | 主地址不是可用于识别的入口几何 |
| Woodside Village | 已下载公开图中 node6117285531/v2、node6117285532/v2 标为 barrier=gate，位于既有物业区域；另一个 gate 在区域外 | 前两点仅作待核对候选，不导入 active 入口，不以半径画圆启用 |
| Park La Brea | 物业区域中有多处 gate/lift_gate，另有 foot=no 的节点 | 多门、多栋、步行/车行权限不能合并成整社区一个到达范围；foot=no 不作为步行配送入口依据 |

当前下载中的候选节点尚未完成新一轮线上版本复核；本批直接 API 请求失败不作更新成功。没有声称这些门是配送入口。上述节点仅在文档记录公开对象编号，未复制贡献者资料或司机位置。

OSM 的 [entrance](https://wiki.openstreetmap.org/wiki/Key:entrance) 是入口位置标签，[barrier=gate](https://wiki.openstreetmap.org/wiki/Tag:barrier%3Dgate) 是可开合的门，通行方式另有 access/foot 信息。它们不证明司机可通行、门外停留区域范围或密码适用楼栋。物业来源：[Del Mar](https://www.delmarpasadena.com/)、[One Santa Fe](https://osfla.com/)。

下一步入口核对需要：公寓/门的对应关系、步行或车行、门外可停留范围、与相邻建筑是否重叠、来源和有效期、现场通过/不通过。只记录结果和公开样本编号，不要求保存个人 GPS 轨迹或真实门禁。确认过的范围才能进入已有逐公寓/入口配置；这是地图事实核对，不是重新引入司机贡献审核。

## 公寓自动卡片集成回归

`verify-public-arrival.ts` 新增真实公开几何的负场景：Del Mar 三个庭院中空区域、Woodside 楼间空地。观察位置是从公开几何生成的合成点，精度2米；不是用户真机位置。

在隔离的一次性本地数据库中，启用仅用于测试的建筑范围后，通过真实 resolve HTTP 接口验证四处均不自动匹配；同一结果交给原生共用自动卡片状态逻辑，不能生成自动卡。庭院孔洞在导入后仍为3个，Woodside 空地距离建筑超过精度半径。已有人工核对的入口区测试仍独立，不把整物业区域或所有空地缓冲成入口。

实际执行：`./scripts/dev verify:library-api` **196项 HTTP/数据库检查 + 8项编译后地址匹配/PostGIS检查通过**（此前192）。脚本仅在一次性本地库运行并清理。首次受沙箱 IPC 限制未执行成功，随后在已授权的本地测试权限内完成；没有改动日常D0数据、云业务库或生产。没有原生页面变更，本次不宣称新增双端视觉或现场通过。

## 面单地址识别实验

新增独立 `apps/mobile/src/address-photo/extract.ts`，只产生最小地址候选；没有调用相机或接入生产搜索页面。保留手动确认，排除寄件区、电话/运单号，处理两栏、城市换行、单位房号、多个目的地；不把提取到地址等同公寓。

可重复实验：

```sh
swift -module-cache-path .tooling/swift-module-cache scripts/ocr/label-address-lab.swift
./scripts/dev exec node --import tsx scripts/d1/evaluate-label-address.ts
```

只生成 `scripts/ocr/fixtures/label-address-synthetic.json` 的12张 TEST 面单，图片和OCR中间结果留在忽略目录 `.tooling/label-address-lab/`；没有读取附件照片，没有网络查询。Apple Vision准确模式/en-US/关闭语言纠正，与iOS模块识别选项一致，但运行环境是macOS，不能代替iPhone或Android结果。运行Vision首次受沙箱限制失败，随后离线实验实际成功。

首轮结果：**11/12 完全匹配，2个负样本没有错误地址候选**。样本包括寄收上下排列、两栏、房号、拆行城市、同行To、截取地址、只有寄件人、干扰数字、两个收件地址、小字、模糊和缺城市。

失败是模糊图片的一位邮编识错，Vision仍给高置信度。保留该失败，不用人工修正真值提高分数；说明置信度不能替代司机核对。识别耗时30–209ms仅为这台Mac的OCR阶段，不含用户拍照、手机耗时、地图服务或完整操作时间。

本批没有新相机按钮、原型交互或iOS/Android相机验收。L2继续做搜索内相机与确认状态，L3再用有授权的脱敏样本实测多承运商/双端。首页自动识别的门外现场证据仍需补齐，D1未完成。

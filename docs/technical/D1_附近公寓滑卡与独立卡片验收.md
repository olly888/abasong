# D1：附近公寓发现与独立卡片

日期：2026-11-01。基线：[ADD-18](../product/Abasong_V12.1_附近公寓滑卡补充.md)。用户随后明确要求每处公寓独立成卡，UI/UX顾问完成只读评审；本批未增加运行时依赖。

## 已实现的行为

首页默认查询真实前台定位附近200米的公寓，不再等精确入口、进入楼栋或停稳8秒。既有resolve及停稳测试作为辅助能力保留，不能再阻挡附近查码。目录按社区边界/建筑轮廓/地址点最短距离排序；Mapbox仅明确apartments分类作为补充，house/detached不直接推荐，已有封闭社区记录仍可出现。

每处公寓独立白底、24圆角、边框与轻阴影，轨道全透明。多卡宽W−64、间距12、两端32，居中卡左右约20露边；首尾有限，不循环复制。单卡宽W−32，不显示1/1。门牌街道单行、密码原样、贡献时间和用户名继续保留。展开聚焦当前公寓，收起回原序号。定位/发需求控件跟随卡高避让。

仅活动卡请求密码，滑动开始即撤下上一卡秘密，迟到响应与地址ID再次核对。滑卡、点地图、展开锁定当前阅读；GPS继续更新，点击定位恢复附近推荐。无记录、读取失败、无资格、粗略/失效定位分开呈现。未收录候选不读取最近公寓密码；地址未知先核对，不猜门牌。

原型使用合成数据，已补齐未收录地址→核对地址→直接共享→同地址展示。原生新增地址核对表单和真实服务契约；共享无需逐条人工审核，已有账号资格规则保持不变。

## 契约与数据库

OpenAPI源与类型一并生成：86 paths、111 operations、133 schemas。新增：

| 操作 | 用途 |
|---|---|
| POST /v1/apartments/discover | 快速目录发现，只有公开地址/分类，不含密码 |
| POST /v1/apartments/discover/mapbox | 独立、限频的临时地图补充，不拖慢目录卡 |
| POST /v1/apartments/address-contributions | 地址确认、永久编码、原子创建/复用公寓并直接共享 |

已有目录和临时地图候选以不同类型表示。临时响应带有效期，只留会话内存。Mapbox补充最多逆编码4个候选，建筑Tilequery达到50条时标记截断；结果不是洛杉矶全量覆盖。大型社区先按已知边界/轮廓去掉重复屋顶，再按明确地址去重，不把主门码套用到不同门牌。

0007增加address_key唯一索引及受约束的敏感角色INSERT/RLS策略。新记录必须是active/unverified、没有猜测的边界/父级/入口，来源为服务器取得的永久编码。服务事务继续校验账号资格、密文与幂等；地址锁和唯一键处理并发，不信任客户端坐标。首次新地址按账号/进程限频；跨实例限流与大城市地址索引优化仍是部署前工作。

实际仅对隔离本机D0应用0007；健康检查要求0001–0007。没有执行Supabase云迁移、生产写入或真实账号授权。临时结果不批量存库。

## Mapbox公开地址实测

本批共2次临时请求、2次永久编码请求，均使用公开物业样本，无司机实时GPS或门禁资料上传。Woodside公开入口附近的建筑查询取得49条明确apartments记录并标记截断，逆编码取得地址建议；这只能证明分类/接口可用，不能证明每个屋顶的地址、门或门码归属。Del Mar公开地址的普通永久请求及实际服务使用的结构化永久请求均HTTP200/地址核对通过，响应未入业务库。

现有账号可以使用永久编码；本机忽略的.env中已启用MAPBOX_PERMANENT_GEOCODING_ENABLED，示例配置仍默认关闭。未升级套餐、购买服务或接受新条款。云环境必须独立配置，不沿用本机就绪结论。永久编码可能计费，本批未开展全城导入。

依据：[Streets building](https://docs.mapbox.com/data/tilesets/reference/mapbox-streets-v8/#building)、[临时与永久地理编码](https://docs.mapbox.com/help/dive-deeper/understand-temporary-vs-permanent-geocoding/)、[Geocoding v6](https://docs.mapbox.com/api/search/geocoding/)。

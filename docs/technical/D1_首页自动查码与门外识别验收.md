# D1 首页自动查码与门外识别：实现与验收

2026-10-31；分支 `codex/d1-home-arrival`，基于 `484f4837bb6ea450f9e31551557dd980a4f20cb6`。对应 [ADD-10 场景需求](../product/Abasong_V12.1_首页自动查码场景补充.md)。本批不是完整 D1 或现场验收；没有云迁移、真实密码、资格授予、短信或部署。

## 本批交付

- 先更新需求、H01 页面规格及交互原型，再落地原生。40 页面节点、282 状态；普通无候选场景改为低高度贡献入口，顶部保留唯一搜索；定位、资料失败、多候选、无密码及无资格分别呈现。
- iOS 复用 Expo 前台持续位置观察；Android 现有 AbasongLocation 增加 LocationManager 连续观察。首页离开/后台销毁观察，返回重新检查权限；蓝点持续更新与相机/卡片锁定分离。展开或手动选择不停止位置观察，定位按钮解除锁定并回位。
- 查找请求串行、只保留最新待查观测、最多每两秒启动一次。失败/位置过期/精度缺失使旧请求结果失效，恢复可继续；旧坐标响应不能覆盖新位置。坐标不记录日志、不持久保存。
- 已有自动匹配继续使用服务器资格和来源规则；新增可信门外到达区域，仍要求唯一、公寓关联可信、精度范围完整包含、有效来源、配置启用和重复稳定观察。客户端开发停留 8 秒、位置新鲜度 20 秒不是现场冻结指标。
- 建筑高亮只用建筑映射，门外到达区域不画成建筑。首次相机命令改为立即移动，修复 Android 初次缩放被卡片布局更新中断的问题。

## 数据和接口

新增 `0005_apartment_arrival_areas.sql`，本地 D0 共 51 表、版本 V12.0001–0005。表包含 apartment/source、MultiPolygon 到达区域、pending/active/withdrawn、核对时间/过期时间；限制合法非空坐标和最大面积，强制 RLS。API/sensitive 只读，worker/public 无权限；不开放普通用户写入接口，不存门禁资料。

`POST /v1/apartments/resolve` 没有新增公开 endpoint；源生成器、OpenAPI 与类型一起增加可选 `reason`（matched/ambiguous/nearby/no_coverage/imprecise/stale_location/policy_disabled）与命中时可选 `match_basis`（boundary/entrance）。既有 status 兼容。候选 DTO 不带密码。无候选仅表示资料不足，不断言当前位置不是公寓。

入口 `active` 且已核对未过期、来源许可有效才能正向命中；过期来源不能增加命中可信度。相交的其他可能公寓/入口使结果降为候选。实际密码仍单独走已鉴权的 access-records 接口；没有通过客户端状态授予真实资格。

## 原生证据边界

iPhone 18 Pro / iOS 27 模拟器和 Android 17 / API 37 模拟器。开发专用 `/arrival-lab` 明确显示 TEST、合成资料和位置更新次数；使用实际操作系统位置流、相同 HomeApartmentContent/Mapbox/卡片代码。到达区域/读取资料采用受控 TEST adapter，正常 App 路由不使用 adapter；Release 路由重定向。模拟器注入位置不是 Mac 或司机实际位置。

服务器入口几何与权限通过上面的真实 HTTP/DB 检查独立验证。因此“TEST 原生卡片通过”不能表述为“真实公寓→生产 API→已授权真实密码已端到端通过”。公开样本仍为本地 6 处 LA 地址、4 处建筑映射、2 处仅地址；没有把公开地址推定为已核对门口或伪造门禁密码。

## 继续工作与出口

首页持续定位及自动卡片引擎已接入正常路由。正常本地数据的自动认定配置仍关闭：缺少已现场核对的入口区域和 T23 阈值证据，当前正常界面以候选/中性状态回退。此限制必须明确，不能让用户误以为现在已覆盖全部 LA 公寓。

下一批先完成允许持久使用的门口样本与来源核对、限定样本范围的真实 API 链路、最低可用共享资格/审核及经授权样本；iPhone 连接后测实际门外与邻栋漂移，再按证据启用范围，不开放全域猜测。截图批次本地核心已经回归，真实承运商样本准确率、共享审核及资源场景独立待验。D2 发需求仍未实现，不因本批完成而开放。

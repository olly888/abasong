# D2 报名、来源会话与需求管理

2026-11-04。依据[完整功能开发计划](../product/Abasong_V12.1_完整功能开发与集中验收计划.md)的B2，基线12c0ee1／CI41797919609成功。分支codex/d2-applications-collaboration。真人短信、真实云业务KMS和独立iPhone包仍在后续集中验收，本批不触发这些操作。

## 交付范围

| 页面/业务 | 实现 |
|---|---|
| D01/P08 报名 | 开放需求的详情内报名面板，预计可到日期/时间、可接件数；车辆求助不填包裹容量。当前缺口不足最低量时不提供报名主动作。失败保留输入；版本变化后须重新查看，不自动替司机接受新条件 |
| P10 报名司机 | 仅发布者可读，显示司机用户名、自报经验、到达时间、件数、撤回/已联系及条件变化；标记已联系不代表答应、到场或接走包裹 |
| U05 我的报名 | 本人列表、当前需求状态、撤回报名、来源记录；资格到期仍能撤回。重新报名复用本人原记录、追加事件，并清除旧的已联系标记 |
| P09 需求管理 | 发布后编辑条件、手动缺口、已找到/关闭、显式重开、复制为新草稿。报名不自动减缺口；零缺口不自动关闭。到期需求即使改成未来日期，仍须显式重开 |
| M02 来源记录基础 | 报名与两人会话、来源关联、不可变需求卡、通知元数据在同一事务；失败全部回滚。同一对用户复用会话，一条需求版本只附一张卡。原生可读来源卡并跳当前需求，支持序列分页/已读水位 |

保留当前V3、三导航和原型页面边界。报名/缺口面板复用支持键盘避让和滚动的底部面板；管理动作放二级面板，不把所有操作堆到详情底部。本人和他人的主动作分开，切对象/账号时清理旧状态，迟到响应不得覆盖新对象。

**本批没有文字发送、完整消息列表、推送、精确集合点共享或实时会话同步。** 原生仅称“来源记录”，不提供尚未接入的“先联系”或发送按钮；B3补齐后恢复最终原型的联系入口。服务端创建/复用会话已可供B3使用，不能把来源卡创建当成用户已发消息或对方已读。通知表与outbox同事务保存允许字段的元数据，worker尚未投递，outbox保持pending；不代表已推送/送达。

复制只带需求条件到新的草稿表单，不复用旧需求ID、报名或会话来源。重开沿用原需求ID与历史报名，旧报名仍保留原观察版本，不自动视作接受新条件。原生复制/完整重开操作仍须集中补验。

## 契约、数据与权限

新增接通11个既有契约操作：reopen、gap、versions、报名提交/发布者列表/本人列表/撤回/已联系、会话创建、来源消息读取、已读更新。加上B1共20个需求/协作操作，不代表OpenAPI全部已实现。

源生成器、OpenAPI和生成类型同步新增Application.applicant_profile（可空、最小资料）以及本人报名的request_id筛选。用户名/经验无须额外读取电话或私密资料。当前设计契约仍88 paths/113 operations/136 schemas。

复用既有applications、application_events、conversations、conversation_sources、messages、conversation_reads、request_versions和notifications；没有新迁移、表、依赖或权限授权。D0仍10版/52表，DevWest仍9版/52表，云镜像与运行环境未改。

服务端每次重查有效账号、会话和实时request.apply/request.publish；客户端JWT里自带的能力无效。报名先锁需求，再检查当前版本、截止、双方屏蔽、最低量、整批/整线、剩余件数/人数；幂等HMAC和对象引用不缓存正文。发布者不能报名自己，普通司机不能读别人的报名名单或会话。已联系和撤回采用行锁及条件更新，重复点击不重复事件。

报名不赋予承运商账户、转派、到场或配送权限。缺口仅发布者手动更新，超过总量拒绝；整线缺口只允许整量或零。总量不能减至当前缺口以下；整线主动修改总件数时保持整线剩余量语义。

发布后改动、缺口、关闭与重开追加版本；当前有效且未屏蔽的报名者得到新来源卡与通知元数据。旧报价/所见版本不改写。历史版本与来源卡再次用白名单组装，即使旧snapshot混入私密字段也不会透出。屏蔽后停止新联系，既有会话可读，当前不可见需求的快照不揭示。已读只能前进，不能用另一会话的sequence推进水位。

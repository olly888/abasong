## 1. 产品与实现范围

首页公寓卡的添加与“我的→共享门禁码→手动填写”共用同一ContributionForm。通用入口直接显示地址、门禁码、门别及来源确认；不先打开全量公寓目录。卡入口按传入公寓ID重新读取地址；读取失败保留本次门禁码，提供重试，不能默默改成新地址。

地址框300ms防抖，同时读取已有公寓和Mapbox候选，按既有完整邮政身份规则去重。选择已有公寓直接绑定ID；外部候选通过原会话retrieve，单一已匹配公寓绑定ID，歧义由司机选择，没有匹配则展示已解析地址供核对。缺地址、无结果或服务失败时，可在同页手动填写完整门牌/街道、城市、州及可选邮编。没有公寓大目录、自动选择最近点或虚构地址坐标。

更换地址保留门禁码和门别，立即清除来源确认并暂时禁用共享；只有明确目标且重新确认后才能提交。前导零和#/*不转换为数字。普通确认仍直接共享，不新增审核。表单里删除重复截图大按钮，截图继续从统一共享菜单进入，原导入流程未改。

共享与私人模式明确，切换保留已填门禁码；首次提交后锁定本次意图。私人条目仍使用原有条目/记录两步API，同次部分失败保持条目键，避免重复创建；共享失败保留地址、值和来源确认，同内容重试复用幂等键，连续点按不重复发起。成功使用本次实际公寓ID回首页；不按当前位置猜回程。普通退出不新增跨次草稿或续填。

## 2. 代码和接口

| 文件／层 | 本批调整 |
|---|---|
| ContributionForm | 同一字段、确认、保存及成功回程；不包含业务账号模拟 |
| ContributionAddressField | 地址预填/读取失败、联想、选择、手动核对、歧义与换址 |
| contribution-address-search | 每次打开表单的会话；300ms由界面防抖；140秒/40次轮换；retrieve使用候选原会话；取消及版本检查丢弃迟到成功/失败 |
| contribute路由 | 保留SensitiveScreen、真实Auth资格和dataRequest；只传ID、模式及既有内存地址键，不通过URL传门禁码 |
| 统一入口 | 统一“共享门禁码／从截图添加／手动填写”；仅改相关入口文案，不宣称整套“我的”已迁移V3.2 |
| PageFrame | 按容器实际窗口Y测量KeyboardAvoidingView偏移，避免嵌套页面/安全区让底部操作落在键盘后方；沿用原布局、颜色和控件 |
| ContributionLab | 仅__DEV__内存适配器，运行相同表单组件；TEST成功回程是回调ID核对，不是模拟器向真实业务库共享 |

复用已有GET `/v1/apartments?limit=5&query=...`、GET `/v1/apartments/{id}`、POST `/v1/search/addresses/suggest`、POST `/v1/search/addresses/retrieve`，以及既有共享/地址贡献/本人私存API。不新增契约、迁移、依赖、推送或云配置。临时Mapbox数据只在本次表单中使用；永久保存仍由原address-contributions服务及其许可配置执行，不保存客户端临时点/结果ID为永久依据。

所有真正的读写仍逐请求鉴权，客户端canContribute只控制呈现；不能把合成Lab资格当服务器权限。退出、后台/账号变化继续通过SensitiveScreen卸载敏感表单并取消未完成查询，不做明文持久化。请求失败与无结果分别呈现，部分服务失败保留可用候选。

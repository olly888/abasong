# R4-06 两场景契约与增量迁移

2026-11-05。基线822a9ecc / PR93，分支`codex/r4-06-delivery-contracts`。R4-05本地组合出口已通过。本批建立V2模型、校验和0015/0016增量，不提前启用未完成的发布服务；R4-07再接事务、报名、缺口、来源与查询，R4-08接原生表单/预览/详情/导航。

## 版本与交付边界

- 旧请求及历史快照保持`request_schema_version=1`，新增字段为空。不按旧kind猜场景，不给未知数量填0，不重写0001–0014。
- V2显式选择`warehouse_shortage`或`delivery_handoff`，与`task_scope=partial/whole_route`分开。kind只是新请求的兼容投影，不用于回填旧记录。
- OpenAPI新增独立V2输入/摘要/详情/去敏快照模型；本批不把它们挂到仍运行V1的端点。模型带准备状态说明，不把类型生成当服务上线。
- 现有V1端点继续严格拒收V2字段，并暂不列出/读取V2数据，防止旧报名与缺口逻辑把约数当精确上限。R4-07统一启用后再移除该隔离。

## 数量与时间

`quantity_mode=exact/estimate/unknown`；未知数为null，已知数为正整数。仅exact允许数值剩余缺口；estimate/unknown的remaining_parcels为空，不自动均分，不自动减件或减人数。整线必须exact、不可拆分、最低量等于整批件数；unknown不填写最低件数。仓库缺人场景需人数，代送人数选填。

`handoff_mode=asap/scheduled`，接手日按America/Los_Angeles。asap只能选当天，服务端以当次时钟生成开始时间，不接受旧草稿时间冒充尽快；scheduled使用明确RFC3339时刻及匹配的洛杉矶日期，发布时不能在过去。客户端本地时间的夏令时选择在R4-08处理，服务不接收无偏移的含糊时间。

有最迟接手时默认在该时刻下架，否则接手日23:59（内部使用该分钟末23:59:59.999，避免最后一分钟无法发布）；自定义下架必须在未来，有接手截止时不晚于该截止。下架可早于未来到场时间，不再与送完要求耦合。送完模式same_day/next_day/contact；前两者默认对应洛杉矶日23:59，可指定该范围内且不早于接手的截止；contact不夹带隐藏截止。日期跨午夜、DST的23/25小时日分别测试。

## 取件、版本与授权

输入只接收发布者确认的地址文字及明确来源`publisher_entered/mapbox_suggestion`，客户端不能提交坐标、供应商结果ID、任意导航URL或认证标记。Mapbox联想文字也需要持久许可，不能删除坐标后标作手填来绕过来源约束。仓库草稿可不完整；发布前要求门牌街道/城市/州与明确确认。途中交接只有地区，不保存私人碰面位置；切换后不能保留仓库地址引用。

新增一张`request_pickup_addresses`，按(request_id,address_version)追加保存仓库地址，强制RLS；requests只保存kind和本需求内的地址版本引用。复合外键防止跨需求串址。父需求发布时的延迟触发器验证该版本地址已确认；不把跨表检查写成CHECK。

取件地址不进入普通发现摘要、游客摘要、消息来源快照或锁屏。只有当前有权登录详情可读当前地址版本；本人可读自己的历史版本。账号失效、草稿他人、屏蔽、旧地址版本均不能借引用读取。API需设置事务内actor并做对象检查，RLS是额外防线，不是JWT验证替代。worker、anon、authenticated和PUBLIC没有新表权限；API只读/追加，不能覆盖或删除历史。

首版可保存发布者独立手填的未定位文字地址；地图与外部导航在R4-08按用户动作开启。供应商衍生文字（即使没有坐标）必须关联已核对、未过期且允许持久化的provider_permanent/licensed_dataset来源；客户端声明不代替后台许可核对。0015已在D0应用，因此新增0016，不改已应用文件：存储来源为publisher_entered/provider_permanent/legacy_unclassified。0015既有地址保留原文并保守标为legacy_unclassified，仅本人审计可读，不可直接重新发布；API不能新增该来源。坐标也须有效持久来源，不接临时结果。本批不调用供应商，不改变永久地理编码配置；后台解析接通及来源过期输出防护属于R4-07。

## 实施与验收

1. 新增严格V2校验与默认时间解析、独立模型及生成类型；现有端点不接受混合版本。
2. 0015为V1保留原约束，为V2增加数量/场景/日期/取件引用约束，0016补齐地址文字来源和受限兼容；本机迁移及readiness共用版本集合。
3. 隔离PostgreSQL从0014带旧数据升级，核对旧行/快照不变；验证null、约数、整线、切换、跨需求外键、未确认地址发布拒绝及角色/对象隔离。
4. 运行相关单元、V1 HTTP/PG回归、D0迁移和生成一致性；不向云库应用，不新增资格，不要求模拟器或iPhone操作。本批没有原生界面变化，不重复未受影响的手势。

约束与RLS按本机PostgreSQL17核对：[CHECK与外键](https://www.postgresql.org/docs/17/ddl-constraints.html)、[行安全](https://www.postgresql.org/docs/17/ddl-rowsecurity.html)。跨表发布确认使用触发器；可空表达式显式处理NULL，不能把SQL未知值当校验通过。

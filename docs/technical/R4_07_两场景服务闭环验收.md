# R4-07 两场景服务闭环与本地验收

2026-11-06（洛杉矶）。分支`codex/r4-07-delivery-services`，基线3bc2037 / PR94，基线精确CI42183906516成功。本批接通R4-06准备的V2服务，不改原生页面，不向云库应用迁移。

## 1. 当前可用范围

仓库缺人找司机、送不完找人代送均已通过实际本地HTTP/PostGIS闭环：草稿→补齐/发布→查询/详情→报名与来源会话→本人编辑/缺口→关闭/重开。未知量为null，约数不是精确缺口上限；报名不减包裹或人数，也不表示承运商已转派或司机到场。平台仍不做结算、长期招聘或自动派单。

旧版客户端继续使用默认V1列表；新版明确查询`request_schema_version=2`。这保留当前App行为，让R4-08统一接表单、预览、详情和列表，不让旧表单把V2当作必须已知数量的旧任务。现有按ID详情及生命周期按实际数据版本处理，不能用旧PATCH/缺口输入更新新对象。

| 接口 | R4-07实际行为 |
|---|---|
| POST `/v1/requests` | 严格的旧输入或显式schema2输入；身份来自验证JWT，草稿仅本人可见；幂等键绑定账号、路由和内容 |
| GET `/v1/requests`、`/v1/me/requests` | 默认schema1；schema2返回不含完整取件地址的摘要。新版day按洛杉矶接手日精确筛选，不按下架日期相交；跨版本cursor拒绝 |
| GET/PATCH `/v1/requests/:id` | 详情按对象权限；V2编辑必须schema2及当前expected_version；同版本并发只有一次成功，另一次409；场景/发布来源不可伪改 |
| publish/reopen/close | 继续使用expected_version及幂等键；发布/重开独立核对时间、数量、取件和当前代表权限；终态编辑不会静默重开 |
| PATCH gap | 只有本人开放且未到期对象；exact为有界精确件数，whole为0或整批；unknown/estimate不允许填写数值件数缺口；人数手动更新 |
| POST applications | 当前版本、有效资格、账号/屏蔽/本人检查；未知/约数可不承诺数量，填写时尊重明确最低量；确定整线须整量；报名及两人会话/来源同事务 |
| versions/messages/application summary | V2保留场景、口径、日期及冻结的显示名；无仓库地址/点位/私下付款正文。消息来源和当前详情分别鉴权 |
| share-links/public摘要/resolve/revoke | 发布者明确确认后创建；公开接口独立白名单，不返回完整需求。resolve仍需登录和对象权限，链接不授工作资格 |

RequestRead、RequestSummaryRead、RequestSnapshot等联合契约由生成源和生成类型同步。空旧/新列表形状相同，列表响应联合使用anyOf，避免合法空列表同时匹配两个oneOf而失败。现有88路径/112操作不新增同义API；契约有160个模型，不能据此宣称全部历史设计接口已实现。

## 2. 数量与时间保护

数量口径贯穿保存、发布、编辑、查询、报名、来源和公开摘要。exact→estimate/unknown会清除精确剩余量；改回exact须本人给出确认件数。减少确定总量低于当前剩余量会拒绝，需先手动调整缺口；人数可选的代送场景显式清空人数时返回null，不制造0。仓库场景仍需人数。

接手日、送完要求、下架分开。希望到场晚于停止展示的时间可以合理存在：报名发生时需求须仍开放，到达须在该接手日及最迟接手范围内。asap初发/重开用当次服务器时钟；默认下架为洛杉矶日末23:59:59.999。编辑已经开始、仍有效的任务时，仅未改变的原始开始可保留，不挪接手日、不自动续期。数据库DATE按日历解析，不能先转UTC再当GPS时刻转洛杉矶日期。

## 3. 仓库地址与发布身份

- 取件地址按本需求版本追加，旧地址不覆盖。相同完整地址、确认状态及有效来源重复保存会复用原版本，不重复地理编码；地址实际变化或改交接方式时，未显式重新选择的派生地区清空，发布前必须核对。
- 手填可保存不完整私人草稿；不完整地址不能发布。Mapbox联想文字也需要持久许可，沿用现有永久地理编码开关、精确组件匹配及固定供应商主机；失败不退回temporary，也不改成手填来源。客户端不能提交点、来源ID或任意导航URL。
- 新版普通列表、报名摘要、版本/消息来源及公开摘要不含完整地址、点位或私下付款正文。详情只读取当前版本；RLS对本人历史、他人当前版本、失效账号、屏蔽及草稿分别约束。来源过期后不返回点位，发布/重开须重新核对；不生成伪坐标。
- 首次发布冻结显示名和DSP来源摘要。团队改名或个人改名不改写该需求来源；历史身份不授予未来代表权限，重开和已发布编辑仍查当前团队所属。0017新增可空publishing_identity及不可修改触发器，不替旧记录猜填历史身份。
- 0017同时要求从终态重开时再次执行取件确认；worker正常关闭/到期仍不需要私有地址权限。旧0015/0016未改写。

## 4. 公开摘要与配置边界

分享仅由发布者显式确认生成，随机token与正常业务JWT无关。链接有效期取需求下架和24小时中较早者；关闭/到期仅返回静态标题、ended及summary:null，撤销后404，重复撤销安全。无权账号不能撤销或通过resolve绕过屏蔽。

`REQUEST_SHARE_BASE_URL`为服务端可选HTTPS接收页来源配置，不能由客户端传入；未配置时创建分享返回503，不生成假链接。测试使用`.invalid`合成来源；真实接收页/域名分发没有在本批部署。R4-08/B5不得把此测试URL变成司机可用分享入口，应按真实分发条件启用。

## 6. R4-08接入顺序与回退

下一项直接进入原生表单工作包：P01两入口→同一P03表单/草稿/编辑/复制/预览→详情和报名→仓库看地图/复制/外部导航→双端同状态核对。保留V3.2组件、已有统一地址联想及来源会话；无新的司机工作台或集合点模块。

客户端需显式选择schema2列表，识别旧/新详情；地址来源由输入路径生成，不新增让司机选择供应商许可的表单。换地址清旧点/派生地区，完整核对后提交；不发送数据库来源ID和坐标。Mapbox保存失败保留本次表单，未定位地址仍可复制或按地址打开导航。三种数量和三个时间含义一致，未知量报名不强制造一个数字。生命周期继续按当前版本提交，并核对旧报名条件更新。

已有0015–0017和历史记录只前向维护；不把V2改回V1、不删除来源/地址版本。紧急代码回退至少回到R4-06的V1隔离栅栏，暂停V2能力；不能用旧精确件数逻辑解释V2。云迁移和原生/现场出口另按授权与对应工作包验收。

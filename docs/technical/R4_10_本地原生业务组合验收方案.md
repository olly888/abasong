# R4-10 本地原生业务组合验收方案

2026-11-06，洛杉矶。前置为 R4-08、R4-09 对应范围通过。R4-09 的 iOS 补验及 Android 两组负责人反馈均通过；前置已满足，现按本文启动R4-10，执行结果另行记录，不提前声明验收通过。

## 1. 出口与边界

用同一套真实本地 Nest API、迁移及受限 PostGIS 角色，接通两场景原生表单、详情、报名、来源会话和手工关闭。复用实际组件及版本/幂等逻辑，不能继续用内存适配器的成功回调冒充业务通过。普通路由与 DEV 测试容器的验证分别记录，不把组件组合当作真实账号登录或整个 App 已完成。

只使用独立一次性测试库与两名合成身份，不使用真实手机号、不改变现有 D0 唯一账号资格，不访问云库/云 KMS或真实消息接收者。原生地图沿用现有服务；业务测试的供应商地址响应使用明确标注的本地 fixture，不计为地图真实覆盖验证。

## 2. 本地服务准备

1. 在既有 `localTarget` 防护验证后，创建随机命名的一次性测试库，顺序执行既有 17 次迁移；不重置 `abasong_d0`，不改已应用迁移。
2. 两名合成用户仅存在于该库，使用本地短期 JWT issuer，API 仍执行真实 IdentityGuard、capability、对象授权和数据库角色检查。私钥/令牌仅在内存，不输出、不提交、不放进 Metro 环境变量或原生包。
3. 如需原生取得本地测试身份，使用仅监听 `127.0.0.1` 的临时测试工具，固定目标为该进程的测试 API；Android 通过模拟器 host alias 访问，不开放局域网或公网，不给业务服务增加“跳过鉴权”接口。
4. API/测试工具退出及到期时清理子进程、该批随机测试库与该批临时角色。只允许匹配完整随机测试名；失败不能回退至本机 D0 或云库。
5. 接口响应丢失和短时不可用只在测试工具中注入，不给正式服务加入故障开关。记录写入数、版本、状态和断言，不记录正文、令牌或连接串。

## 3. 组合验收矩阵

| 场景 | 要验证的结果 | 证据 |
|---|---|---|
| 仓库缺人 | 原生核对→发布→真实详情；取件地址与派送区域分开 | 双端原生＋对应HTTP/PG行 |
| 送不完代送 | 途中交接，不沿用仓库对象；未知量不显示为0 | 双端原生＋服务响应 |
| 编辑／复制 | 编辑遵守当前版本；复制形成新草稿/新ID，过期时间不照搬 | 服务版本、ID与原生回程 |
| 一仓库两地址 | 更换地址清确认与旧区域；历史版本不被改写 | 地址版本/来源＋原生确认 |
| 无坐标 | 保留完整地址、复制/导航；不猜附近点或伪造成功 | 失败状态原生观察 |
| 报名／联系 | 使用司机身份；可选容量符合约数/未知规则；同来源已有会话不重复 | 报名/来源会话实际记录 |
| 缺口／关闭 | 报名不自动扣减，发布人手工更新；关闭后不再推荐但已有会话保留 | 真实查询与对象权限 |
| 可接活／跨日 | 未来时间不叫在线；到期或关闭停止推荐 | 原生U03与实际找人查询 |
| 保存响应丢失 | 复用同一幂等键，重试不重复创建/发布/报名/消息 | 真实写入计数与版本 |
| 条件/资格变化 | 旧版本不覆盖；新报名需重新核对；失效资格不能新发布 | 真实403/409＋原生保留输入 |
| 系统返回／前后台 | 返回核对页保留，放弃需确认，后台回来不重复发送 | 双端手势/键盘分别记录 |

已验且未受影响的地图回位、滑卡和仓库复制/导航不机械重跑；只有本次真实组合发现差异时补验。系统键盘、返回、前后台及普通路由未测项逐项保留，不能由纯模型测试替代。

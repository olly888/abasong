# R4-13 核心差异收拢与未收录截图共享

2026-11-06，洛杉矶。起点35b1644 / PR100（精确HEAD CI42320654115通过）；分支`codex/r4-13-unlisted-import-closure`。本批实现D08未收录地址的本地批次共享，逐项收拢R4核心差异；不宣称整个App、云业务或现场已经验收。

## 1. 实际实现

- B05复用手填贡献的`ContributionAddressField`：查询候选或核对完整门牌/街道、城市、州、邮编；更换地址保留原样门禁码和门别，清除选中与来源确认，不提供全城公寓下拉。
- `ImportCandidateEdit`/候选增补可空`confirmed_address`，提交结果增补可空`apartment_id`，兼容旧批次。已收录ID和结构化地址互斥；显示文本与地址身份矛盾拒绝，客户端不能上传坐标或许可凭证。
- **许可校验在候选持久化之前完成。** 原始OCR/独立输入与临时地图选址在客户端分开；新选址不冒充OCR原文写入草稿。已有地址保守匹配，无唯一关联时不取最近点；新地址使用现有Mapbox永久地理编码开关、身份/精度检查。服务端许可证据仅存在加密批次，不返回客户端，不接受客户端提供。
- 地址确认失败逐项呈现，其他已确认条目继续提交。地址准备失败是客户端明确区分的未提交结果，不伪造服务端私存/共享计划；网络丢响应保留每条精确请求及幂等键。失败重试不重复查询已确认地址、私存或贡献。
- 私存及公共地址关联同事务；共享阶段复用原独立来源。仅独立OCR/自由文本私存不调用供应商、不创建公共地址；选择了结构化地图地址，即使只私存，也先确认持久化许可。不是批量复制临时搜索结果建立城市地址库。
- 私存前失败且无持久结果的计划允许重新核对；已私存/共享条目继续锁定。旧版本/旧提交回放不能改变新修订。新地址请求前后重验当前账号/共享资格，仍使用原受限数据库角色。
- 完成后按实际提交结果的公寓ID回首页，不因元数据迟到重发贡献或猜GPS目标。新地址初始`unverified`只表示司机确认关联，不表示现场验证，也不把一个社区门码套给全部楼栋。

原型B05同步为地址联想/手填，移除全目录选择；缺少城市不能确认，修改密码保留`#/*`和前导零，完成返回本次共享公寓，点定位恢复附近推荐。原型新地址不伪造地图坐标；其浏览器合成与真实API证据分开。

## 2. 契约、数据与依赖

沿用现有加密JSON候选/计划，**无新DDL、无修改已应用迁移**，D0仍17迁移/54表。OpenAPI生成源、YAML和TS共同更新；公开路径数88、操作112、schema160。本次复用Nest/pg/EnvelopeCrypto、Mapbox永久地址服务、Expo58/RN和V3.2既有组件；不新增应用依赖、原生模块、权限或锁文件。

地址准备当前每账号20次/分钟、实例共享20次/秒，有界逐项调用；已收录或已有许可证据不重查。Mapbox限额/许可未启用明确失败，不以临时结果或本地密钥降级。参考[Mapbox官方存储说明](https://docs.mapbox.com/api/search/geocoding/#storing-geocoding-results)。本批供应商为合成上游，不是实时Mapbox授权实测。

静态校验工具补齐既有oneOf封闭输入、安装注销凭证端点和带query的本地链接识别；历史档案不参与当前链接检查。临时Python校验环境不属于应用依赖。静态SQL解析不冒充数据库执行。

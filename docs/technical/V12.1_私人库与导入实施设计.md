# V12.1 私人库、主动共享与导入实施设计

2026-10-30。T27/T32–T35实施输入；依据[产品补充](../product/Abasong_V12.1_我的公寓与私存共享补充.md)。下列路径为下一批源契约方案，尚未加入OpenAPI或实现服务。已应用0001保持不动，后续使用增量迁移。无云端DDL授权，本设计不应用到云端。

## 1. 对象与访问边界

| 对象 | 建议实体 | 边界 |
|---|---|---|
| 本人公寓项 | personal_apartments | owner_id、可空apartment_id、自填地址/名称、自定区域、version；已收录项每owner/apartment唯一；不使用GPS强行补全未知地址 |
| 私人记录 | personal_access_records | owner_id、personal_apartment_id、version、删除状态；同owner外键，不能关联他人公寓项 |
| 私人正文 | personal_access_secrets | 独立密文角色；密码、门别、备注及未知地址等私人正文不在列表摘要中返回；AAD绑定owner/对象/版本 |
| 导入批次/原图/候选 | import_batches/import_sources/import_candidates | owner、状态、generation、有限留存；原图私有且短期，正式私存不受草稿到期清理影响 |
| 逐项保存意图 | import_item_commits | owner、batch/candidate/revision、固定mode、private_result、share_result、引用ID；分别幂等 |
| 纠正关联 | access_corrections | owner、原贡献事件、替代贡献事件、原因类型/时间；原记录不覆写 |
| 查看去重事件 | access_view_events | 服务端已授权实际揭示后产生；保留最小去重信息，汇总不返回查看者身份 |

自定区域首版可为本人公寓项上的标签字段，不需要区域公共表。私人地址与标签也不进入公共地图或共享DTO；列表需要的最小地址经owner授权后按需解密。已收录收藏只存公寓ID引用，读取最新有权共享资料；不保存公共密码快照。

共享沿用0001中的access_records/access_secrets/access_contributions/access_feedback。纠正关系用新实体/事件扩展；不能复用修改私存接口。私存正文与共享正文分别加密、分别授权，任何公开需求摘要也不得引用私人资料。

## 2. API职责与拟定路径

统一Bearer认证；正常账号可操作本人的私人库。访问其他共享密码、主动共享/纠正仍要求当前服务端能力。所有ID查询带owner条件；越权/不存在统一404。响应Cache-Control: no-store，日志屏蔽正文。

| 方法与拟定路径 | 输入/输出边界 |
|---|---|
| GET /v1/me/apartment-library | 游标/区域过滤；只返回本人公寓摘要与私存条数，不回密码 |
| POST /v1/me/apartment-library | apartment_id或自填地址二选一；禁止接受owner_id；同公寓重试返回原项 |
| GET /v1/me/apartment-library/{id} | 本人元数据；私人正文与共享正文分别请求，不混进一个缓存对象 |
| PATCH /v1/me/apartment-library/{id} | 自定名称/区域、expected_version；不接受公共公寓或权限字段 |
| DELETE /v1/me/apartment-library/{id} | 删除本人项/私人记录；不删除公共公寓或共享贡献 |
| POST /v1/me/apartment-library/{id}/records | 自有密码字符串、门别、私人备注；仅私存 |
| GET /v1/me/private-access-records/{id} | owner授权后揭示本人正文；不要求access.read |
| PATCH /v1/me/private-access-records/{id} | expected_version与本人正文；不改变已有共享 |
| DELETE /v1/me/private-access-records/{id} | 仅本人私存；共享引用保留独立生命周期 |
| POST /v1/me/private-access-records/{id}/share | expected_private_version、明确来源声明及目标公寓/提议；不收任意owner或私人备注 |
| POST /v1/me/contributions/{id}/corrections | 本人贡献事件ID、正确码/门别核对、声明、预期版本；返回新旧事件关联与复核状态 |
| GET /v1/me/contributions/summary | 本人贡献摘要、合法计数、最近反馈；正文仍走独立授权揭示 |

写入均需幂等键，指纹用受控密钥HMAC，不能把明文码或低熵码的裸哈希写进通用幂等表。expected_version冲突409；格式不符400；资格变化403；密钥不可用503且不退明文。列表游标不能允许改变owner过滤。批次接口另扩展创建、上传授权、识别、核对、确认、逐项提交、恢复、取消；源契约需明确状态枚举和限制后再生成类型，不能只改客户端类型。

## 3. 保存与共享事务

1. 批次提交锁定mode为private_only或private_and_share，并持有候选revision和用户确认。未确认修改必须重新确认。
2. 每候选先在私存事务内完成owner检查、正文加密与幂等保存，记录private_saved。相同请求重试返回已有ID，不重复加密写入/重复记录。
3. 需要共享时单独检查当前资格、对象与来源，再复用共享去重事务；成功/同码/待审核/失败分别记录。共享失败保留private_saved，重试只重做共享。
4. 新建公寓提议待审核，不直接给未定位地址建立active公共公寓。私存成功不依赖提议审核。
5. 取消对未提交项停止处理；已提交事实不能回滚或显示成从未发生。worker按generation/lease比较更新，旧任务不得回写已取消批次。
6. 幂等键相同且正文/模式不同返回409；同批模式锁定后不能在失败重试时静默转换私存为共享。

存储层至少独立private_status和share_status；不能用一个“提交成功”覆盖双阶段结果。原型目前只演示主流程；该两阶段错误语义是后端必须补齐的验收项。

## 4. 纠正与统计

纠正事务锁定本人贡献事件及涉及共享记录；校验本人来源仍有效，再创建/复用正确共享码，写纠正关联和本人来源终止事件。只有本人来源且没有需保留的其他有效来源/反馈时，原码按规则退出展示；否则进入复核，不删除他人记录。复用正确码不刷新其原contributed_at，任何反馈/查看不迁移。现有排名函数规则不变。

查看统计只由服务端成功正文揭示产生，排除自己、预取、失败、重试/重复读取及滥用。去重窗口与留存由T23冻结后配置；未冻结时不要上线一个推测的统计数字。反馈摘要取当前有效反馈，不将同码确认当有用票；查看不等于进入成功。

## 5. 实现顺序与准入

先在源生成器增加DTO、operationId、能力/对象规则与独立响应；生成OpenAPI/types，更新页面目录的pending标记并运行契约校验。再新增本地迁移与owner/密文角色约束，在隔离D0数据库执行；随后实现API与真实HTTP隔离测试，最后接入原生U06/U09和截图链路。OCR供应商实测可独立推进，不阻塞手动私存的数据设计。

必须验证：A猜B对象；共享资格撤回仍能读本人私存却不能读他人共享；AAD替换失败；私存修改与共享互不覆盖；两阶段故障及幂等；未知公寓提议；同码并发；纠正保留历史；退出/切账号清内存；日志/异常不含正文。开发加密适配器必须明确本地与生产KMS区别，未配置生产密钥时拒绝生产启动，不能将本地测试密钥称为生产加密完成。

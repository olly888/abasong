# Abasong V12 API 契约与权限规则

日期：2026-10-29。机器契约：[openapi-v12.yaml](openapi-v12.yaml)；生成源：[generate_v12_openapi.py](../../scripts/generate_v12_openapi.py)。本文件补足 OpenAPI 不能自动表达的对象、字段、状态与安全规则。契约不代表接口已经实现。

当前增量：[V12.1页面与契约对齐](V12.1_页面梳理与契约对齐.md)优先；只做临时配送支援与灵活运力协作，不做长期招聘。公开需求分享是独立只读摘要接口，不扩大正常业务权限。

## 1. 协议与身份

HTTPS JSON，路径 `/v1`，UTF-8。响应为直接 DTO，列表为 `{items,next_cursor}`；不是另套未声明的 data 包装。服务响应 `X-Request-ID`，错误 `{code,message,request_id}`，不回栈、SQL、密文、手机号或供应商密钥。契约使用 `.invalid` 占位域名，不是真实已部署 API。

OTP 发起、验证、刷新、退出使用 Supabase Auth SDK，不在自有 API 复制一套口令接口。业务 JWT 校验签名、iss、aud、exp/nbf、sub；同一环境只接受指定 issuer/算法。非对称 JWKS 缓存与 key rotation 按供方规则处理；JWT decode 不等于 verify。检查用户本地 status、session_invalid_before、资格有效期，敏感请求禁用仅基于 token 内的旧资格缓存。

`POST /me/bootstrap` 只为已验证 JWT 的 sub 建立账号。客户端不能传 actor_id、publisher_id、contributor_id、verified、staff_role；输入额外字段拒绝，非静默接收。普通资料 PATCH 只更新 DTO 白名单，自报 experience 不包含 source；已核验经验由独立审核记录组合输出，不让本人覆盖。

删除账号等敏感操作要求最近重新认证；核对 Auth 真实会话/认证时间，不能把刷新后 JWT 的 iat 当作用户刚重新登录。删除入口请求返回任务状态前即停用敏感访问；正式 Auth 删除由后台受控处理。

## 2. 权限模型

“司机/DSP”是公开业务身份，不是管理员角色。发布者/报名者/会话参与者是对象关系；进入资料的阅读/贡献是时效性能力，必须独立授权。手机号验证不等于取得所有公寓的访问授权。

| 主体 | 能做 | 明确不能做 |
|---|---|---|
| 未登录 | 登录流程、健康检查、发布者主动分享的独立公开需求摘要 | 正常业务账户/需求全对象、密码、消息、需求报名列表 |
| 活跃登录用户 | 最小公开资料/区域/公寓元信息、自己的设置、允许的社区内容、自己的会话 | 下载密码库、公开他人联系方式、猜 ID 读他人私聊 |
| 具 `access.read` 能力且未到期 | 对允许公寓逐对象读取可展示进入信息、反馈 | 将能力等同对任意敏感数据的权限；绕过失效/撤回 |
| 具 `access.contribute` 能力 | 提议公寓、贡献有权分享的进入信息 | 自授 verified、改他人的原始贡献时间、无权搬运承运商资料 |
| 具 `request.publish` 能力 | 本人发布/更新需求，使用有权代表的组织来源 | 冒用别的 DSP、查看别人的全部报名司机 |
| 具 `request.apply` 能力 | 对开放且有效、非本人、未屏蔽需求报名 | 伪造到场、自动接走包裹或获得承运商转派权限 |
| 需求发布者 | 看本需求报名、联系、改缺口、关闭、分享集合点 | 把报名当同意新价格/已到场；读不相关会话 |
| 报名者 | 自己报名/撤回、看所报名需求版本 | 看其他报名者的联系方式或私聊 |
| 两人会话参与者 | 看/发本会话消息、推进本人已读水位 | 任意替换会话 ID、读另一对人的消息 |
| `ops.review` 员工 | MFA后审核允许的对象与举报 | 默认解密全部密码/消息、授员工权限 |
| `ops.reveal` 员工 | MFA+目的/理由+允许对象后必要揭示密码，写审计 | 批量导出、无理由查看私聊或公寓整库 |
| `ops.user_manage` 员工 | MFA后授予/撤回工作能力、受控账号动作 | 经普通接口自授员工能力；员工权限走受控部署/IAM流程 |

员工能力不能通过普通个人资料或普通授权 API 获得。员工接口标记 `x-internal`，部署层限制内部访问范围，服务层仍验证 MFA/资格/对象和审计，不能只靠隐藏菜单。架构中采用相同 Auth 用户 ID，但员工使用更强认证及受控授权路径；仅手机 OTP 无法通过员工接口要求。

## 3. 对象/字段规则矩阵

| 对象 | 可读范围 | 可写范围 | 输出排除 |
|---|---|---|---|
| 公寓基础资料 | 活跃登录用户，限有效/可见对象 | 贡献提议/纠错；运营核验后生效 | 供应商受限原始响应、密码指纹 |
| 进入记录正文 | 资格有效、对象允许、状态 active且适用 | 有权贡献；本人可请求撤回；确认失效运营处理 | 对外不返回ciphertext、DEK、HMAC、内部反滥用详情 |
| 本人反馈 | 本人当前反馈，汇总状态按允许输出 | 本人一条当前状态与追加事件 | 他人敏感身份、刷票判定内部细节 |
| 需求草稿 | 仅本人；运营按举报目的查看 | 本人版本化更新 | 不在找活/圈子公开草稿 |
| 已发布需求 | 活跃用户可见；关闭后保留终态 | 本人；审核可关闭违规内容 | 精确集合点、私人电话、报名名单 |
| 需求版本 | 发布者/已报名者/有权审核 | 服务生成不可变去敏快照 | 密码、原消息、精确集合点/个人联系方式 |
| 报名 | 报名本人或本需求发布者 | 本人报名/撤回；发布者可标已联系 | 不公开全体司机报名行为 |
| 可用司机 | 主动声明有效的区域档案 | 本人时段/区域/容量 | 实时GPS、轨迹、电话号码 |
| 精确集合点 | 发布者，及其明确共享且未撤销/屏蔽的会话参与者 | 仅发布者分享/撤回 | 不因报名自动揭示，公开需求响应不带出 |
| 会话与消息 | 本人作为pair一员；移除消息不返回原文 | 本人且双方未屏蔽；服务端校验来源卡权限 | 不返回加密字段；列表不返回私聊预览正文 |
| 常联系/备注 | 仅owner | 仅owner，存在实际会话才添加 | 不向被收藏者或DSP同事公开备注 |
| 通知/设备 | 仅本人 | 本人标读/设置/解绑 | 对他人不返回令牌、安装ID |
| 举报 | 报告者收到提交回执；员工按目的处理 | 本人提交/员工处理 | 不公开举报人身份给被举报者 |

对象不可见与不存在统一404，避免 ID 枚举泄露。需要合法身份但无某项能力时返回403 `CAPABILITY_REQUIRED`；已知本人需求状态不允许操作返回409。对外字段使用专门输出 DTO，不能直接序列化 ORM 原始行。

## 4. 接口分组与闭环

完整路径、字段及错误由 OpenAPI 定义；当前包含账号/设置、区域/组织、公寓定位/自有搜索/外部临时联想、进入资料/贡献/反馈、配送需求/版本/缺口/报名、司机可用性、会话/消息/集合点分享、常联系/屏蔽、社区/回复、通知/设备、举报/内部审核。

外部地址 suggest/retrieve 的 session_token 只用于同一次交互；响应 `use_mode=temporary` 明确限制，服务不偷偷保存地址坐标。提交自有公寓提议必须来自本人/有权方的独立观察和声明，不允许把临时 API 返回内容自动转成永久授权来源。

`GET access-records` 是受保护读取，不存在任何公开“首页聚合接口一次带回所有密码”。`resolve` 只回公寓候选元信息；安全能力不足时仍可展示基础地点，正文请求独立拒绝。地图 GeoJSON 后续如扩展只含允许公开的 ID/区域/状态。

司机档案公开的只是自愿提供的工作资料，API 返回 `currently_available` 根据 enabled+时间计算，不根据在线心跳。更新 availability 首建 expected_version=0，已有状态需当前 version；未开放/到期的司机不在找人列表推荐，但旧会话不消失。

## 5. 幂等、版本与错误

带 `Idempotency-Key` 的 POST：UUID，作用域 user+route；摘要使用独立服务密钥HMAC，避免低熵门码被离线枚举。同key同意图返回原对象/当前允许状态，同key不同意图返回409 `IDEMPOTENCY_CONFLICT`；进行中同key返回409 `REQUEST_IN_PROGRESS` 与重试策略。缓存仅对象引用，不存明文响应。建议保留24h，生产前冻结。

消息另有 sender+client_message_id 唯一，反馈有 user+client_event_id 唯一；客户端网络重试复用 UUID，新的实际反馈生成新 UUID。反馈重放返回原结果，不刷新票时间；同一用户新实际使用可以更新其一条当前状态，票数仍为一人一票。撤回最后有效有用应立即改变分组。

`expected_version` 防并发覆盖，409 `VERSION_CONFLICT` 后先拉当前对象给用户选择，不自动改价重发。公开状态修改必须生成快照/outbox；缺口变化是发布者声明，不派生履约状态。GET游标稳定基于时间+ID/消息sequence，并绑定查询视图/过滤，limit最大100；密码记录默认10最多20，API必须覆盖普通列表的100上限。

| HTTP | 典型 code | 客户端行为 |
|---|---|---|
| 400 | INVALID_INPUT / INVALID_TIMEZONE | 字段内显示必要错误，保留草稿 |
| 401 | AUTH_REQUIRED / TOKEN_EXPIRED | Auth刷新一次，失败回登录并保留安全上下文 |
| 403 | CAPABILITY_REQUIRED / ACCOUNT_SUSPENDED / STAFF_MFA_REQUIRED | 不重复自动重试，不用缓存绕过 |
| 404 | NOT_FOUND | 内容已不可见/移除，返回上一层 |
| 409 | VERSION_CONFLICT / REQUEST_CLOSED / IDEMPOTENCY_CONFLICT | 拉最新状态，避免重复提交 |
| 422 | INVALID_PUBLISH_CONDITIONS / INAPPLICABLE_SCOPE | 必要字段或条件纠正 |
| 429 | RATE_LIMITED | 读 Retry-After，退避；不每秒重试 |
| 503 | MAP_PROVIDER_UNAVAILABLE / DECRYPTION_UNAVAILABLE | 保留当前选择与输入，提供重试/手动找公寓 |

授权失败优先于解密，不能因查询已解密缓存把撤回密码继续回给用户。敏感响应 `no-store`，业务调用与 APM/代理层均禁止缓存/请求体采集。

## 6. 发布与输入的补充约束

- 正式发布需区域、取件地区、时间/截止、承运商、数量、报价单位、理货和接手条件；车辆/其他求助使用其简化规则，不能误要求每件报价。
- 同时修改总数与缺口时应保持剩余≤总数；既有报名不因改数量自动撤回或接受新条件。
- `kind` 发布后不可改；关键条件变更必须通知，需求版本记录永不覆盖。组织身份只来自服务端已验证的代表关系。
- 用户文本大小、控制字符、URL、嵌套JSON均限制；动态/回复不得公开门禁码、面单、住户联系方式。简单数字正则不能保证识别所有泄露，用户举报+运营审查是必要闭环。
- 图片/视频/文件上传、群聊、支付、承运商扫码/POD、派单和配送完成单没有首版接口。
- 内部揭示只支持有目的密码核验；一般员工不能调用“读所有消息”接口。本版没有全库导出接口。

## 7. 权限测试与审计要求

每个GET/列表与变更至少测：未登录、正常本人、另一个用户、过期能力、封禁账号、屏蔽关系、终态对象、跨环境/伪造JWT。员工接口增加无MFA/错能力/无理由/无对象关联测试。

关键例子：A的请求报名列表不可被C看；B可看自己和A的会话，不可通过猜ID看A和C；B有 access.read 也不能读 withdrawn 记录；A屏蔽B后B不能通过新需求重建会话；A的设备令牌不允许B用猜测device_id删除；凭旧JWT但本地suspended仍立即拒敏感接口。

审计只存actor/object/action/result/reason/request_id，不存密码、私聊正文、token或精确GPS。公开查看是否需要逐条访问审计可按风险设计，员工揭示与资格/状态修改必须记录。自动化静态校验不等于以上测试已运行。

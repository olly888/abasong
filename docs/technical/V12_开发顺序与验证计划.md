## 2. 验证层次

1. 静态：OpenAPI结构/引用、SQL顶层语法、字段白名单、无禁止业务接口、文档链接。
2. 真实数据库：角色/扩展、RLS与GRANT、外键/唯一键、append-only、事务并发、空间索引。
3. API集成：签名/本地状态/能力/对象、敏感字段、版本冲突、幂等、屏蔽、到期。
4. 移动端：iOS/Android原生地图、位置权限、恢复、字体、读屏、键盘与手势、推送。
5. 现场：相同公寓样本与设备、已授权资料，记录错栋/无资料/进入反馈及支援联系；供应商成本按实际调用核算。

当前完成第1层的指定静态检查，第2–5层未执行。测试环境无运行中的Docker/PostgreSQL，不连接现有云数据库代替隔离测试。

## 3. 必测用例

| ID | 操作/条件 | 预期 |
|---|---|---|
| AUTH01 | 伪造签名、错issuer/aud、过期JWT | 401，未查业务敏感正文 |
| AUTH02 | 合法旧JWT但本地账号suspended/资格revoked | 立即拒绝对应访问 |
| AUTH03 | 本人PATCH塞source=verified/ops角色/别人的user_id | 400，不授予任何权限 |
| ACL01 | 登录无access.read读密码 | 403；地图元信息不携带码 |
| ACL02 | 有资格读取withdrawn/invalid码 | 正文不可读，不用缓存绕过 |
| ACL03 | C猜测A的报名列表/对话/设备ID | 404，不泄露对象存在 |
| ACL04 | 员工仅ops.review调用reveal或无MFA调用ops | 403，审计失败访问 |
| ACL05 | B报名后未获集合点分享 | 不返回精确集合点；明确授权后才可读 |
| DB01 | API运行角色读access_secrets/message_secrets | 权限拒绝；敏感角色受控路径可读 |
| DB02 | anon/authenticated经Data API读abasong业务表 | schema未公开且无权限 |
| DB03 | 普通API修改/删除历史事件、版本/审计 | 权限拒绝 |
| DATA01 | 同码同范围并发贡献/不同门相同数字 | 前者一记录多事件；后者不同范围记录 |
| DATA02 | 有用票更多的旧码与较新同组码 | 较新贡献排前；票数不决定同组顺序 |
| DATA03 | 最后一票撤回/超窗/排除 | 回普通组；摘要正确更新 |
| DATA04 | 同client_event_id重复反馈 | 不刷票、不刷新更新时间 |
| DATA05 | KMS断连/错误AAD/密文替换 | 不解密、不退明文，明确错误 |
| REQ01 | 同用户同时报名、关单与报名并发 | 唯一报名；按锁提交顺序确定能否新报 |
| REQ02 | 旧expected_version改报价/缺口 | 409；原条件快照不被覆盖 |
| REQ03 | 100件需求收到3个报名 | 不自动减件；发布者手动确认缺口 |
| REQ04 | worker未及时处理到期状态 | 查询也不会把到期项当开放/可用 |
| MSG01 | 同client_message_id重复/不同内容重用 | 前者同消息，后者409 |
| MSG02 | 双向屏蔽后新建会话/报名/发消息/通知 | 不通过另一个需求绕过屏蔽 |
| MSG03 | 指定会话传入另一会话sequence标读 | 拒绝，不清除无关未读 |
| PUSH01 | ticket接受但receipt失败/DeviceNotRegistered | 不称已到达用户；重试或停用token |
| PUSH02 | worker崩溃重领同outbox | 站内事件唯一，外部重复允许按ID去重 |
| LOC01 | 相邻多栋、旧位置、粗略权限 | 候选/搜索，不自信展示错栋密码 |
| LOC02 | 读码时GPS漂移/切回原App再回来 | 保持选择和阅读位置，主动定位才重选 |
| LIC01 | Search Box/Temporary地址返回 | 不进入永久公寓库，许可可追溯 |
| OPS01 | 举报未经核实指控另一司机 | 不自动信用扣分或封禁 |
| DEL01 | 删除账号后旧JWT/可用/开放需求 | 拒绝访问并移出开放列表；任务有状态 |
| RESTORE01 | 从旧备份恢复 | 密钥可用，撤回/封禁事件恢复，不重新开放无权码 |

## 4. 当前检查重现

```sh
python3 scripts/generate_v12_openapi.py
python3 scripts/validate_v12_contracts.py
```

验证器依赖 PyYAML、pglast、openapi-spec-validator；本次仅安装在 `/private/tmp/abasong-v12-validation`，运行时通过 `PYTHONPATH` 引用，不改系统依赖。正式CI应建立隔离虚拟环境和锁定依赖；临时目录不是可复现项目依赖锁。

[静态结果](V12_静态校验结果.json) 明确区分passed与not_run。pglast只解析顶层SQL，DO内PL/pgSQL须数据库实际编译；不得把parse通过报告成完整迁移成功。

## 5. 开发准入与发布准入

工程开发可以开始，按模块补齐实现与测试。公开上线前仍需：真实账号/签名/短信/推送配置、地图授权、原生版本兼容、数据库隔离实测、合法公寓资料、运营责任人、参数冻结、费用预算与恢复演练。品牌候选未确认不阻塞组件骨架，但正式品牌资产发布前必须统一，不能让V2和V3令牌随机混用。

# V3.4 仓库找司机与途中代送：原生实现与验收

2026-11-07，洛杉矶。本批落实[用户确认的 V3.4 原型](http://127.0.0.1:8765/v12.1-experience/index.html?ux=v34&task=delivery)中两种发布场景和核对页。沿用现有 React Native 组件、品牌和发布接口。系统日期和时间控件沿用项目已有的 [Expo SDK 58 日期选择器](https://docs.expo.dev/versions/v58.0.0/sdk/date-time-picker/)。

| 场景 | 新建默认 | 核对重点 |
| --- | --- | --- |
| 仓库缺人，找司机 | 仓库取件；今天、约时间，到场时间留空；包裹约数、1 名司机 | 完整仓库地址、取件区域和派送区域分别列出；件数、人数、报价可核对 |
| 送不完，找人代送 | 途中交接；今天、尽快到场；件数口径为确定 | 交接地区与派送区域分别列出；具体交接地点联系后确认；保留承接方式、件数和报价 |

表单先填写地点、到场安排、任务量和报价，接手要求及补充条件按需展开。使用点选和司机人数加减；两个业务区域独立，代送可主动选「与交接地区相同」。修改仓库地址需要重新确认取件地址和区域。按件、按线路、议价之间切换时清空旧报价。发布者选择保持显式；新增团队后由本人选择，已发布需求保留原身份。

到场日期以洛杉矶为准。点「选日期」后取消不改值；改期清空之前的到场时间，未来日期须明确选时间。核对页分列到场、最迟接手（如果有）和下架。自动下架按最迟接手计算，未填最迟接手则为接手日当地当天结束；若自定义，下架需晚于到场、晚于当前时间，且不能晚于已填的最迟接手时间。「送完要求」另列，次日或当天可选明确截止时间。

核对失败滚动到第一个有问题的字段，显示就地提示；若字段在折叠区，先展开。核对页各组的「修改」返回对应区域；通用返回保留之前的滚动位置，编辑中的取件地址、数量、报价、到场和补充条件仍在。核对使用已验证的资料，确认提交时复核当前时间，沿用原有草稿写入、幂等键和版本冲突处理。无新接口、迁移或依赖。

- 全仓 lint、类型、构建和 518 项测试通过，其中 6 项新增覆盖默认值、日期和计价联动、仓库地址复核、洛杉矶夏令时、时间冲突定位和历史编辑保留；配送相关两个测试文件共 18 项通过。
- 本地隔离 API / PostgreSQL：622 项实际 HTTP 和数据库检查通过。包含两场景发布、仓库地址来源、权限、幂等与时效校验；数据库为本机测试环境。
- iOS 模拟器（iPhone 18 Pro / iOS 27.0）：仓库与代送新建默认、仓库地址缺项、取消日期、改期后到场清空并定位错误、下架冲突展开并定位、自动下架显示、分组返回和内容保留。两个场景均打开核对页，对照原型查看信息层次与底栏。
- Android 模拟器：仓库和代送新建默认、缺仓库地址和缺交接地区、两场景核对和代送按组返回、日期选择取消、改期后定位到场、下架冲突定位和自动下架、系统返回。手动将报价改为 1.86 美元后，核对页显示新值，分组回程保留 1.86 及 150 件。
- iOS／Android 的 release JavaScript 导出通过；模拟器运行使用已有开发客户端和本地 Metro。本批没有新签名包、真机操作、云端发布、真实业务写入或远程 CI 验收。

## 需求详情、报名与联系

详情和报名共用派送区域、到场时间、数量、人数和报价摘要。仓库场景分别列出仓库地址、取件区域和派送区域，并提供地图、复制和导航。代送按交接地区展示，具体交接地点由双方联系确认。约数按约数展示，未知数量显示「数量待确认」。报价、到场和接手要求复用核对页口径。精确件数有变化时，详情和报名展示实际剩余件数。

V2 个人及团队草稿从详情点「核对需求」进入原草稿的编辑与核对流程。司机报名时，预填到场时间落在允许的洛杉矶接手日期及最迟接手时间内。报名提交与取消固定在底栏。旧版本报名会引导刷新当前需求，网络失败保留填写内容。原输入重试使用相同幂等键，成功后打开该次报名的会话。已有报名从详情进入只显示该需求的「我的报名」。

| 验收 | 结果 |
| --- | --- |
| iOS 代送 | 保存草稿、重新打开、核对并发布、司机查看详情、取消报名后重新打开、响应丢失后保留到场时间并重试、进入同一会话。在最终底栏再测失败提示、重试和取消。 |
| Android 仓库 | 选择未来日期和到场时间、核对并发布、核对派送和取件区域、查看仓库地图及复制地址、打开报名。发布人改价后，旧版本提交被拦下。刷新后从详情核对新报价，重新报名并进入会话。导航入口已显示，地址编码由工程测试覆盖。 |
| 本机隔离 API / PostgreSQL | 40 次 HTTP 调用、32 项业务断言通过。覆盖仓库编辑、代送原草稿发布、复制生成独立需求、报名响应丢失后的去重及会话复用。双端操作共留下两条合成报名、一个会话，临时库和角色清理后均为 0。 |
| 工程检查 | lint、类型、构建和 520 项测试通过。iOS 和 Android 的 Release JavaScript 导出通过。设备范围为现有开发客户端与本机模拟器。 |

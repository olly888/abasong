## 1. 实施结果

查码、找活、找人改用同一个 `HomeResultCard`，由 `HomeApartmentCard` 和 `HomeDiscoveryCard` 提供三种业务内容。组件统一定义标题、核心信息、底栏和独立操作，不再依靠三个页面各自拼接高度。

| 布局项 | 原生规则 |
|---|---|
| 普通卡高度 | 180 逻辑单位；包含边框与内边距 |
| 内边距／圆角 | 14／16 |
| 标题／核心信息／底栏 | 最小高 46／48／36；槽位间距 10 |
| 列表 | 顶部 4、卡间距 12；保留外层纵向滚动 |
| 第二张预览 | 正常竖屏留 44 高，只见首行地址或标题；查码不露出城市或半条门禁码 |
| 短屏 | 可用高度不足 596 时取消预览，优先保留完整首卡 |
| 长码和大字 | 允许卡片增高，不截断前导零、星号、井号，不建立卡内滚动 |

`HomeWorkspace` 根据父容器实际可用高度、模式栏／分区栏的实测高度和字体缩放，计算剩余地图高度；不再次猜测扣除安全区。正常屏幕列表预算为 240，地图获得其余空间。三模式共享同一窗口尺寸下的测量缓存，减少模式切换时先回到旧 42% 布局的闪动。

大字时不承诺一屏容纳整张长卡：优先保证文字完整、列表可滚动。分区标题与操作分行，避免标题被挤成单字竖排；顶部改为搜索＋消息的紧凑组合，给地图和定位控件留出空间。正常字号保留字标，字标宽 124、保持原资产比例。

## 2. 内容和交互

- 查码：首行保留加粗门牌、常规街道和同行距离；完整地址可在详情查看，读屏标签仍包含城市、州和邮编。完整门禁码及门别在核心条，贡献时间／用户名在底栏。无记录、读取失败、无资格及暂停共享仍占用相同槽位，失败显示重试。
- 找活：标题为配送区域，承运商及场景降级；核心条突出报价与件数／缺口；底栏保留到场时间和取件／交接方式。
- 找人：姓名、区域、状态；核心条显示本人声明的接活时段；底栏显示容量、车辆、配送经验并标注自报。没有虚构的司机精确距离。
- 同日接活时段省去重复结束日期；跨洛杉矶日期时完整显示两端日期与时间，允许两行，避免将跨日误读为当日。
- 点卡打开原详情；独立“添加门禁码／重试”直接执行对应操作。没有把按钮嵌套在另一个可点击卡片按钮内。
- 卡片无障碍名称包含地址／价格／时段等完整业务信息；查码沿用逐字符零及 `#/*` 读法。内部重复文本不再形成重复焦点。

## 5. 明确边界和下一批

**DTL-02 完成的是组件与可见布局；DTL-03 的读取门槛仍待实现。** 当前列表仍沿用 15% item 可见判断，第二张仅露标题时可能进入读取集合，不能声称已完成“仅核心区可见才读码”。下一批必须将标题预览、核心区可见、主动选中分开，同时验证慢响应、模式记忆和贡献回到同一公寓。

## 6. 紧凑布局更新（2026-11-10）

- 查码、找活、找人沿用同一张卡片，普通高度为 156。查码标题区压紧，首行显示门牌、街道和有效距离。完整地址仍在详情及读屏标签中保留。长码和放大文字可以撑高卡片。

- Chromium 的四种视口覆盖三模式共用尺寸、详细地址、长码及大字，28 项通过。390×844 的第二张可见约 125 CSS px，430×932 可见完整 156 CSS px。模拟器继续使用合成地址和码。
- iPhone 17e 与 Android 模拟器核对通过。首行仅有门牌和街道，距离在右上角。iOS 可直接看到第二张的门禁码；Android 当前高密度下可见第二张地址及距离，滚动后显示完整卡片。用户在双端确认滚动到 102 可选中，复核 102 的代码与建筑高亮一致。详情包含街道、城市、州及邮编，关闭后 102 保持选中。定位数据有效时，102 右上角显示约 20 m。过期距离按既有规则清除。
- 全量工程检查通过 101 个文件、624 项测试及 lint、类型检查和构建。合成截图在本机 `.tooling/home-street-only-native/`，现场与真机验收暂缓。

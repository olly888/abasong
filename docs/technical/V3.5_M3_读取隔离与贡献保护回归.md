# V3.5 · M3 读取隔离与贡献保护回归

2026-11-08，洛杉矶。本批为锁屏期间可执行的本地工程工作。**客户端保护与真实本地接口回归通过；新版列表的双端滚动、返回和最终视觉仍待验。没有更新云服务或已安装内测包。**

## 1. 本批修正

### 1.1 反馈后只刷新目标公寓

旧实现先单独读取一次共享资料，再通知可见行读取器重试，会重复读取；若读取器仍有旧请求，重试还可能被忽略。

现在反馈成功只使该公寓的读取失效，立即移除旧正文并发起一次更新。旧请求即使忽略取消、晚于新结果到达，也不能填回旧码。其他可见公寓保留各自结果。两条并发槽都占用时，目标行先清除正文，等空槽再读取，不继续展示旧正文。

反馈提交过程中切换列表焦点，不再使反馈按钮一直处于忙碌状态。

### 1.2 区分公寓停显与账号资格失效

| 服务结果 | 可见行处理 |
|---|---|
| 指定公寓暂停共享 | 清除该公寓正文、取消旧请求；其他公寓不受影响 |
| `CAPABILITY_REQUIRED`、`ACCOUNT_UNAVAILABLE` 或 401 | 清除当前全部门禁正文并取消待返回请求；旧的客户端资格快照不能继续触发读取 |
| 单对象拒绝／不可见 | 对应行显示不可读取，不冒充“暂无共享门禁码” |
| 网络或服务失败 | 对应行显示失败和重试；其他地址内容保持独立 |
| 成功且无记录 | 才显示暂无共享门禁码，并保留贡献入口 |

资格重新确认或新的账号/会话建立后，必须重新经过服务端鉴权读取。客户端不缓存门禁正文到阅读位置记忆；切换模式、离屏、销毁会话时不带走正文。这里没有取消服务端权限检查，也没有给真实账号新增资格。

### 1.3 共享成功后回到目标卡片

发现旧列表偏移可能在返回时覆盖目标卡片定位：地址已选中，但卡片仍在屏幕外。

新增待定位的公寓 ID，直到目标卡实际可见才消费该意图。明确的地址跳转优先于旧滚动偏移；同一公寓回程保留镜头，新的公寓/搜索目标清除旧镜头关联。普通模式切换和详情返回仍复用原阅读记忆。新增逻辑不保存门禁正文。

本人纠正沿用既有流程：先回“我共享的”查看本人新旧来源，再通过“在地图查看”回同一公寓；没有擅自改变为提交后强制跳首页。新首页的实际滚动回程还须双端原生补验。

### 2.1 对真实接口验证的限定

新增 `scripts/d1/verify-visible-access.ts` 被既有 `verify:library-api` 调用。它直接组合生产客户端读取协调器与真实本地 HTTP 服务，以两名具备不同资格的合成账号和一名无资格账号验证：

- 不同公寓的 `*0012#`、`#0008*` 独立返回，无码地址为成功空结果。
- 提交与纠正使用同一幂等键重试，只有一份实际贡献/替换来源；本人已纠正历史隐藏旧值。
- 将旧的 HTTP 成功响应延迟到纠正之后才交给客户端，仍保留 `#0010*` 与正确门别。
- 同一个未过期 JWT 对应的数据库资格到期后，新读取收到拒绝；所有可见门禁正文清除。
- 无资格账号不能读取或贡献，他人不能读取本人来源详情。

首次运行在测试配置阶段被 403 拒绝：测试贡献账号没有本人详情所需的查看资格。只给一次性测试库中的该合成账号补齐既有契约要求，重跑通过；没有改变产品授权规则。

测试脚本先校验数据库名必须为 `abasong_d1_library_test_*`，结束后清理一次性数据库与测试角色。门禁内容、令牌和连接字符串不输出到日志。导入日志中预期的 `IMPORT_DB_FAILED P0001` 来自失败注入，用于验证回滚；整套测试退出码为 0。

### 2.2 误匹配新增覆盖

对已有六个公开公寓样本分别加入：错误城市、错误州、额外房号、额外楼栋、缺少城市。即使查询坐标与公寓相同，也不得据“最近”绑定门禁码。另增加未知 house 地址与最近公寓不能自动互绑的检查。

已有 Woodside 54 个屋顶只关联一次社区、社区远中心、相邻地址、200 米边缘和失效资料覆盖继续通过。**这些证明当前本地匹配规则，不证明 Mapbox 最新分类覆盖或真实配送入口准确性。** 没有新增外部地理数据、Mapbox 调用或扩大到 500/1000 米；扩围仍是 M4。

## 3. 留给解锁后的有限补验

沿用 M2 的 TEST 原生入口，不要求重新做全部历史 R4/B5 流程：

1. 多卡可见时只重试失败卡；地址、码、焦点和地图一致。
2. 反馈期间滚动至另一公寓，完成后按钮可再操作，不串码。
3. 从非首行或新收录地址贡献后，目标卡实际进入可视区；普通返回仍保留阅读位置。
4. 本人纠正后回共享记录，再在地图查看同一地址；保留所有符号与前导零。

# V3.5 M4-02：找活、找人查询与分页

更新：2026-11-08，America/Los_Angeles。状态：**本地实现及自动验证通过；iOS、Android 新版原生操作待补**。本轮没有部署云端或更新已安装内测包。

## 已落实的用户行为

- 找活与找人继续使用上方地图、下方纵向独立卡片。标题分别为「配送需求」「可接活司机」，不把全部区域的结果称为附近结果。
- 区域、日期、承运商／经验条件通过真实 API 查询。找活只提供「仓库找司机」「途中找人代送」两个场景；途中代送同时包含部分包裹和整条线路，不再使用旧三类型菜单。
- 卡片选中、地图回位和详情返回不改变筛选；每个模式保留自己的阅读状态。更换筛选重置为第一页。
- 每页 20 条，最多 5 页；下一页只请求对应游标，不重复请求前面所有页。相同对象按 ID 合并，不能因跨页出现两次生成两张卡片。
- 下一页网络失败时保留已加载卡片、选中和列表位置，在底部显示「加载更多失败，已加载内容保留」和「重试加载更多」。同次重试使用原游标。
- 游标失效（404/409）或出现游标循环，提示「结果已变化，请重新加载」，重新读取当前筛选。首屏／完整刷新失败仍显示失败态，不伪装成空结果。
- 401/403 不保留之前可见结果；离开、账号切换、模式或筛选变化取消旧请求，迟到的成功或失败不得覆盖新结果。
- 达到 5 页且服务端仍有结果时显示「结果较多，请缩小筛选范围」。标题数量与地图区域数量只统计当前已加载、仍有效的对象，不是全量统计。
- 需求关单／过期、司机关闭接活／时段结束后从查询结果移除。未来时段显示「待开始」。司机标记是自报服务区域的展示点，不是实时 GPS，不显示编造的距离。

## 接口与数据边界

`GET /v1/requests?request_schema_version=2&scenario=delivery_handoff&region_id=…&day=YYYY-MM-DD&query=…&limit=20&cursor=…`

- 新增可选 `scenario=warehouse_shortage|delivery_handoff`。默认旧 schema=1 与 `kind` 过滤仍兼容；新版客户端使用 schema=2 + scenario。
- 需求 `day` 按洛杉矶接手日期精确匹配；司机 `day` 按洛杉矶当日与可接时段相交匹配，沿用既有时区规则。
- SQL 仍执行账号、屏蔽、开放状态、下架时间及对象限制。摘要不新增电话、微信、仓库详细地址、私有交接点或司机 GPS。
- 生成源 `scripts/request_v2_contracts.py`、OpenAPI YAML、生成 TypeScript 同步；没有数据库迁移、新包或新云资源。
- 页面数据只保存在当前组件／账号会话内；暂停或离开清除分页快照。区域目录返回未遍历的下一页时明确失败，不静默遗漏筛选项。
- 当前云端尚未更新新 `scenario` 参数，后续集成部署需先更新 API 再更新候选 App。本批本地实现不等于云端已接通。

## 待解锁的双端操作

当前 Mac 原生工具报告锁屏。本轮没有要求重复已通过的旧手势；下列新版操作仍待实际核对：

1. `home-integration-lab?layout=muse&mode=people&scene=pages-retry`：滚到末尾加载更多，首次失败保留原列表；重试后追加，进入详情再返回保留位置。
2. 同入口 `scene=pages-slow`：下一页等待时换区域／日期，迟到响应不得混入新结果；切模式再返回仍保留自己的筛选。
3. `scene=pages-denied`：下一页拒绝后清空列表并显示失败；`scene=pages-limit`：达到五页后有缩小筛选提示。
4. 找活筛选只有两种场景，地图点区域／列表选中／详情回程的含义分离；窄屏、大字号及键盘状态不遮挡操作。

这些均为 TEST 内存场景，不能当作正式用户或云权限验收；接口权限已另在独立本地数据库测试。

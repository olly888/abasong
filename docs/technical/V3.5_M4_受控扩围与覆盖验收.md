## 2. 覆盖判断为何单独处理

Mapbox Tilequery 的 `radius` 并不等于无限地理覆盖。官方说明：查询 tileset 的最大缩放级别，涉及所在瓦片及八个相邻瓦片；返回条数最多 50。设置更大 radius，并不能单凭成功响应就证明圆内全部被查询。[Tilequery API](https://docs.mapbox.com/api/maps/tilequery/)

本批读取 TileJSON 的 `maxzoom`，用同一原点计算九瓦片的地理范围是否包含目标圆，并留 5 米保守余量；元数据仅在进程内缓存五分钟。元数据失败、范围不足、50 条上限、逆地理预算耗尽或地址无法明确，均标记覆盖不完整。瓦片范围判断独立于原生地图当前有没有加载完整视野。[Mapbox Streets v8](https://docs.mapbox.com/data/tilesets/reference/mapbox-streets-v8/)

**有界扩围不是承诺每次一定能查完整 1 km。** 例如实际 tileset 的九瓦片不能覆盖某处 500 米圆时，会在该档停止并标记部分覆盖；不会继续把 1 km 宣称已查遍。`queried` 只说明当前资料源查询完成，不代表 Mapbox 收录了所有公寓或大型门禁社区。公开地址、已有业务关联和供应商分类仍是互补关系。

## 3. 契约与服务边界

| 项目 | 本批规则 |
|---|---|
| 请求 | Mapbox 附近发现接受可选 `expand: true`；省略保留原有固定 200 米流程；普通业务库端点不接受扩围开关 |
| 任意范围 | 客户端不能传任意 radius；服务只允许 200/500/1000 |
| `radius_m` | 最后一次成功形成结果的范围；下一档失败不会把旧卡片标成新范围 |
| `coverage` | 分别标识 catalog queried/capped 与 mapbox not_requested/queried/partial/unavailable；都是增量可选字段 |
| `expansion` | 尝试档位、停止原因、查询计数和耗时；只含诊断数字，不含门禁正文、账号或额外定位信息 |
| 时间与数量预算 | 一周期供应商中止预算 8 秒；catalog 最多 3 次、Tilequery 最多 7 次、临时逆地理最多 4 次、TileJSON 最多 1 次 |
| 50 条上限 | 原有最多四个偏移补查保留，但仍标 partial 并停止扩围；不会爬取全城资料 |
| 频率 | 沿用每账号 25 秒、全局 1 秒的现有发现限流，一周期只占一次；滚动列表不触发扩围 |
| 存储 | 临时供应商地址和元数据仅当前请求/短期内存使用；不新增表、不批量持久化供应商结果 |

8 秒是供应商请求共享的中止预算，同时在档位间核对耗时；不是数据库和整个 HTTP 请求的绝对响应时间保证。移动端已有 10 秒请求超时保持不变。失败不自动开启无穷循环。

生成源、OpenAPI 和生成类型同时更新。需要服务端与新版 App 配套发布；本批尚未部署。原固定范围调用仍通过兼容测试。

## 4. 地址、距离与门禁隔离

1. 每个扩围周期使用同一位置观测。catalog 仍优先按有效社区边界/建筑范围计算距离，范围扩大不改变地址匹配规则。
2. 补查点返回的距离不能冒充距司机的距离；换回原查询点计算保守距离，并保留距离依据。
3. 跨档复用最多四次逆地理结果；同一明确地址合并，已关联公寓以业务 ID 去重。未确认地址不凭最近点绑门禁码。
4. 普通 house 不因范围变大而生成公寓；已明确收录的社区关联按既有规则继续可见。发现接口不读取共享门禁正文。
5. 客户端把结果、范围、来源与观测作为一个快照处理；不将不同位置或不同档位的数据随意拼接。只接受允许的半径，保留距离过期隐藏与漂移裁剪。
6. 每档及响应前重验账号与位置时效；资格/账号撤销和过期定位不降级成可用数据。M3 的可见行受权读取、离屏清除、对象隔离和迟到响应防护继续生效。

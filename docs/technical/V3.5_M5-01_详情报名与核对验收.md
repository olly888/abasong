# V3.5 M5-01 · 需求详情、报名与发布核对

2026-11-08，America/Los_Angeles。状态：**本地实现和自动回归通过；新版 iOS/Android 原生操作待补。**

## 交付内容

本批沿用上方地图、下方纵向卡的 Muse 结构，接续 M4-02 进入两场景详情与发布链路。只调整既有页面的信息组织与共用组件，不新增业务场景、收费、自动分配或额外必填项。

| 页面 | 本批变化 | 保留规则 |
|---|---|---|
| 需求详情 | 场景弱化；派送区域、报价、件数及人数组成核心摘要；下方按取件/交接、接手要求、截止时间与身份分组 | 完整仓库地址、地图/复制/导航、本人管理、报价单位、约数/待确认、真实剩余缺口 |
| 发布核对 | 任务量与报价置前，取件与派送、到场与下架、接手要求在中间，发布身份放末尾；分组修改按钮至少48触控高度 | 原分组锚点、默认值、洛杉矶时间、最迟接手/下架约束、版本和幂等逻辑 |
| 报名 | 核心摘要之后显示完整取件地址；“本次可接活”的日期、时间和件数提前；要求信息置后 | 约数/未知件数可留空，整批确定件数锁定；提交前版本检查、失败输入保留和重试 |
| 表单 | 使用同一分组容器及层级，移除旧详情的嵌套边框块 | 已实现的 V3.4 点选、地址确认、错误定位、草稿与返回修改 |

共用 `DeliverySection` 管理标题、间距、分隔；`DeliverySummaryBlock` 统一详情/报名/核对摘要；`DeliveryFact` 统一标签和值。价格条用既有品牌浅蓝与深蓝文字，其他内容保持黑白灰。没有固定卡高；320宽或系统字体较大时摘要改纵向，地址和文字允许换行。三类业务字段仍按场景呈现，不硬套统一字段。

报名字段错误现在定位到日期/时间组或件数组，不再统一滚到末尾。采用可取消的有限测量重试；取消、重新输入、退出后不遗留滚动任务。此行为已在实际 RN-web 组件验证，原生键盘和读屏仍待验收。

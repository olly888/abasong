# V3.5 M6-02 · 消息、邀请与未读语义

2026-11-08，America/Los_Angeles。**本地实现、真实本地接口/数据库和浏览器组件检查通过；iOS、Android 原生操作与最终视觉待补。** 使用既有正式字标、品牌蓝、Lucide 图标和共享组件，没有开放正式邀请分发、发送外部消息或增加账号资格。

## 页面与行为

| 范围 | 本批调整 | 保留的边界 |
|---|---|---|
| 首页消息入口 | 使用统一未读角标，来源为同一消息汇总 | 对话和通知仍在同一个入口；司机圈回复不另加一次 |
| 消息中心 | 对话/通知使用等宽分段切换；统一字级、行间距、分隔与角标；通知内显示司机圈回复子集 | 不新增首页通知按钮，不把圈内回复数当全站未读 |
| 通知已读 | 服务端确认本条已读成功后，更新当前行并重读汇总 | 请求失败保留未读；重复确认不重复扣数；进入司机圈、浏览帖子不批量清除通知或对话水位 |
| 慢响应与账号 | 账号切换重建页面；焦点、标签、前后台变化先重新验证；异步读取按请求和已读版本隔离 | 迟到列表、迟到汇总不能恢复旧账号内容或已读角标；401/403 清除记录与计数，404 移除已不可见通知 |
| 邀请司机 | 官方字标、核心价值、三行说明与二维码区域采用统一层次；次级操作可换行；闭合状态使用共享状态组件 | 普通构建仍显示“邀请分享暂未开放”；只有 DEV 本机预览可测试原有分享/保存/复制功能 |
| 接收邀请 | 原型继续展示产品价值及可用入口 | 不自动授予门禁资料查看资格，不加入 DSP，不产生邀请人数、奖励或“已发送”假成功 |

共享 `UnreadBadge` 使用品牌蓝、20 最小数字角标、8 点状提示和 `99+` 上限；父控件的无障碍标签提供实际未读数。`MapModeSwitch` 支持可选角标和明确选中状态，不改变首页三模式业务。通知加载失败与空列表分开，未重新验证时不展示旧列表。

邀请图复用 `InvitePoster`，不重新绘制字标，不从当前页面截取门禁资料、私有地址或账号资料。此次没有重做系统图片保存和系统分享的实现；其原生效果仍需同批补验，不能由浏览器截图代替。

## 契约与权限

`GET /v1/me/inbox-summary` 新增必需的非负整数 `unread_circle_replies`。由生成源更新 OpenAPI 和客户端类型，不只改生成文件。

| 字段 | 口径 |
|---|---|
| `unread_messages` | 有权读取会话中尚未读的消息数 |
| `unread_conversations` | 有未读消息的会话数，不与消息数相加 |
| `unread_notifications` | 当前账号有权看到的未读通知总数 |
| `unread_circle_replies` | 上述通知中 `circle_reply` 的子集，不额外计入总角标 |

首页角标仍为 `unread_messages + unread_notifications`。服务端子集计数与通知列表复用现有对象可见性条件，删除、屏蔽及资格失效不能只隐藏列表而继续泄露旧计数。未新增迁移、RLS 策略、收费、团队或新权限。云端尚未部署此字段；后续 M7 先验证对应服务版本，再制作统一候选。

中间问题均保留解释：

- 沙箱首次禁止本机监听，按现有本地验证权限重跑后通过，没有降低断言。
- 接口检查第一次与构建并行，加载了旧 API 编译产物而缺少新字段。构建完成后按原断言重新执行，660 项通过；这不是“历史测试数据”问题。
- RN-web 分段控件最初未输出 `aria-selected`，补充明确选中属性后通过。
- 审查发现连续已读的两次汇总可能倒序返回；增加汇总请求序号和已读版本校验，专门延迟第一份汇总的组件检查通过。
- 原型的旧司机圈覆盖函数沿用旧消息页、分段按钮也未等宽。统一渲染入口及等宽样式后重新核对，没有把原型样本视为真实 API 数据。

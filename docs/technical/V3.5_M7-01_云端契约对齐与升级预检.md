## 2. 需要一起对齐的契约

| 能力 | 新版要求 | 升级前的判断 |
| --- | --- | --- |
| 附近公寓 | `/v1/apartments/discover/mapbox` 接受 `expand: true`，返回覆盖、实际范围、尝试范围和停止原因 | 发布回执对应的旧输入校验为 strict 且不接受 `expand`；需要升级服务。此结论来自源码对比，本批没有用真实账号调用旧发现接口 |
| 有界扩围 | 从 200 m 开始，仅上一档成功且覆盖充分、不同候选不足 3 个时尝试 500 / 1000 m；最多 20 个候选 | 数据不足、供应商部分覆盖、请求失败不能写成“附近没有公寓”；也不保证每处都能得到完整 1 km 覆盖 |
| 找活筛选 | 需求查询增加 `scenario`，区分仓库缺人和途中代送 | 与新版筛选同时升级，保留旧调用的默认行为 |
| 消息计数 | 增加 `unread_circle_replies` | 旧客户端可忽略新增字段；新版缺字段时不能编造未读数量 |
| 共享保护 | 第 0023 次迁移及配套服务统一识别公寓暂停共享状态 | 新 API 缺任一必要迁移时 `/health/ready` 返回 503，必须先迁移后切服务 |

`expand` 只属于 Mapbox 发现入口，普通 `/discover` 不开放任意扩围或客户端自定半径。保留可见卡片按权限读取、切对象隔离、贡献回到原地址及失败重试。暂停共享保留地址，不返回共享正文；无需逐条人工审核，也不增加司机操作。

| 情况 | 处理 |
| --- | --- |

| 迁移成功、新镜像尚未就绪，且状态表从未写入操作 | 先停止其他业务写操作，核实表为空，再按实际记录的旧摘要回退服务；数据库保留 23。旧服务不依赖新表的判断目前为源码兼容性分析，执行前仍需实际镜像复核 |
| 已产生暂停／恢复操作 | **禁止自动回退到不识别暂停状态的旧 API。** 优先修复当前兼容版本；如不可用则保持接口明确失败，不能以恢复旧服务为由重新展示受限门禁码 |
| S3／KMS／资格检查异常 | 停止验收与发布；保持原资源和授权边界，不关闭加密、不改成公共图片、不给普通账号全局放权 |

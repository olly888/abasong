## 读屏环境的新结论

不能继续使用旧版“iOS 模拟器不支持 VoiceOver”的笼统判断。[Xcode27 发布说明](https://developer.apple.com/documentation/xcode-release-notes/xcode-27-release-notes)记载了 Device Hub 的 VoiceOver 开关修复及新的读屏测试能力；本机 Xcode27.2 的开关已经实际启用模拟器读屏。出现焦点框、系统进程运行只证明环境启动，不能替代听取朗读、逐项焦点移动、选中状态与密码符号读法验证。测试后已通过界面将 VoiceOver 关闭，并读取 off；未开启 Mac 本机 VoiceOver。

Android 环境为 Apple M5、Emulator37.2.13、官方 API36/API37 Play 镜像。Hypervisor 检测通过；API37镜像为rev7，不能把官方文档中“更新至rev5以上解决Play认证”当成本机启动崩溃的修复。本轮在只读、无快照、单核、无音频模式下分别尝试 API36 host GPU 与 API37 swiftshader / 禁用 Vulkan；均发生 CPU/main-loop 挂起并以139结束。第二次开启内核输出也未得到可用的系统启动证据。两个进程已退出，未擦除 AVD、未变更原 emulator-5556 数据、未登录 Google 账号。依据：[Android Emulator 官方排障](https://developer.android.com/studio/run/emulator-troubleshooting)。

收尾复核：两份日志均先报 `QEMU2 CPU0 thread` 约19.6秒未响应，随后 `QEMU2 main loop` 约15秒未响应；两套镜像与可用AOSP模拟器均为arm64-v8a，不能据此归因为ABI填错或Abasong崩溃。仅凭这些日志尚不能确定宿主机兼容性根因。本轮没有重复启动同样参数。

下一次应针对具体启动日志检查兼容性，或使用可运行的官方设备环境；不重复同样参数盲试，也不从非官方来源侧载读屏 APK 来宣称完成。实际读屏验收仍需分别记录：首页三模式焦点顺序、完整门禁码的前导零与符号、门别选中状态、错误与重试提示、弹层关闭后焦点回到入口。不得以AX标签存在代替朗读通过。

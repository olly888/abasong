# Abasong · iOS / Android 实时预览

当前默认设备为 iPhone18Pro / iOS27.0 与项目独立 Android17 / API37 ARM64 模拟器。两端使用同一个 Metro 服务，代码保存后支持 Fast Refresh。

## 日常启动

在终端进入 `/Users/olly/Abasong`。

第一个终端启动开发服务，并保持运行：

```sh
cd /Users/olly/Abasong
./scripts/dev preview:native
```

第二个终端打开 iOS：

```sh
cd /Users/olly/Abasong
./scripts/dev preview:ios
```

脚本会打开本机 Xcode 的 Device Hub（旧版Xcode则为Simulator），默认启动 iPhone18Pro、构建并安装 Debug 开发版、连接本机8081服务。首次构建需要等待；后续页面修改通常不必重跑。设备左侧选择 iPhone18Pro；首次弹出“在Abasong中打开”时点击“打开”。

第三个终端打开 Android：

```sh
cd /Users/olly/Abasong
./scripts/dev preview:android
```

脚本检查服务、启动项目专用模拟器、安装开发包、设置本机端口连接并打开 `Abasong · Android` 实时画面窗口。画面可用鼠标操作。由于当前模拟器直接图形窗口存在渲染兼容问题，采用无窗口模拟器搭配scrcpy5.0.1显示同一设备的实时画面；运行的仍是Android17原生App。

Android默认复用已有Debug APK；没有APK时会自动编译。原生库/权限配置变化后：

```sh
./scripts/dev preview:android --rebuild
```

iOS可临时切换设备，例如：

```sh
ABASONG_IOS_DEVICE='iPhone Duo' ./scripts/dev preview:ios
```

## 开发时如何查看

- 日常文字、样式和多数JS/TS交互：我修改并保存后，两端自动刷新；你可以同时比较。
- 无需在每次页面修改后重新打包。新增原生模块、修改原生权限或Expo配置后重新运行构建命令。
- Metro终端中按 `r` 可手动重新加载已连接客户端；关闭这个终端会停止实时更新。
- 关闭Android画面窗口不清空模拟器资料，也不停止Metro；再次运行preview:android重新打开即可。
- iOS本次已从Release替换为Debug开发构建。Release内嵌JS包不能作为日常Fast Refresh入口。
- 仅监听本机127.0.0.1:8081。Android经adb reverse连接；iOS使用本机回环地址，不需要开放局域网端口。

当前预览可查看实际地图与三导航，公寓查询/密码/贡献反馈页面按D1进度接入；排序SQL实现本身不会产生可见页面。原型仍保留作交互和视觉基线。

- 代码检查、类型检查、测试及构建通过；Web和iOS JS导出通过。浏览器预览为可选入口 `./scripts/dev preview`，与原生开发服务共用8081，不能重复占用端口。

## 本机路径

- 原生服务入口：`package.json` 的preview:native / preview:ios / preview:android。
- iOS启动脚本：`scripts/preview/ios.sh`。
- Android启动脚本：`scripts/preview/android.mjs`，底层环境由`scripts/android`提供。
- SDK/模拟器及日志：忽略的`.tooling/`；token仍仅在忽略的本机环境配置。

## D1安全存储构建要求

新增ExpoSecureStore和ExpoCrypto后应重新prebuild和原生构建，安装完成后冷启动应用，避免旧进程保留旧原生模块。iOS模拟器使用标准本地签名；不要加CODE_SIGNING_ALLOWED=NO，未签名包虽然能显示地图，但实测Keychain读取出现entitlement错误。模拟器本地签名不需要发布证书或付费开发者账号。

## 首页定位模块更新（2026-10-30）

Android新增AbasongLocation前台单次GPS模块后已重新编译安装。旧APK不能只靠Fast Refresh获取此能力；新增/修改原生模块须重新编译并安装。iOS本批仅更新JS相机控制，现有Debug版可实时刷新。开发齿轮已通过Expo官方API隐藏，仍可使用开发菜单快捷方式；它不是产品设置。

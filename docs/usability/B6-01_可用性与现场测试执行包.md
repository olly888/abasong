## 1. 招募与主持

- 5 名在洛杉矶地区有公寓配送经验的司机，编号 D01–D05。尽量兼顾熟线和新线、不同手机熟练度。若方便，至少包含 1 名使用 iPhone、1 名使用 Android 的司机。2 名有临时补人经历、参与排班或派工的 DSP，编号 S01–S02。兼职多角色者只计一人。
- 主持观察优先安排 1 名司机和 1 名 DSP，用于发现任务描述或设备准备问题。原任务、初始状态、终点和计时口径一致时可计入首轮。若修改上述任一项，标为预演并另跑正式首轮。
- 司机约 25–35 分钟，DSP 约 20–30 分钟。可先约主持人本机面谈，或由主持人共享画面让远程参与者自行操作。远程无法实际操作的反馈记为访谈。现场仅请愿意配合的司机在正常路线顺路补测，单个公共停靠点预留约 10 分钟。
- 联系名单、时间和资料提供者授权由组织者私下保管。记录仅用编号。开场说明自愿参加、随时退出、只记匿名操作。默认手记，单独征得同意后方可录制合成原型。真实场景使用结果勾选，避免门禁、住户及包裹内容进入影像或观察笔记。

**可直接转发给参与者的邀约**

**主持人操作**

1. 每人开独立浏览器会话，从[本机原型首页](http://127.0.0.1:8765/v12.1-experience/index.html?v=r3-delivery#home)开始。链接供主持人使用。手机窄屏下应看不到主持人场景面板。原型以洛杉矶 2026-11-04 2:20 PM 为演示时间。参与者可在自己的任务之间保留合成贡献或需求。
2. 从[既有任务卡](V3.2_五司机两DSP可用性测试包.md)逐条读目标。司机优先完成 T01–T04，再做 T05/T08。DSP 做 T06、T07、T08、T09。使用[既有 38 行记录](V3.2_可用性记录模板.csv)。T03 使用合成行人门图和字符待核对图，开题时给每名司机同一张合成源资料卡，标明第二图疑似 I 的字符已由来源确认是数字 1，让参与者自己决定怎么修。T04 复用本人的测试贡献。T08 可在同一会话切回桌面宽度，从主持人面板预设下一条合成消息失败，再恢复手机视口。
3. 读完任务、允许操作时起表，达到正确终点时停表。无提示完成、提示后完成、失败、未测分别填 `independent`、`assisted`、`failed`、`not_run`。先让参与者说出所见与预期，再给必要提示。记录提示时点、错误和排除的设备暂停秒数。
4. 报告每项无提示完成数 / 尝试人数、未测数、完成耗时中位数及问题。司机核心任务沿用每项至少 4/5，DSP 的 T06/T07/T09 各 2/2 无关键误解。错楼读码、错址绑定、把未核对内容误共享或误以为已经接单属于关键问题，先修复再复测。司机圈及账户的跟进模板保持各自分开。

**现场前检查**。记录业务 App 版本、系统、现场环境、网络类型。用计划使用的真机和经批准的测试账号，在预定网络上确认冷启动、HTTPS、定位权限、底图、附近发现以及账号读码资格均可用。核对测试区域中用于验证读码的授权资料及门别。本轮只读查到云内测 `/health/live` 和 `/health/ready` 均返回 HTTP 200。正常业务包的离开 Mac 启动、账号资格和业务读码仍需单独验证。原型主持和材料准备可以先走。入口核对专用 App 的公共观察单独记为 `entry_review`。正式业务路径条件不足记 `blocked`，待业务包与账号具备后复跑。[独立现场版方案](../technical/D1_独立现场版与HTTPS测试环境方案.md) · [云内测与双账号前置](../technical/A4_云业务配置与双账号验收.md)

**现场操作**。在公共区域停好车或步行停稳。主持人事先从公开门牌核对目标，不指点按钮。先打开公寓首页，看目标是否进入附近候选、第一张是否为目标、切卡地图是否同步，以及完整地址和门别能否核对。以首页可操作为起点，到参与者找到并确认正确地址和资料状态为终点。先记附近发现，之后才允许用搜索补救，单独记搜索是否找到。观察时间建议 30 秒，超时如实记并给参与者继续的机会。相邻合法公寓排第一不一定是错误，只有错把非目标的资料绑定到目标或用户误认它是目标才记问题。

**资料状态分开记录**。正确地址可出现 `available`、`no_record`、`not_entitled`、`fetch_failed` 或 `unknown_scope`。可见资料只记录有无与门别是否正确。只有正常配送中经许可实际使用才勾选 `valid` 或 `invalid`，其余 `untested`。停在门外即可完成大部分观察。识别错址、错门别或可疑暴露时停止读码，记匿名问题并复测。将[空白现场模板](B6-01_现场记录模板.csv)复制到本机忽略目录，用地点编号和公共观察类别记录，不填坐标、住户信息、真实密码或完整路线。

**汇总口径**。按地点报告公共门外试次与去重公寓数。对业务可操作的已尝试公寓，分别报告附近找到正确目标数 / 尝试数、搜索补救数 / 有补救尝试数。另列预检阻塞、定位失败和网络失败，区分候选没出和设备打不开。对核址后读码请求完成的有权试次，计算有资料数 / 成功读取状态数。有效率只计经许可验证的资料，单列未验证数。市政负例和重复 Woodside 观察点独立报告，不能混作新增公寓。

现场表的 `environment` 填 `business_pilot` 或 `entry_review`，`preflight_status` 填 `ready` 或阻塞原因。附近结果使用 `target_found`、`target_missing`、`location_failed`、`network_failed` 或 `wrong_binding`。CT01 单独填 `control_clear` 或 `false_apartment`。完成一次实际尝试填 `observed`，未尝试保持 `planned` 或填 `blocked`。模板里的 6 行是排期位置。

## 3. 截图识别准备与操作

- 先收 **10 张**有授权且已经脱敏的真实版式截图。尽量覆盖至少两种承运商版式。建议 4 张清晰单地址、2 张同图多地址、2 张模糊或截断、2 张无码负例。在正例里兼顾前导零和首尾符号。发现明显错误先修复，再按既有目标扩展至 30–50 张。若其中某类拿不到，记录缺口。
- 请资料提供者在发送前遮掉姓名、电话、房号、包裹或订单号、条码/二维码、账号头像、消息和定位。把实际门禁值替换为相同长度和符号位置的合成值，地址只保留获准的公开建筑地址，或使用合成地址。用导出的扁平图片核对脱敏效果及元数据。替换过的文本单列为 `masked_layout`，报告真实版式的测试结果。只有获准保留的原始目标文字可另归 `redacted_original`，两类分报。
- 由两人分开读脱敏后的地址、合成码、门别或歧义，再对照确认。只有一人可核对时记录 `single_review`，留作预筛。看不清的内容记不可辨认，负例标明确实无码。经授权用途、日期与真值只留在本机 `.tooling/ocr-real/` 的受控批次目录。原图不必交给主持人。匿名空模板在[OCR 记录表](B6-01_OCR记录模板.csv)，只填计数、用时、匿名样本编号及问题编号。
- 两平台尽量用同一组图和固定版本。在设备先记录机器给出的初始结果，再让司机核对或修正。识别时应用会用提取出的街道发起地址匹配查询。若有任何目标字段未经授权传出设备，使用合成替换图做联机试验，或只用已授权的离线回放。真实版式试验停在核对页并退出清掉本次选择。只有隔离合成流程才操作确认共享。若采集到了真实原生识别行，可用[现有离线评分工具](../../scripts/ocr/README.md)，否则按 UI 观察记录完整性与耗时，并标明 `native_ui` 或 `simulator_ui`。浏览器原型只用于观察操作。
- OCR 表每张图每个平台首次实际运行一行。三组 `expected` / `scorable` / `exact` 列分别填写地址、值和配对的预期条数、可辨认条数和逐字正确条数。完整门禁字面一致包含大小写、前导零及首尾符号。未识别到的可辨认项仍在分母，超出真值的候选另填 `false_candidates`。不可辨认目标仍计入歧义和提示观察。地址是否找到业务目录可另记问题号，与地址文字是否读对分开。
- 分 iOS / Android、真机 / 模拟器、版式、清晰度和脱敏类别报告。低置信提示、无码误提取、人工更正次数、识别等待时间和人工核对时间分别记录。小样本先给 n/N、成功耗时中位数及全体耗时范围，失败与未测一并列。
